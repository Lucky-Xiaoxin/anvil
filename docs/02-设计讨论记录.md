## 2026-10-04 · 第 15 轮：mock-02 交付后 —— 切换动效改向（卡片飞出飞入）

- mock-02 已交付（4 屏 + 8 张实拍）。用户看了渐隐渐出后改口径：**推翻第 14 轮"切换 ≤200ms 淡入淡出"**，换成卡片编排：旧卡向两侧飞出、新卡自底部飞入。已在 `feat/mock02-card-fly` 分支落到视觉稿里。
- 定稿编排：
  - **方向**按卡片中心相对内容中线的左右分派 —— 左侧卡向左飞、被内容区左边缘裁掉（视觉上钻进侧边栏底下）并在末段淡出；右侧卡向右飞出屏幕外；跨行宽卡（格子图 / 曲线 / 降级条）算中部走右侧。
  - **顺序**：飞出 = 离中线远的先走（外圈先、中部后）；飞入 = 离中线近的先来（中部先、外圈后）。宽卡压后出、提前入，正好当节奏锚点。
  - **时序不变量**（用户硬要求："任意两张卡片的起步和完成时间都要不一样"）：第 i 张 `delay = i×STEP`、`duration = DUR + i×DSTEP`，STEP 与 DSTEP 同为正 ⇒ 起步与完成时间都严格递增，两两不撞；飞入段整体晚于飞出段一个 handoff，跨段也不撞。这条是**构造性保证**，不靠调参碰运气。
  - 参数：飞出 `110/14/5`、飞入 `160/16/6`，两段间空档 24ms；总时长 ≈ **520ms**（7 张卡）。比淡入淡出慢 2.7 倍，是这次改动实打实的代价 —— 换到"这一屏的东西被 physically 换走了"的连续感。要压回 300ms 内：两组 DUR 各砍半、STEP 降到 8/10，不变量仍然成立（已写进视觉稿的口径表）。
- 实测方式：CDP 驱动本机 Chromium，直接读 `document.getAnimations()` 的 `startTime + delay` 与 `activeDuration`，逐卡打印起步/完成/位移/末帧透明度 —— 起步与完成碰撞均为「无」，方向与顺序符合上述规则。截图留 3 张中程帧（`_shot-v3-fly-070/150/330.png`）。
- 过程中抓到两个真 bug：① 死区取 12% 时内侧左卡被判成"中部"改飞右侧，收到 3% 才对；② 飞出动画不写 `fill:forwards` 的话，先飞完的卡会在换屏前"复活"回原位（150ms 那帧拍到过）。
- 同步改了 `09` §1.1/§7 与 `10` 的切换动画口径；`04`（切片 1 契约）与 `mock-01` 未动。
- 待用户定：这套编排是否就是切片 2 终稿（是 → 冻结 mock-02，实现 agent 照做；否 → 继续调）。平台识别色两档与段位色提亮表仍挂着（第 14 轮遗留）。

## 2026-10-03 · 第 4 轮：判题边界 + 平台三角色梳理 + 数据同步机制

**判题（新问题：VP 没有测试数据怎么办？能不能像 VJ 那样代提交？）**

- 结论：**工作台不做判题、不做入口**。"判题永远发生在已经能判题的地方"——题在哪能交（CF Gym / QOJ / 洛谷 / 自家 VJ）就在哪交；工作台只负责：回放榜 + 把结果收进来叠加。
- VJ 式"模拟向 OJ 提交"（远程判题中转）的技术代价：维护各 OJ 登录态 + 模拟提交 + 轮询结果 → 极脆、维护地狱、ToS 风险；需要就用 VJ 本身，不自建。
- 本地判题（拿测试数据本地跑）：仅公开测试数据的场次可行（QOJ/UCUP 类），定位 P2 彩蛋；且本地自测已有 VS Code CPH 工作流，不重复造。
- CF Gym 提交**可能**可走官方 API 自动读（待实测：能否读到 gym 提交 + 时间能否换算成 VP 相对时间）；不行 → 一键手动记兜底。

**平台三角色框架（解决"有点乱"）**

1. **打题的地方**（交代码、出判定）：CF(含 Gym) / AtCoder / VJudge / QOJ / 洛谷 —— 工作台绝不取代。
2. **数据源**（做题史/rating/标签）：CF 官方 API（最全）· AT 社区数据（AtCoder Problems/kenkoooo）· 洛谷非官方接口 · XCPC = heimaom 管线 + srk-collection。
3. **榜单文档**（VP 用）：algoux/srk-collection · algoux 本地导出（补充）。

同一平台常身兼多角，按角色分开记：在 CF 交题（角 1），从 CF API 读数据（角 2）。
一句话：**判题永远在外面，数据永远往里拉，榜单永远只是文档。**

**数据同步机制（回答"启动拉 API 还是练习全搬到系统里"）**

- **同步式（选定方向）**：首次全量 + 启动增量 + 手动刷新；日常练习完全不变。CF 历史拉全量后，热力图第一天就能出图。
- 不做"入口式 VJ"：判题中转脆 + 体验打不过原生平台 + 工程巨大无独有价值。
- "半入口"只做两件事：跳转（一键到题目/提交页）+ 回填（结果自动/一键收回）。
- 平台接入优先级初判：CF → XCPC(heimaom) → AT → 洛谷 → VJ（手动）。（待用户认可）
