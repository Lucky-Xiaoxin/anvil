## 2026-10-03 · 第 4 轮：判题边界 + 平台三角色梳理 + 数据同步机制

**判题（新问题：VP 没有测试数据怎么办？能不能像 VJ 那样代提交？）**

- 结论：**工作台不做判题、不做入口**。"判题永远发生在已经能判题的地方"——题在哪能交（CF Gym / QOJ / 洛谷 / 自家 VJ）就在哪交；工作台只负责：回放榜 + 把结果收进来叠加。
- VJ 式"模拟向 OJ 提交"（远程判题中转）的技术代价：维护各 OJ 登录态 + 模拟提交 + 轮询结果 → 极脆、维护地狱、ToS 风险；需要就用 VJ 本身，不自建。
- 本地判题（拿测试数据本地跑）：仅公开测试数据的场次可行（QOJ/UCUP 类），定位 P2 彩蛋；且本地自测已有 VS Code CPH 工作流，不重复造。
- CF Gym 提交**可能**可走官方 API 自动读（待实测：能否读到 gym 提交 + 时间能否换算成 VP 相对时间）；不行 → 一键手动记兜底。

**平台三角色框架（解决"有点乱"）**

1. **打题的地方**（交代码、出判定）：CF(含 Gym) / AtCoder / VJudge / QOJ / 洛谷 —— 工作台绝不取代。
2. **数据源**（做题史/rating/标签）：CF 官方 API（最全）· AT 社区数据（AtCoder Problems/kenkoooo）· 洛谷非官方接口 · XCPC = heimaom 管线 + srk-collection。
3. **榜单文档**（VP 用）：algoux/srk-collection · algoux 本地导出（补充）。

同一平台常身兼多角，按角色分开记：在 CF 交题（角 1），从 CF API 读数据（角 2）。
一句话：**判题永远在外面，数据永远往里拉，榜单永远只是文档。**

**数据同步机制（回答"启动拉 API 还是练习全搬到系统里"）**

- **同步式（选定方向）**：首次全量 + 启动增量 + 手动刷新；日常练习完全不变。CF 历史拉全量后，热力图第一天就能出图。
- 不做"入口式 VJ"：判题中转脆 + 体验打不过原生平台 + 工程巨大无独有价值。
- "半入口"只做两件事：跳转（一键到题目/提交页）+ 回填（结果自动/一键收回）。
- 平台接入优先级初判：CF → XCPC(heimaom) → AT → 洛谷 → VJ（手动）。（待用户认可）

## 2026-10-03 · 第 3 轮：VP 理想流程确认 + 掌握度/分类方案（我方建议，待反馈）

**VP 理想体验（用户原话归纳）**：只要拿到"榜单文档 + 自己的提交结果"→ VP 时看虚拟回放榜滚到当前时刻 + 自己的行叠进去 + 罚时自动算 + 全场（含打星）排名可见 + **实时牌区**；对标 CF 的折腾流程（勾非正式 → 找自己 → 记罚时 → 切回正式 → 逐个翻排名 → 再切 xcpcio 看奖牌）。

- 轻路径初判：榜单从 `algoux/srk-collection` 直接拉（省掉找/导文件）；自己的提交先"手动一键记"（未来再看 CF gym 能否自动读）。

**要的是两张图（本轮澄清）**：

1. **活跃度格子图**（GitHub/洛谷式：日 × 做题量）——全局一张 + 每个算法大类各一张。
2. **掌握度热力图**（知识点 × 掌握程度）——H1 说的"热力图"。
   （两者数据同源但含义不同："出勤" vs "能力"。洛谷格子图形态直接参考。）

**掌握度方案（我的建议）**：

- 不做 0-100 玄学总分，做**"稳定难度带"**：估"你在多难的题上能稳定做出来"（各平台难度标尺通用：CF rating / AT 难度 / 洛谷 / heimaom 题目 rating）。
- 流水线：每道题 → 证据（d 难度，q 质量 [一次过 > 多次过 > 赛后独立补出 > 看题解/AI 过]，t 时间）→ 按节点聚合取**加权中位数难度 d\*** → 上色 = d\*，透明度/边框 = 样本量（≥3 道才实色；颜色点开可看"由哪几道题算出"）。
- 大类不取平均（会掩洞），短板提示方式待 UI 定。
- 分类树：**固定两级**（~12 大类 × 5-15 子类，对齐 QOJ 题型 / 洛谷标签 / OI-Wiki），**第三层不做**（数据稀疏 + 题目多标签 + 维护成本），细粒度（点分治/树剖…）→ 别名映射并入二级节点。
- 标签来源：CF API / AT 社区难度库 / 洛谷 / XCPC 侧 heimaom 的 QOJ 映射（2023 至今）；冷门手动补。
- 兜底：映射做不干净时，v1 先出"平台原生标签"版图，后归一。

**待用户**：方向是否一致（G2：方向一致才不弃坑）→ 然后聊最小骨架。
