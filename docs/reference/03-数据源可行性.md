## 1. 结论矩阵

| 平台 | 能拉什么 | 怎么拉 | 实测结果 | 风险 |
|---|---|---|---|---|
| **Codeforces** | ① 全部提交（含 Gym、VP；题目、判定、语言、时间）② CF 题自带 tags + rating ③ rating 史 ④ 全题库 tags + rating | 官方 API（无需 key）：`user.status`（分页 count ≤ 10000）、`user.rating`、`problemset.problems`；限速约 1 req / 2s | ✅ Benq 窗口 8585 条提交中含 **870 条 Gym 提交**；CF 题 `problem.tags/rating` 内嵌（实测例：`["math"], 3500`）；**Gym 题无 tags/rating**；`author.participantType` 可区分 PRACTICE / VIRTUAL；练习模式 `relativeTimeSeconds = 2147483647`（哨兵） | 低（官方接口） |
| **AtCoder** | ① 提交明细（题号/判定/时间）② 题目难度模型 ③ 参赛 / rating 史 ④ 比赛列表 | ①+②+④ 社区 kenkoooo（`kenkoooo.com/atcoder/` 路径下：`atcoder-api/v3/user/submissions`、`resources/problem-models.json`、`resources/contests.json`）③ **官方** `atcoder.jp/users/{u}/history/json`（单请求全量、无分页；**是参赛史不是提交史**；robots.txt 灰色 → 仅用户触发、不轮询） | ✅ 2026-10-04 复验全 200 且在更新（problem-models 隔日 +1.6KB）→ 否定 08 的「全系下线」；⚠️ kenkoooo 为社区 best-effort（无 SLA）：按"本地缓存 + 源状态 + 优雅降级"处理；history 对不存在 handle 返回 200+`[]`（不能判存在性） | 中（官方页灰色 + 社区源单点） |
| **XCPC（评级/赛事）** | rating 逐场轨迹、选手详情、比赛详情、题型面板、赛前预测；榜单原件 | `github.com/Hei-MaoM/xcpcrating` 导出 JSON（meta / contests-index / contests/<slug> / players/<shard> / leaderboards / period-index）；`github.com/algoux/srk-collection` | ✅ 契约已读，公开可直接消费 | 低 |
| **洛谷** | 题目数据（难度/标签）可拉；**用户提交记录难** | 页面请求带 `x-luogu-type: content-only` 头；提交记录列表需登录态 + 反爬严 | ⚠️ 题目页实测 200；记录列表 302（需进一步研究） | 中高（非官方、会变） |
| **VJudge** | 无官方 API；仅老的非官方抓取项目 | 不自动 → 手动记录 / 以后浏览器辅助 | ❌ 证实用户判断 | 高（放弃自动） |
| **QOJ** | 未测 | — | ⏳ 低优先 | 待查 |

## 3. 两个关键发现

1. **VP 自动记录大概率成立**：CF Gym 提交能通过 `user.status` 拉到，且带 `participantType`（VIRTUAL 可辨）与场内相对时间。等一场真实 VP 后拉一次 API 即可定案（列入待实测）。
2. **标签自动覆盖率比预想高（AT 除外）**：CF 题内嵌标签、XCPC 有 QOJ 映射、洛谷站内有标签——"掌握度热力图"的自动填充在主流数据上基本成立，只有 Gym / 老比赛题需要手动补。**AT 侧无规范标签源（仅个人仓库），暂不进掌握热力图**（AT 难度可拉，但热力图按知识点组织、需要标签）。
