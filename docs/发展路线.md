## 1. 产品边界

- 形态：本地 Web，Windows 优先；判题在外面，数据往里拉，榜单只是文档。
- 三模块：个人数据（CF / AT / XCPC）、模拟榜单（目录 / 回放 / 成绩）、工坊（文件编排 / 导入 / 题目标记）。
- 工坊管文件编排与训练标记，不管代码内容、不判题、不做流程教练。
- 旧 v1.0 的赛后复盘 / 补题簿 / SRS 不做；用**题目标记 + 待补汇总**替代。需要更重的复盘时另立契约，不回头补旧管线。
- 看板是本地可视化（数据在浏览器），不作为仓库资产；本文是文本权威版。

## 4. 推荐顺序

1. **5e 赛后题目标记**（当前）。
2. **5b 模板工作流**（去掉词表编辑）。
3. **拍板个人赛事入口**；决定后再看是否扩题目标记覆盖。
4. **打磨批次**：junction 跳过判据、UI 测试基建、P3。
5. **掌握图**：只有题目标记积累出可用证据、且你确认要看“知识点强弱”时再立项；否则不做。

不做时间承诺；顺序按依赖与验证价值排。

---

## 5. “完整”的尺子

- 按当前三模块口径：约 **4/5**；缺 5e、5b、个人赛事入口拍板、打磨欠账。
- 按旧 v1.0 闭环口径：约 **6 成**；但旧管线后半段已被主动放弃，不作为目标。
- 日常可用的判断：首页回答“我最近怎么样”；题目标记上线后，工坊能回答“这场还欠哪几题”。不做“今天该练什么”的教练型推荐。

## 7. 工作方式

- 一个批次 = 一个分支 = 一个 PR；契约 / 实现 / 报告 / 截图同分支。
- 契约草案在分支上保持“草案”；实现合并前改“现行”；main 只留合并后的现行文档。
- 新决策先改本文，再改契约；本文不替代契约、不复制实现细节。
- 看板只做可视化；与本文冲突时以本文为准。
