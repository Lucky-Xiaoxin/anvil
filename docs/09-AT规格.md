## 2. 数据源（2026-10-04 实测，照抄）

**AT 提交明细（社区 kenkoooo）**：

```
GET https://kenkoooo.com/atcoder/atcoder-api/v3/user/submissions?user={h}&from_second=0
→ [{id, epoch_second, problem_id, contest_id, user_id, language, point, length, result, execution_time}]
```
单请求全量、无分页；一次同步只打 1 次。大号响应可达数 MB → 超时放宽（≥60s）。

**AT 参赛 / rating 史（官方）**：

```
GET https://atcoder.jp/users/{h}/history/json
→ [{IsRated, Place, OldRating, NewRating, Performance, InnerPerformance,
    ContestScreenName, ContestName, ContestNameEn, EndTime}]
```

**坑（照抄处理）**：

- `history/json` 对**不存在的 handle 返回 200 + `[]`** → 不可用于存在性校验；校验用 `GET https://atcoder.jp/users/{h}` 的页面状态码（200/404）。
- `ContestScreenName` 形如 `agc078.contest.atcoder.jp` → `contest_key` = 去掉 `.contest.atcoder.jp` 后缀（`agc078`）。
- `IsRated:false` 条目 OldRating==NewRating、Performance=0 → **主曲线只收 `IsRated:true`**；非 rated 只计入"参赛 N 场"。
- kenkoooo 是**社区 best-effort 源（无 SLA）**：失败不得阻塞 CF；重试 = 串行、429/5xx 退避 ≤2 次；成功结果缓存本地。
- ⚠️ 端点主机是 `kenkoooo.com/atcoder/…` 这条路径；`atcoder-api.kenkoooo.com` 等旧子域已死，别用（详见 `docs/08` 复验注记）。
- 限流：kenkoooo ≈ 1 req/s、官方同低频；**全程串行，不并发**。`history/json` 属官方 robots 灰色口径 → **仅用户点击触发**。

## 3. 基建：多源化

### 3.1 Schema v2（`vault/anvil.db`，v1→v2 事务内重建 + 幂等）

```sql
-- submissions：加 source 列，主键改 (source, id)（重建表迁移）
CREATE TABLE submissions (
  source TEXT NOT NULL DEFAULT 'cf',
  id INTEGER NOT NULL,              -- CF 提交 id / kenkoooo 提交 id（不同命名空间，勿混）
  contest_id INTEGER,
  problem_key TEXT NOT NULL,        -- 'cf:{contestId}:{index}' / 'at:{problem_id}'
  problem_name TEXT, problem_rating INTEGER, problem_tags_json TEXT,
  verdict TEXT, language TEXT, participant_type TEXT,
  created_ts INTEGER NOT NULL, relative_ts INTEGER,
  PRIMARY KEY (source, id)
);
-- rating_history：重建为 source 化
CREATE TABLE rating_history (
  source TEXT NOT NULL, contest_key TEXT NOT NULL,   -- CF: "2268" / AT: "abc300"
  contest_name TEXT, rank INTEGER,
  old_rating INTEGER, new_rating INTEGER,
  is_rated INTEGER NOT NULL DEFAULT 1,
  updated_ts INTEGER,
  PRIMARY KEY (source, contest_key)
);
```

- CF 迁移：`source='cf'`、`contest_key = CAST(contest_id AS TEXT)`、`is_rated=1`。
- `sync_state` 键按源命名（`cf:last_sync_at`、`at:last_sync_at`）。

### 3.2 配置与校验

- `vault/config.json` → `{ cfHandle, atHandle?, port }`。
- AT handle 校验：宽松字符集 `[A-Za-z0-9_\-\.]{1,64}`，**存在性走 `/users/{h}` 页面状态码**（§2）。
- 设置页两行：CF / AT，各含 handle 输入、校验、源状态、上次同步、单源同步按钮。

### 3.3 SyncSource 接口（冻结，供本切片 + 未来 XCPC 用）

```ts
interface SyncSource {
  id: 'cf' | 'at'
  checkHandle(handle: string): Promise<{ ok: true } | { ok: false; message: string }>
  sync(handle: string, onProgress: (p: SyncProgress) => void): Promise<SyncResult>
}
```

**必须**：按源域清空/重建（换 AT handle 只清 `source='at'`）；单源失败不影响其它源；进度按源上报。

## 4. API 变化

```
GET  /api/status    -> 顶层保持兼容 + sources: { cf: {configured, handle, lastSyncAt, counts, status}, at: {...} }
POST /api/config    { cfHandle?, atHandle? }        # 分源校验；换 AT handle 只清 AT 数据
POST /api/sync      { source: 'cf' | 'at' }          # 默认 cf
GET  /api/sync/state -> { cf: {...}, at: {...} }     # CF 字段保持切片 1 语义；AT 无 pages/offsite 概念
GET  /api/dashboard?source=cf|at                     # 默认 cf；与切片 1 同构 payload；source=xcpc → 501
```

- AT payload 增量：`rating.series[]` 附 `place? / performance? / isRated`（tooltip 用）；`stats.entryCount`（"参赛 N 场"）。
- 取不到值一律 `—`（沿用 `docs/04` §4.4 规则）。

## 5. AT 卡口径（诚实标注）

- 4 统计卡与 CF 同构：总过题（`distinct problem_id` 首次 AC）/ 当月过题（+ 近 6 月柱）/ AT Rating / 连续训练——**聚合函数直接复用 `packages/shared`，输入换成 AT 提交**。
- rating 卡：`rankLabel` = **AT 原生色名**（Gray / Brown / Green / Cyan / Blue / Yellow / Orange / Red），颜色 = AT 原生色；副行 = "参赛 N 场（非 rated M 场）"；tooltip 附 `Place`（"第 59 名 · Perf 2455"）。
- **诚实标注（一行，从简）**：`2016 起 · 参赛史非提交史 · 来源：AtCoder 官方页 / AtCoder Problems`。
- 活跃格子：与 CF 同构（当日 AC 去重题数、5 档、tooltip），标题注明平台。

## 6. 时区钉死

- 全部日/月分桶改为**固定 `Asia/Shanghai`**：offset 算术 `new Date((epoch + 8*3600) * 1000)` + UTC getter；禁止依赖运行机时区。
- 设置页脚注："时区口径：Asia/Shanghai（固定）"。
- 单测：epoch → day 映射与运行环境 TZ 无关。

## 7. UI / 视觉

- 以 `design/mock-02-three-ends.html` 为视觉基线（产出后冻结）；组件复用切片 1（`StatCard / ActivityGrid / RatingChart / Wizard` 等）。
- 平台识别色只作用于：tab 选中指示、详情区标题 accent、统计卡底部读数线（强度以 mock-02 两档对比定稿为准）；**热力色阶与琥珀主色不动；rating 数字颜色走段位色规则**。
- 切换动画：渐隐渐出 ≤200ms；reduced-motion 直落。

## 8. 测试与验收

- 单测：v1→v2 迁移幂等（重复迁移不炸、CF 数据完好）；AT 同步（`contest_key` 清洗、`IsRated` 分流、`200+[]` 判空、kenkoooo 响应解析、重试退避）；按源清库（换 AT handle 不动 CF）；时区固定；聚合复用用例回归。
- 手测：设置页配 AT handle → 同步 → AT tab 全量呈现；模拟源不可达 → 缓存 + 提示不崩；切 tab 动效；CF tab 回归（无锁定卡、曲线整行、数字不变）。
- reviewer 验收：真实 AT handle 冒烟（可用公开 `chokudai`）；对照 AtCoder 官方页面抽查 2-3 个数字（rating / 场次）。

## 9. XCPC 契约（先行冻结，本切片不实现）

- **数据源**：heimaom 静态导出 `https://heimaom.cn/data/…`（GitHub Pages 同源备份）。关键文件：`meta.json`（`generatedAt` 当版本号）、`players/<shard>.json`（shard = md5(key) 前 2 位十六进制）、`contests-index.json`、`contests/<slug>.json`；身份搜索走 `search/players/<首字符 shard>`（站点自身实现，含拼音首字母回退——可直接沿用其分片约定）。
- **身份模型**：key = `姓名@学校`（其管线规范化后的原样字符串）。认领流程：设置页输入姓名 → server 拉候选分片 → 用户选 → 存 `xcpcPlayerKey`。
- **数据形状**（PlayerDetail 摘要）：`{key, name, org, contests, rating, allRank, officialRank, officialRating, medals?: {final|regional|invitational|provincial: {gold, silver, bronze}}, history: [{contestId, title, startAt, teamName, rank, teamCount, official, rated, perf, rating_after, rankOfficial, teamCountOfficial}], skillPanel?}`。两榜（all / official），本工具默认用 **official**。
- **未来 dashboard 形态**（切片 3 再设计）：`source=xcpc` payload = rating 轨迹 + 逐场记录 + 奖牌统计；**无活跃格子**（该源没有提交粒度）。
- **兼容性**：`rating_history` 直接容纳（`source='xcpc'`、`contest_key`=slug）；`submissions` 不使用。
- 展示口径预留：XCPC rating **无段位色名**（不套 CF/AT 规则）；`skillPanel`（13 轴、grade、topPercent）留给掌握图切片，不在 XCPC 卡首版展示。
