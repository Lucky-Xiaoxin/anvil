## 0. 一句话目标

给工作台加第四块：**「模拟榜单」**——从一张收录 394 场 ICPC/CCPC/省赛的目录里挑一场，用真实榜单数据**回放比赛过程**（计时、封榜、任意时刻重建、终榜回顾）。这是"跟榜"工具：你自己在别处做题，榜单按真实节奏走给你看。

## 1. 数据现实（先理解再动手 · 全部为 2026-10-07 实测）

**来源**：`algoux/srk-collection` 的静态导出，经 jsDelivr 直取（社区整理的官方榜单快照，**非官方**；我们的界面按惯例标来源）。两个文件：

1. **目录** `official/config.yaml`（48KB）：一棵树，**394 场比赛**。五类顶层：ICPC / CCPC / 省赛（按省分组）/ 校级 / UCUP → 年份 → 场次；场次叶子名自带日期，如「2025-11-16 沈阳站」「2026-04-11 深圳邀请赛」。
2. **单场榜单** `official/<路径>.srk.json`（**单场 1.5MB 级**，进榜单页加载一次）——以 2025 上海站实测解剖：

| 维度 | 实测数据 | 设计含义 |
|---|---|---|
| 规模 | **356 队**（正式 331 + 打星 25）· **13 题** | 榜是长表：13 个题列 + 6 个信息列，密度是本稿第一难题（见 §2 必答） |
| 时长 / 封榜 | 5 小时；本场未声明封榜段（**缺省按 1 小时**） | "封榜"是视觉重头戏：最后 1 小时答案隐藏 |
| 奖牌 | 金 30 / 银 60 / 铜 90（按正式队名次，ICPC 预设） | 行底金/银/铜色带，回放中实时滚出 |
| 提交明细 | 每队每题含**逐次提交时间戳（毫秒）**+ 结果 | 可以重建"任意时刻"的榜单——回放/时间轴的底气 |
| 结果枚举 | AC / FB / WA / TLE / RTE / CE（+ 冻结占位 `?`） | 题目格的状态设计要覆盖全 |
| 题目标题 | 有（英文题名；含 0 AC 的题、FB 深绿） | 列头给别名 + 悬停全名；题格"首杀"值得一档色 |
| 队伍 | 队名 + 学校 + **三名队员姓名** + 机位号 + 打星标记 | 队伍弹层有真内容可放 |
| 开始时刻 | `startAt` 带时区（如 2025-11-23T09:00:00+08:00） | 目录行可展示日期（现成在名字里） |

**回放机制**（数据全在本地，纯前端）：进榜 → 时钟从 0:00 走 → 每秒按"时间 ≤ 当前"过滤提交重建榜 → 封榜段答案打码 → 走完自动落回顾模式（滑条拖到任意时刻）。**"开始模拟"点下去就开钟，不做准备页；刷新/离开再回来按开始时刻续钟**。

**诚实标注**：数据来源 algoux/srk-collection（社区快照）· 回放的是已打完的比赛 · 封榜/时间轴为模拟。

## 2. 要设计什么（三屏 + 组件屏）

**s1 · 模拟榜单主页（赛事目录）**
- 入口 = 侧栏「模拟榜单」（新名字，见 s4 壳）。内容区承载：**树/分组目录**（五类 → 年份 → 场次）+ 一个搜索框（按赛事名过滤）。
- 每场一行：日期 + 名称 + 两个动作「**开始模拟**」「**查看终榜**」。行信息密度可参考切三编年表的克制感。
- 态：加载中（拉 config）/ 加载失败（CDN 不可达）/ 搜索无结果。

**s2 · 回放榜（进行中 · 建议画在"封榜时刻"附近）**
- 顶栏：比赛名（长名截断）+ **计时器** + 「回到目录」+（封榜段内可给一个显式"封榜中"提示）。
- 筛选：仅正式队（默认关）/ 含打星。
- 榜体：`R#`（金/银/铜行底）· `S#`（学校排名，仅该校头名显示）· Organization · Team（★=打星）· Solved · Penalty · **A–M 十三个题列**。
- 题目格五态：空 / 罚时中（`-n` + 末次时间）/ AC（时间 + 次数）/ FB（首杀深色变体）/ **封榜冻结（灰 + `?n`）**。点击 → 提交明细弹层（逐次结果 + 时间）。
- 队伍弹层（点队名）：队名 / 学校 / 三名队员 / 打星标记 / 机位号。

**s3 · 回顾模式（终榜 + 时间轴）**
- 走完自动进入：无计时器，出现**时间轴滑条**；拖动重建任意时刻的榜（含封榜段内的"历史封榜态"也要能看）。
- 与 s2 共用榜体，差异只在顶栏与滑条区。

**s4 · 组件与状态（兼必答对照 · 含壳改动）**
- 组件卡：题目格全状态横排、奖牌行底三色、目录行（默认/hover/进行中）、队伍弹层、提交明细弹层、空/错/加载态。
- **壳·侧栏收起态**（本稿唯一壳改动）：收起按钮位置；收起后只留图标轨道（宽度自行主张），**悬停显示文字**（样式走全站 tooltip 体系或小浮标，你定）；收起态下 navfoot 的处理（内容裁掉还是只留符号）。**顺带把导航三处新名字直接画进稿**：`个人数据` / `工坊` / `模拟榜单`（`设置` 不变）。

**必答四题**（完成时逐条给主张）：
1. **表格密度与列宽**：内容区约 1030px（1440 基准）要放下 6 信息列 + 13 题列——题列最小尺寸、字号与行高的取值；1280 下是收窄还是榜表内部横滚，给方案与理由（切三编年表定的是"不横滚"，但榜单表列更多，**允许你推翻**，说清代价即可）。
2. **模块识别色**：倾向不给新平台色（保持中性，竞赛语义色就够：AC 绿 / 罚时红 / 冻结灰 / 金银铜）；若你认为需要一个"模拟榜单"的模块强调色，给对照并说明。
3. **封榜态表达**：冻结格 + 榜内提示的强度（既要看得出"在封榜"，又不能盖过表格本身）。
4. **侧栏收起态**：样式与悬停文字的做法。

## 3. 硬约束（沿用，不得破）

- tokens / 组件 / 动效全部沿用 mock-01/02/03x；**手写 CSS、零外部依赖**；1440×900 基准 + 1280×800 不破版；reduced-motion 直落终值。
- 文案从简：不写解释性注释；口径与来源进脚注/tooltip；开发细节不进 UI。
- **不要参考任何第三方站的视觉**（浅色苹果风之类）——功能清单见附录，本稿必须是深色工作台家族的第四块。
- 演示数据：**种子生成/手编 100–120 队即可**（视觉等价于真实的 356 队），但形状严格贴近实测：13 题（含 1 题 0 AC、1 题有 FB）、金 30 银 60 铜 90 的奖牌区、≥8 支打星队分散、队伍带学校与三名队员；至少覆盖"回放中（含封榜时刻）"与"终榜回顾"两态。确定性数据、页脚"数据为演示假数据"。
