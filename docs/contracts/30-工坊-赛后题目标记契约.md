## 已拍板

1. **标记单位 = 某一场比赛的某一题（`contest` + `alias`），不是某一次 VP / 某一份存档。** 同一场比赛打多次，只有一份题目标记；多存档仍各自记录“那一次打成什么样”。
2. **进度三态 + 重点星标。** 进度 = `待补题` / `已补` / `已过`；重点 = 独立星标，可与任意进度共存，也可以只有重点或只有标签。三者全空 = 未标记。
3. **预填只填 AC。** 保存成绩时只把“我的成绩”里 AC 的题预填成 `已过`；只填空，不覆盖已有进度；非 AC 不预填；`待补题` 永不自动。
4. **保存后提示，由用户决定。** 保存成绩成功后，在榜单顶层给一条提示「成绩已保存 · 去标记这场题目？」+ `去标记` / `暂不`；不自动跳转，是否跳转、是否标记都由用户决定。
5. **未标记的不管它。** 不统计、不筛选、不提醒，也不推断“能力之外”。未标记 = 未评估 / 不纳入。
6. **主题标签只存在于题目行。** 题目行有进度、重点或标签即算“已标记”；三者全空回到未标记。对象级主题标签（`primary` / `related`）、两级词表、`TagTree`、主题筛选 / 交集筛选、5b 词表编辑全部退役；对象级自由标签（`labels`）保留作检索。
7. **掌握图（5d）暂不做，从近期路线图移除。** 本片不为掌握图预留数据结构；题目标签只服务待补 / 重点汇总与检索。
8. **不关联具体代码文件。** 不做单题目录对象，不把 `A.cpp` 绑到题号，不从文件名推断题号；不做补题状态机、SRS、复习提醒、每日任务。

## 3. 语义与数据

### 3.1 身份与作用域

- 标记挂在工坊 `contest` 对象上，身份仍为 `contest.id`；官方场次仍由 `arenaPath` 唯一确定。
- 一个比赛一份 `problem-marks.json`；不是 `WorkKind`，不进入对象 / 标签计数，不改变比赛 `updatedAt` 或默认模板排序。
- 同一 `arenaPath` 的多份成绩存档共享这一份标记；存档不是标记的归属单位。
- 比赛没有 `arenaPath`（非官方 / 自建场）→ 不提供题目标记；详情不显示该区。
- 比赛有 `arenaPath` 但没有题目清单 → 详情显示「还没有题目清单」+ `从榜单补齐`；用户点补齐后建立快照，全部未标记。
- 换受管根不迁移标记；同一 `arenaPath` 在另一个根里是另一场比赛，标记不共享。

### 3.2 文件与 schema

位置：比赛文件夹根目录 `problem-marks.json`，与 `record.json` 同级；不放进 `.anvil-records/`。
扫描器把它视为受管元数据（加入工坊元数据文件名单，与 `.anvil.json` / `record.json` 同级处理），不能登记成对象、不能作为题组候选、不能通过 import 收编；文件列表可显示，但标注为元数据。

```json
{
  "schema": 1,
  "arenaPath": "official/icpc/icpc2025/icpc2025shanghai.srk.json",
  "problems": [
    { "alias": "A", "title": "A. 某某题" },
    { "alias": "B", "title": "B. 另一题" }
  ],
  "marks": {
    "A": { "progress": "contest-ac", "star": false, "tags": [], "updatedAt": "2026-10-30T12:00:00.000Z" },
    "B": { "progress": "todo", "star": true, "tags": ["dp"], "updatedAt": "2026-10-30T12:00:00.000Z" }
  },
  "prefillApplied": ["A"]
}
```

| 字段 | 规则 |
|---|---|
| `schema` | 固定 1；读到 `schema > 1` → 409 `conflict`，不降级、不覆盖；未知顶层字段在重写时保留。 |
| `arenaPath` | 必须与宿主比赛的 `links.arenaPath` 一致；不一致 → 409 `conflict`（手改 / 复制文件夹造成）。 |
| `problems` | 题目清单快照，按榜单顺序；最多 40 题；`alias` 唯一、匹配 `^[A-Za-z0-9_-]{1,8}$`；`title` 最多 200 字符，可为空。 |
| `marks` | 键必须是 `problems` 中的 `alias`；未知 alias 不进入 DTO，文件原样保留，界面提示“有标记未能读取”。 |
| `marks.*.progress` | 三态 `todo` / `post-solved` / `contest-ac`；缺省或 `null` = 没有进度。 |
| `marks.*.star` | 布尔；缺省 false。 |
| `marks.*.tags` | 自由文本数组；最多 8 个，每个 1–24 字符（去首尾空白、去重、去空）；不允许换行 / 控制字符。 |
| `marks.*.updatedAt` | 服务端写入的 ISO 时间；客户端不传。 |
| `prefillApplied` | 服务端内部字段：曾经自动预填过的 alias；用于“清空后不再反复填回”。不进入 DTO。 |

- 条目存在规则：`progress != null || star === true || tags.length > 0`；三者全空即删除该 alias 的条目。
- 空文件（`marks: {}`）合法；`problems` 为空不合法（至少 1 题；实测榜单均有题）。
- `prefillApplied` 只增不减；它不表示“用户看过”，只表示“自动预填发生过”。

### 3.3 标记规则

| 当前 | 动作 | 结果 |
|---|---|---|
| 未标记 | 选 `待补题` / `已补` / `已过` | 对应进度；条目存在 |
| 未标记 | 点 `重点` | 只有星标；条目存在，进度仍为空 |
| 未标记 | 加标签 | 只有标签；条目存在，进度仍为空 |
| 任意 | 改进度 / 星标 / 标签 | 立即持久化；不改其它题 |
| 任意 | 清空进度、关星标、删完标签 | 条目删除，回到未标记 |

- 进度是**人工声明**，不按提交时间、AC 时间或存档结束时间自动改写；唯一自动写入是 §3.4 的 AC 预填。
- `已过` / `已补` 的区分由用户判断；系统不检查先后顺序，也不因第二次存档自动改状态。
- `待补题` 是用户意图，不是“有提交但没过”的系统推断；非 AC 提交永远不自动进入待补。
- 没有历史记录 / 审计 / 撤销；本片只有一个当前状态。需要历史另立契约。
- 未标记的题不进入任何汇总、筛选、提醒；这是产品语义，不是空态文案的客套话。

### 3.4 AC 预填

输入：题目清单快照、当前 `marks`、`prefillApplied`、本次保存的成绩存档 `ghost.subs`。
`ghost.subs[].p` 是榜单题序（0-based），按 `problems[p].alias` 映射。

```text
for sub in ghost.subs:
  if sub.r != 'AC': continue
  alias = problems[sub.p]?.alias
  if alias == null: continue
  if marks[alias]?.progress != null: continue      # 不覆盖手选
  if alias in prefillApplied: continue              # 用户清空过，不再填回
  marks[alias] = { progress: 'contest-ac', star: false, tags: [], updatedAt: now }
  prefillApplied += alias
```

- 只预填 `contest-ac`（UI 文案「已过」）；不预填 `todo` / `post-solved`。
- 已有进度（包括用户手选 `待补题` / `已补` / `已过`）一律不动。
- 只有星标 / 只有标签、进度为空的题，AC 时可以补上 `已过`（星标 / 标签保留）。
- 重复保存同一份成绩：第一次填过的 alias 已在 `prefillApplied` 或已有进度，不再变化；幂等。
- 用户把自动预填的 `已过` 清空后，再次保存同一场不会填回（`prefillApplied` 拦住）；这是刻意行为，避免“清不掉”。
- 记录找不到 / `recordId` 不属于该比赛 → 不预填；同步题目清单仍可成功（如果请求不带 `recordId`）。
- 服务端不信任客户端传来的“AC 列表”；只读存档 `ghost`。没有 `ghost` 的补录成绩（`manual` 且零提交）不预填。

### 3.5 汇总口径

| 字段 | 计算 |
|---|---|
| `total` | `problems.length` |
| `marked` | `Object.keys(marks).length`（有任何进度 / 星标 / 标签的题） |
| `todo` | `progress === 'todo'` 的数量 |
| `starred` | `star === true` 的数量 |

- 未标记不计入 `marked`、`todo`、`starred`；`marked < total` 是正常的。
- 列表徽章只显示 `todo > 0` 的 `待补 N` 与 `starred > 0` 的 `重点 M`；两者都为 0 不显示。
- 详情汇总可额外显示 `已过 / 已补` 数量，但列表不摊开。

### 3.6 对象级标签退役

- **删除**：`primary` / `related` 编辑 UI、`TagTree`、标签筛选、标签计数、主题词表读取、`aliases` 检索、5b 词表编辑 UI。
- **保留**：对象级自由标签 `labels`（最多 20 个、每个 24 字符，沿用 23）；用于检索与快速标记，不做主题分类。
- **数据**：现有 `.anvil.json` 的 `primary` / `related` 原样保留，不删除、不重写；读取忽略，界面不再展示。不做自动迁移到 `labels` 或题目标记。
- **模板分类**：模板的「一级分类」选择器随词表退役；新建模板统一落 `templates/_unsorted/`，旧模板已在其它分类目录里的不搬。
- **词表文件**：已有 `.anvil/taxonomy.json` 原样保留、不读取、不删除；新建工作区不再生成。
- **检索**：对象搜索只覆盖 `title` / `labels` / `relPath`；不再拼 `primary` / `related` 的节点名。`TODO(切片5b)` 的别名检索一并取消。
- **DTO**：`WorkObjectDto` / `WorkObjectDetailDto` 不再返回 `tags.primary` / `tags.related`；`labels` 保留。
- **写接口**：`POST /api/work/update` 删除 `tags` 入参；不再写入 `primary` / `related`；`labels` 保留。旧客户端传 `tags` 按 400 `invalid`，不静默忽略。
- 23 的 §7（两级标签）与 §15.2（词表编辑 / 别名检索）由本篇部分接管；对象模型、路径、安全、导入、回收站规则不变。

### 3.7 生命周期与兼容

| 场景 | 行为 |
|---|---|
| 建立快照 | 第一次 `sync` 写入 `problem-marks.json`；全部未标记；不自动建“待补”。 |
| 再次 `sync` | 同一 `arenaPath`：alias 集合一致 → 更新标题、保留标记；alias 集合不同 → 409 `problem-set-mismatch`，不静默丢标记。本片不提供自动重建 / 合并入口；提示只说明原因，不引导到只在无快照时出现的「从榜单补齐」。 |
| 归档比赛 | 对象编排只读仍沿用 27；**题目标记例外可写**。详情顶部提示「已归档；题目标记仍可修改」。 |
| 比赛移入回收站 | 比赛目录连同 `problem-marks.json` 一起移动；不产生独立标记回收条目。恢复整场时原样回来。 |
| 存档改名 / 回收 / 恢复 | 不触碰 `problem-marks.json`；多份存档共享标记。 |
| 换受管根 | 标记不迁移；新根里的同 `arenaPath` 是另一场比赛。 |
| 文件损坏 / schema 过高 | 详情显示错误；列表不显示汇总徽章；不覆盖、不自动修复；其它功能不受影响。 |
| 删除比赛永久 | 随整站清空一起删；本片不提供标记级永久删除。 |
| 旧数据 | 没有 `problem-marks.json` = 全部未标记；不补造。 |

## 4. API / DTO

### 4.1 DTO

```ts
type ProblemMarkProgress = 'todo' | 'post-solved' | 'contest-ac';

interface ProblemMark {
  progress: ProblemMarkProgress | null;
  star: boolean;
  tags: string[];
  updatedAt: string;
}

interface ProblemMarksDto {
  contestId: string;
  arenaPath: string;
  revision: string;                 // 原文件字节 SHA-256
  problems: { alias: string; title: string }[];
  marks: Record<string, ProblemMark>;
  /** 快照外的手写标记条目数；> 0 时界面提示“有标记未能读取”，文件原样保留 */
  unreadableMarks?: number;
}

interface ProblemMarkSummary {
  total: number;
  marked: number;
  todo: number;
  starred: number;
}
```

- `WorkObjectDto` 对 `contest` 增加可选的 `problemMarkSummary?: ProblemMarkSummary`；没有合法文件 / 没有 `arenaPath` 时不返回。
- `WorkObjectDetailDto` 对 `contest` 增加 `problemMarks?: ProblemMarksDto | null`；没有 `arenaPath` 或没有文件时为 `null`，并在需要时给 `problemMarksError?: string`（损坏 / schema 过高 / 宿主不一致）。
- `WorkTreeDto` 增加 `problemTags: string[]`：本工作区所有合法题目标记里用过的标签，去重、最多 200，按使用次数降序再按字母序；用于详情标签输入的自动补全，不读词表。
- 详情仍从 `GET /api/work/object` 一次拿到；列表徽章与标签补全从 `GET /api/work/tree` 一次拿到，不新增 N+1 请求。

### 4.2 接口

| 方法与路径 | 入参 | 成功结果 |
|---|---|---|
| `POST /api/work/problem-marks/sync` | `{ arenaPath, problems: [{alias,title}], recordId? }` | 200 `{ problemMarks: ProblemMarksDto }`；首次创建 / 幂等重试均为 200 |
| `POST /api/work/problem-marks/update` | `{ arenaPath, expectedRevision, marks: Record<string, { progress, star, tags }> }` | 200 `{ problemMarks: ProblemMarksDto }` |

- `sync`：
  - `recordId` 形状沿用 29 的存档地址（`rec_...` / `legacy`）；不接受其它值。
  - 按 `arenaPath` 找唯一宿主（活动 / 归档；回收站里 → 409 `conflict`；重复 → 409 `conflict`；完全没有 → 404 `not-found`）。
  - 首次写文件；已有文件时校验 alias 集合一致，更新标题，保留标记；不一致 → 409 `problem-set-mismatch`。
  - `recordId` 有值且属于该比赛 → 读该存档 `ghost`，按 §3.4 预填；`recordId` 不属于 / 不存在 → 404 `not-found`，不写标记（快照仍可另请求）。
  - 不带 `recordId` → 只建 / 更新快照，不预填。
  - 幂等：同输入重复调用不产生重复标记、不反复填回已清空的自动标记。
- `update`：
  - 必须是已存在 `problem-marks.json` 的比赛；文件不存在 → 404 `not-found`（先 `sync` 建快照）。
  - 整份 `marks` 替换；服务端重算 `updatedAt`、保留 `prefillApplied`、删除全空条目；客户端不传 `prefillApplied` / `updatedAt`。
  - `expectedRevision` 不匹配 → 409 `conflict`；客户端重新读取后重试，不自动合并、不静默覆盖。
  - 归档比赛允许写；对象 meta 的归档冻结不由本接口绕过。
- `bodyLimit` 64 KiB；题目最多 40、每份标记最多 8 个标签，远低于上限；超限 413。
- 写请求沿用全局 `application/json` + 本机 Origin / `Sec-Fetch-Site` 防护；与工坊其它写入共用写队列。

### 4.3 错误

| 状态 | kind | 场景 |
|---|---|---|
| 400 | `invalid` | alias 不在快照 / 非法 alias / 标签超限 / 进度枚举非法 / `problems` 为空或重复 |
| 404 | `not-found` | 没有宿主比赛 / 没有 `problem-marks.json` / `recordId` 不存在或不属于该比赛 |
| 409 | `conflict` | 版本过期、宿主重复、宿主在回收站、`arenaPath` 不一致、`schema > 1`、手改导致不可读 |
| 409 | `problem-set-mismatch` | 已有快照的 alias 集合与本次 `problems` 不一致；不静默丢标记 |
| 413 | — | 请求体超限 |
| 500 | `internal` | 读写异常；保留可恢复内容，详情见 `vault/anvil-server.log` |

## 5. 安全与原子性

- `problem-marks.json` 路径固定由服务端定位；客户端只传 `arenaPath` / `contestId`，不传文件路径。
- `arenaPath` 复用既有 `contestPathOk` 白名单；写入前重新核对宿主与 `arenaPath` 一致。
- alias 必须匹配 `^[A-Za-z0-9_-]{1,8}$` 且在快照内；拒绝 `__proto__` 等原型键（用 `Object.create(null)` / Map 解析）。
- 标签清洗：去首尾空白、去重、去空、限长；拒绝换行 / 控制字符；不做 HTML 拼接（前端渲染仍按文本转义）。
- 版本 = 原文件字节 SHA-256；读取返回、更新必带；手改文件同样让旧版本失效。
- 写入 = 同目录临时文件 + 原子替换；失败保留旧文件并清理本次临时文件；与工坊其它写入共用写队列。
- 每级已存在路径检查普通文件 / 目录与根内归属；不跟随 symlink / junction；越界返回 `unsafe-path`。
- 读取不做网络请求；题目快照由客户端从已加载 / 已缓存的榜单提供，服务端不代拉。
- `schema > 1` 不降级、不覆盖；未知顶层字段重写时保留。
- 归档例外：标记写入允许；对象 meta / 标题 / parent / labels / trash 仍按 27 拒绝。实现时不要把归档冻结错误地套到标记接口。
- 回收站：标记文件随比赛目录移动；恢复按整场恢复；不提供标记级回收 / 永久删除接口。

## 6. 界面 / 状态 / 交互

### 6.1 榜单保存成功后的提示

- 成绩保存成功后，在榜单顶层出现一条**非阻塞**提示条（不是 modal，不自动跳转）：
  - 主文案：`成绩已保存 · 去标记这场题目？`
  - 按钮：`去标记` / `暂不`
  - 副文案：`只标记你在意的题；没标记的不影响统计。`
- `去标记` → 深链 `#/master?object=<contestId>&panel=problems`；打开工坊比赛详情并定位到题目标记区。用户可用详情里的 `回到回放` 回榜单。
- `暂不` / 关闭 → 只关提示，不改变保存结果、不改变任何标记。
- 每次保存成功都可以出现；不做“只提示一次”的持久抑制。查看历史 / 只读不出现。
- 题目清单同步失败时：提示条改为 `成绩已保存 · 题目清单同步失败（原因）` + `重试` / `去工坊`；成绩不回滚。详情里是否有「从榜单补齐」取决于有没有快照，提示条不再做此承诺。
- 清单与当前榜单的 alias 集合不一致（`problem-set-mismatch`）：提示条改为 `成绩已保存 · 题目清单与当前榜单不一致`，说明已有清单与榜单不同、暂不自动重建；不提供重试（同一输入必然再次失败），只给 `去工坊` / `知道了`。
- 归档比赛保存成绩后仍提示；文案加一句 `这场已归档，题目标记仍可修改`。

### 6.2 工坊比赛详情的「题目标记」区

- 位置：比赛详情主体上部、历史成绩之前；归档时仍显示且可编辑。
- 标题行：`题目标记` + 汇总 `13 题 · 已标记 3 · 待补 2 · 重点 1`；没有标记时 `还没有标记。只标记你在意的题。`
- 行：题号徽章 + 题名 + 进度分段（`未标记` / `待补题` / `已补` / `已过`）+ `重点` 星标 + 标签 chips + 标签输入。
- 默认全部 `未标记`；已标记行有轻微强调，未标记行减弱；顺序按榜单题序（A–M），不按标记状态重排。
- “未标记”只描述**进度**这一维；只有星标 / 只有标签的行仍算已标记，星标与标签照常显示，不因进度为空而隐藏。
- 标签输入：占位 `加标签（如 dp / 字符串）`；Enter 添加、× 删除；自动补全来自本工作区已用过的题目标签（去重，最多 20 条建议）；不读两级词表。
- 保存：每次变更立即写整份 `marks`；连续变更合并为一次在途写入；显示 `保存中… / 已保存 / 保存失败 · 重试`。失败保留本地状态，不假装已保存。
- 冲突：409 时提示 `另一页面已更新，重新载入后再改`；不自动覆盖；重新载入后保留用户本地未提交的修改由界面提示决定，不静默丢弃。
- 离开页面时仍有未落盘变更 → 提示 `标记未保存`；不允许静默丢。

### 6.3 工坊比赛列表

- 比赛行显示派生徽章：`待补 2`（橙）/ `重点 1`（紫）；为 0 不显示。
- 工具栏增加 `有待补题` 筛选；开启时只列 `todo > 0` 的比赛；没有命中给空态 `没有待补题`。
- `有待补题` 与对象类型 / 自由标签 / 搜索可叠加；与已退役的主题标签筛选互斥（后者不存在）。
- 不新增独立页面；全局待补面板后置，本片不实现。

### 6.4 深链

- `#/master?object=<contestId>&panel=problems`：工坊加载后选中该对象、滚动到题目标记区并聚焦标题；对象不存在 / 在回收站 / 已归档 → 提示 `这场比赛不可用`，停在列表，不静默打开别的对象（归档对象从「看归档」进入修改，2026-10-30 拍板）。
- 工坊未初始化 / 根不可用 → 走既有设置引导；初始化后不自动追加深链对象，用户可再点一次。
- 深链只用于定位，不改变任何标记。

### 6.5 空态 / 错误态 / 归档

| 场景 | 文案 / 行为 |
|---|---|
| 非官方场次（无 `arenaPath`） | 不显示题目标记区；需要时提示 `非官方场次暂不支持题目标记。` |
| 有 `arenaPath`、无快照 | `还没有题目清单。` + `从榜单补齐`；拉取失败沿用榜单两档文案，有缓存时用缓存 |
| 没有标记 | `还没有标记。只标记你在意的题。` |
| 标记文件损坏 / schema 过高 | `标记文件读不出来（原因）。成绩与对象不受影响。` + `重试`；不提供自动修复 |
| 归档 | `已归档；题目标记仍可修改。`；其它管理动作仍只读 |
| 保存失败 | `保存失败 · 重试`；本地状态保留 |
| 冲突 | `另一页面已更新，重新载入后再改。` |
| 同步失败 | `题目清单同步失败 · 重试`；成绩已保存 |

## 7. 测试与验收

### 7.1 单测（纯函数）

- schema / 解析：合法文件、缺字段、`schema > 1`、`arenaPath` 不一致、alias 重复 / 非法、标题超长、题目为空、未知 alias、非法 progress、标签超限 / 去重 / 控制字符。

- 预填：AC 只填空进度；非 AC 不填；`p` 越界跳过；已有手选不覆盖；`prefillApplied` 阻止填回；重复调用幂等；只有星标 / 只有标签时补 `已过` 且保留。
- 汇总：`total / marked / todo / starred`；未标记不计数；空文件；星标-only 计入 `marked` 与 `starred`、不计 `todo`。
- 标签退役：对象搜索不再命中 `primary` / `related` 节点名；`labels` 仍命中；`TODO(切片5b)` 别名检索删除。

### 7.2 API / 服务

- `sync`：无宿主 404；重复 / 回收站 409；首次建文件；同 alias 集合幂等；alias 集合不同 409 `problem-set-mismatch`；带 `recordId` 预填；不带 `recordId` 只建快照；`recordId` 不属于该场 404；不写标记。
- `update`：版本过期 409；非法 alias 400；标签超限 400；整份替换；全空条目删除；`prefillApplied` 保留；归档可写；回收站宿主 409 / 404；路径穿越 / symlink / junction 拒绝。
- 详情 / 列表：有文件返回 `problemMarks` / `problemMarkSummary`；无文件 `null` / 不返回；损坏文件给错误且不阻塞其它对象。
- 回收 / 恢复：标记文件随比赛整体移动；恢复后仍在；不产生独立回收条目。
- 不真实网络：所有用例注入临时根与缓存榜单；禁止 `fetch` 真出网。

### 7.3 手测 / 浏览器验收

1. 官方场打一场，保存成绩（A 有 AC、B 有提交但未 AC）→ 顶层提示出现；`去标记` 打开比赛详情。

3. 再保存一次：B 仍 `待补题`，A 不被改写；新 AC 的 C 若进度为空则预填 `已过`。
4. 清空 A 的自动 `已过`；再保存同一场：A 不被填回。
5. 归档比赛；把 B 改成 `已补`；刷新后保留；其它管理动作仍只读。
6. 列表出现 `待补 1` / `重点 1`；`有待补题` 筛选只列这场；清空 B 后徽章消失。
7. 无 `arenaPath` 的比赛：不显示标记区。
8. 有 `arenaPath` 无快照：`从榜单补齐` 拉缓存 / 上游后建立；全部未标记。
9. 1280 宽度：无横滚；键盘可操作进度 / 星标 / 标签。
10. 手改坏 `problem-marks.json`：详情报错、列表无徽章、成绩与对象正常；不覆盖。
