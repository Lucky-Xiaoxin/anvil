> **状态：草案（已实现待合并）。** 本契约在 5a-2「一个源目录 = 一个题组」之上，增加「一次扫描多个叶子目录」和「来源路径虚拟视图」。
> **基础契约**：`docs/contracts/24-工坊-旧代码导入契约.md`。未被本文改写的扫描安全、staging、manifest、去重、打开方式继续有效；`docs/contracts/23-工坊-代码管辖契约.md` 仍定义对象模型。

> **日期**：2026-10-23。

## 已拍板

1. **年 / 月不变成对象，也不变成物理目录。** `2026`、`10` 只是来源路径的分组，不是 `contest`，也不是受管根里的目录层。
2. **一个被选中的叶子目录 = 一个题组（`contest`）。** 一次提交可以生成多个题组；仍然不生成 `problem` 对象。
3. **一次扫描一个旧根，候选可以很多。** 系统只扫描和预览，不自动全选、不自动提交。
4. **容器和叶子分开。** 含多个下级题组的目录默认是容器，不作为题组整体导入；它的直接散落文件单独显示。
5. **来源路径是 provenance，不是身份。** 导入时记录 `sourcePath`，用于虚拟来源树、追溯和详情展示；它不参与路径解析和对象身份。
6. **散题单独处理。** 容器里的直接散落文件默认不导入；用户明确选择时，才生成一个「散题」题组。
7. **父目录与子目录不能同时选中。** 选中父目录表示整个子树作为一个题组；选中子目录表示各个子题组独立导入。
8. **现有 5a-2 单目录导入保留为特殊情况。** 没有下级题组的源目录仍然是一个题组；不引入第二套导入 API。

## 0. 一句话目标

让一个旧代码根目录下的多个比赛文件夹，经一次扫描、人工勾选后批量变成平铺的题组对象，并用来源路径在界面上还原「年份 / 月份 / 比赛」的浏览层级，而不引入年 / 月对象或额外维护目录。

## 1. 交付物（Definition of Done）

1. **批量扫描**：用户选择一个源根目录，服务端返回所有可选题组、容器、散题和忽略统计；扫描阶段对源目录只读，不写受管根。
2. **单目录兼容**：源根本身只有一个叶子题组时，行为与 5a-2 一致；一次提交只生成一个 `contest`。
3. **多题组导入**：一次提交可以生成多个互不嵌套的 `contest`；每个题组仍是独立原子单元，允许部分成功。
4. **扁平落盘**：所有导入题组落在 `contests/` 下，不创建 `2026/`、`10/` 等中间目录，不把来源目录结构复制成受管目录结构。
5. **来源路径**：每个导入题组在 `.anvil.json` 写入可选的 `sourcePath`（源根相对 POSIX 路径，例如 `2026/10/10.ptc`）；手动创建 / 旧对象可以没有该字段。
6. **来源视图**：工作台可按 `sourcePath` 聚合为虚拟来源组（例如 `2026 > 10`），组头可折叠；虚拟组不是对象、不能打开、不能被回收站或标签操作。
7. **散题**：容器中未归入子题组的直接文件默认忽略；用户明确选中时生成一个标题可改的「散题」题组，仍只生成一个 `contest`。
8. **父子互斥**：选择父目录和其后代目录时给出明确冲突；服务端拒绝，前端不能在提交时静默合并或重复复制。
9. **去重**：同一真实源路径 + 同一范围（整子树 / 散题）+ 同一指纹的历史对象自动跳过；不同源路径的同内容只提示潜在重复，不自动合并。
10. **安全与恢复**：沿用 5a-2 的源路径校验、忽略表、上限、staging、manifest、崩溃恢复和符号链接防护；新增的 `sourcePath` 不参与文件系统解析。
11. **测试与验收**：§10 通过；`npm run verify` 全绿；既有 536 条测试不回归；交付报告包含批量预览、来源视图、散题和部分成功截图。

## 2. 范围

### 2.1 本片做

- 一个任意来源根目录的递归只读扫描；
- 多个叶子题组候选、容器候选、散题候选；
- 父子目录互斥选择；
- 一次提交多个题组；
- `sourcePath` 元数据与虚拟来源树；
- 散题作为独立题组导入；
- 复用现有 staging / manifest / 指纹 / 重复矩阵；

- 启动时扫描、目录监听、自动导入、持续同步；

- 新建或补全 `problem` 对象；
- 迁移、删除、转换旧 `problem` 对象；
- 导入历史管理 UI、撤销整批、永久删除；
- 多受管根、文件监视、编译运行、判题、模板验证；
- 修改源目录内容、移动源文件、改写源 `.anvil.json`；
- 跨批次合并同一题组的来源。

## 3. 语义

### 3.1 源树与工作区树是两棵树

```text
源树（只读，用于发现）              工作区树（导入结果）
ACM/                               contests/
  2026/                             2026-10-23_10-ptc/
    10/                             2026-10-23_17-vp/
      10.ptc/                       2026-10-23_icpc-1/
      17.VP/                        2026-10-23_tree-dp/
      TreeDP/
  2026_ICPC_1/
```

- 源树的 `2026`、`10` 只是来源层级；工作区不创建它们。
- 每个选中的叶子目录生成一个平铺的 `contest`。
- 题组内部的源码、子目录、测试数据保持原相对结构。

### 3.2 叶子、容器、散题

- **叶子题组**：包含主源码、且直接下级没有多个含源码目录的目录；默认作为一个题组整体导入。
- **容器**：直接下级有 **两个或更多** 含源码目录的目录；默认不整体导入，而是让用户选择其下级叶子。
- **散题**：容器目录自身的非忽略普通文件，不属于任何下级题组；单独显示，默认不选。
- **混合目录**：自身有源码、同时有一个或多个含源码子目录的目录。它是可选题组，但默认策略见 §4.3。

“含源码目录”指其子树至少有一个主源码文件（`.cpp` / `.cc` / `.cxx` / `.c` / `.py` / `.java` / `.kt` / `.go` / `.rs`）；只有文档、图片或测试数据的目录不单独产生题组候选。

### 3.3 `sourcePath`

`.anvil.json` 可增加可选字段：

```json
{
  "schema": 1,
  "id": "obj_7f3a2c9b1d",
  "kind": "contest",
  "title": "10.ptc",
  "sourcePath": "2026/10/10.ptc"
}
```

约束：

- 只由导入器写入；手动创建和旧对象可以缺省；
- 源根相对 POSIX 路径，不以 `/` 开头，不含反斜杠、`.`、`..` 段；
- 1–300 字符；源根本身作为题组时不写该字段；
- **只用于展示、来源分组和追溯，不用于解析文件路径**；
- 对象改名、移动、打标、归档、回收站恢复都不改写它；
- 对象被复制到别处时该字段可随 meta 复制，可能过期，这是可接受的 provenance；不把它当作身份或去重唯一键。

### 3.4 来源视图示例

```text
来源
  2026
    10
      10.ptc          # sourcePath = 2026/10/10.ptc
      17.VP           # sourcePath = 2026/10/17.VP
      TreeDP          # sourcePath = 2026/10/TreeDP
    7
      ...
  （根）
    2026_ICPC_1       # sourcePath = 2026_ICPC_1
  未归入来源
    手动创建的题组
```

来源视图是**派生视图**：节点由对象 `sourcePath` 按 `/` 切分得到，不是磁盘目录，不产生 `.anvil.json`。

## 4. 扫描

### 4.1 源目录校验与上限

完全沿用 5a-2：

- 源根必须是存在的绝对普通目录，不得是符号链接 / junction / UNC / 盘符根 / 系统目录；
- 源根不得与受管根互为祖先或后代；
- 忽略表、深度 16、文件 10,000、总字节 1 GiB、单文件 128 MiB、候选 2,000 不变；
- 扫描只允许 `lstat` / `realpath` / 枚举 / 读取普通文件 / 计算 hash；
- 不跟随符号链接，不创建锁文件或缓存。

### 4.2 目录分类

扫描建立非忽略文件与目录树后：

1. 标记每个目录 `hasSource`：子树里至少有一个主源码文件。
2. 对每个 `hasSource` 目录，统计**直接下级**中 `hasSource` 的目录数量 `childSourceCount`。
3. 生成候选：
   - **题组候选**（`scope='subtree'`）：目录本身；复制整棵子树。
   - **散题候选**（`scope='direct'`）：仅当目录有直接非忽略文件；只复制该目录的直接文件，不含下级目录。
4. 标记 `isContainer = childSourceCount >= 2`。
5. 源根 `''` 也按同一规则处理；若源根本身有源码且没有多个下级源码目录，它就是一个题组候选。

每个目录候选都必须能被用户看到；容器默认不选，但允许用户明确选择「整个目录作为一个题组」。

### 4.3 默认选择

- **叶子题组**（`childSourceCount <= 1`）默认选中；
- **容器**（`childSourceCount >= 2`）默认不选，默认选它的下级叶子；
- **混合目录**（自身有源码且 `childSourceCount >= 1`）如果被判定为容器，默认不选；其直接文件作为散题默认不选；
- **默认选中冲突**：父子候选同时满足上面的默认条件时，混合目录（自身有直接主源码）优先——祖先保持选中，后代默认取消，避免漏掉父目录的直接源码；纯包装目录（自身没有直接源码）仍让位给更深的叶子。容器本身不默认选中，所以其下级叶子不受影响；
- **散题**默认不选；
- **同源同指纹已导入**：沿用 5a-2，默认选中但提交时自动跳过；
- **同源新版本 / 不同源同内容（含同批不同源或不同范围）**：默认不选，需要用户明确确认；同一批内出现相同指纹时，所有涉及的候选都标记潜在重复（不保留“第一个”默认选中），选中必须带 `keepDuplicate`；
- 每个候选必须返回 `reasons`，说明「容器」「叶子」「散题」「存在下级源码」等判断依据。

### 4.4 扫描结果

`totals` 统计整个源根：

- `files`：扫描到的非忽略普通文件数；
- `bytes`：总字节数；
- `candidates`：题组 + 容器 + 散题候选总数；
- `ignored`：忽略项数。

没有任何 `hasSource` 目录时返回空候选和明确警告，不创建空题组。

## 5. 选择与提交

### 5.1 父子互斥

- 选中一个 `scope='subtree'` 的父候选时，所有后代候选不可选；
- 选中一个后代候选时，父候选不可选；
- 选中一个容器的「整个目录」候选时，该容器的散题候选也必须不可选（散题已包含在整棵子树内）；
- 选中一个容器的散题候选时，容器整体候选和后代候选都不能被它隐式包含；散题只复制直接文件；
- 前端必须在勾选时即时表现互斥，服务端仍要重新校验，不能信任客户端。

### 5.2 原子单元

- 每个选中的题组候选 = 一个 `contest` 对象 = 一个原子发布单元；
- 每个选中的散题候选 = 一个 `contest` 对象 = 一个独立原子发布单元；
- 一次提交可以有多个单元；某个单元源内容变化只拒绝该单元，其他单元可成功；
- 整批不承诺全有或全无，结果页必须显示成功 / 跳过 / 失败清单。

### 5.3 结果

- 成功的题组进入 `contests/`，标题可被用户在预览中修改；
- 散题标题默认为「`<目录名> 散题`」，可修改；
- 结果对象写入 `sourcePath`；散题使用其目录的 `sourcePath`；
- 导入结束后默认选中第一件成功对象；没有成功项则停留在结果页；
- 返回工坊后刷新树，来源视图立即可见。

## 6. API 与 DTO

### 6.1 扫描

沿用：

```http
POST /api/work/import/scan
{ "sourceRoot": "C:/Users/.../Desktop/ACM" }
```

`WorkImportPlanDto` 保持原形状，候选 DTO 增加：

```ts
export type WorkImportScope = 'subtree' | 'direct';

export interface WorkImportCandidateDto {
  // 既有字段：itemId / unitId / sourceRelPath / confidence /
  // suggestedTitle / reasons / files / bytes / filePreview /
  // filesTruncated / fingerprint / duplicate / selectedByDefault
  sourceParentRelPath: string | null;
  scope: WorkImportScope;
  isContainer: boolean;
  sourceCount: number;
}
```

- `sourceRelPath`：候选目录相对源根路径；源根自身为 `''`；
- `sourceParentRelPath`：用于构建预览树；源根为 `null`；
- `scope='direct'` 表示散题；
- `sourceCount`：该候选将复制范围内的主源码数量；
- `files` / `bytes` / `fingerprint` 都按候选范围计算：`subtree` 含后代，`direct` 只含直接文件。

旧客户端忽略新增字段仍可工作；新前端不得把 `sourceRelPath` 当对象路径。

### 6.2 提交

沿用：

```http
POST /api/work/import/commit
{
  "planId": "...",
  "items": [
    { "itemId": "item_...", "selected": true, "title": "10.ptc" }
  ]
}
```

`WorkImportCommitInput` 不变。服务端从 plan 读取 `sourceRelPath`、`scope`、指纹、文件清单和 `sourcePath`；客户端不能提交：

- 源绝对路径；
- 目标路径；
- 指纹；
- 文件清单；
- `scope` / `isContainer` / `sourcePath`。

### 6.3 对象 DTO

`WorkObjectDto` 增加可选字段：

```ts
/** 导入来源（源根相对 POSIX 路径）；手动创建 / 旧对象没有 */
sourcePath?: string;
```

`.anvil.json` 中为顶层 `sourcePath`，不把它放进 `links`。`WorkDetailDto` 继承该字段；详情页只读显示。

### 6.4 错误

沿用 5a-2 的错误种类：

- `import-source-invalid`
- `import-limit`
- `import-plan-expired`
- `import-root-changed`
- `import-source-changed`
- `import-conflict`

新增选择冲突使用 `import-conflict`：父目录与后代同时选中、散题与整目录同时选中、空候选、非法 scope 等。批级校验失败返回 4xx，不创建 manifest；合法批次开始后，单元失败进入 200 结果。

## 7. 发布、去重与恢复

### 7.1 落盘

- 每个题组的目标路径继续由现有 `buildWorkRelPath('contest', ...)` 分配；
- 所有题组平铺在 `contests/`；
- 题组内部复制其 `scope` 范围内全部非忽略普通文件，保留相对目录；
- 不复制空目录；
- 不把来源的 `2026`、`10` 写进目标路径。

### 7.2 来源键

历史去重键由三部分组成：

```text
规范化真实源根 + sourceRelPath + scope
```

例如：

```text
C:/Users/.../Desktop/ACM + 2026/10/10.ptc + subtree
C:/Users/.../Desktop/ACM + 2026/10           + direct
```

同一路径的整目录题组和散题不是同一个来源，不能互相覆盖或误跳过。Windows 路径大小写归一规则沿用 5a-2。

### 7.3 指纹

- `subtree`：子树内所有将复制文件按目标相对路径排序后计算；
- `direct`：只计算直接文件；
- 文件名、大小、SHA-256 改变都会改变指纹；
- 同一批内不同来源或不同范围（scope）的候选如果指纹相同，全部标为潜在重复、默认不选；不自动合并，也不把其中第一个视为可信副本；
- 源文件只读，不因导入改变。

### 7.4 manifest

沿用 `status:running` 预写 journal、`planned → staged → published → success` 状态机和原子 manifest。新增：

- manifest item 保存 `scope`；
- 一个 unit 只对应一个 `contest`（5a-3 不生成 problem）；
- 恢复按 manifest 的 objectId + targetRelPath 对账；
- 失败清理只针对本批 staging，不碰源目录。

### 7.5 部分成功

- 每个选中候选独立提交；
- 源文件变化只影响对应单元；
- 结果返回 `units[]`，每个单元 success / failed；
- 已成功的单元不回滚，失败的单元不留下可见半成品。

## 8. 界面

### 8.1 导入预览

- 以源目录树展示候选，容器和叶子有明确文字，不只靠颜色；
- 每个候选显示：路径、类型（题组 / 容器 / 散题）、文件数、主源码数、将复制的文件摘要、理由、重复状态；
- 默认勾选叶子，容器只作为树节点 / 可选的整目录候选；散题单独一行；
- 父候选与后代候选互斥；勾选父候选时禁用后代，勾选散题时禁用整目录；
- 已选后代时，祖先整目录候选仍可点击；点击后自动改为选择祖先、并取消全部后代，不需要先手动清空；
- 标题可编辑；
- 1280 宽度不产生横向页面滚动；路径中段省略并保留 tooltip；
- 可选来源根路径输入、扫描 / 取消 / 提交按钮。

### 8.2 导入结果

显示：

- 成功题组数；
- 自动跳过数；
- 未选中数（用户主动没勾的候选）；
- 失败单元及原因；
- 新建题组入口；
- manifest 路径；
- 若部分成功，明确标注「部分成功」，不显示为全部完成。

### 8.3 来源视图

- 中间列表的「比赛」分区内，按 `sourcePath` 的父路径生成虚拟来源组头；
- 组头显示来源层级（例如 `2026 / 10`）、题组数量、总文件数；可折叠；
- 叶子题组行继续显示「题组」徽章、标题、标签、文件数；
- 没有 `sourcePath` 的题组显示在「未归入来源」或现有平铺区；
- 搜索 / 标签筛选命中时自动展开对应来源组；无命中的组隐藏；
- 来源组头不是对象：不能选中、打开、归档、打标、移入回收站；
- 排序按来源路径的年 / 月数字和名称自然排序，**不使用原始文件名字典序**；
- 旧 `problem` 兼容区和旧比赛折叠组不受影响；
- 详情页「关联」区显示只读来源路径；
- 如果当前没有任何 `sourcePath`，列表退化为 5a-2 的平铺表现。

## 9. 安全边界

- 源路径、符号链接、junction、真实路径校验全部沿用 5a-2；
- `sourcePath` 写入前做 POSIX 相对路径清洗；不合法则整个单元拒绝；
- `sourcePath` 不可用于 `resolveInside`、打开、复制或 manifest 拼接；
- 目标路径分配、staging、manifest 写入继续逐级校验符号链接；
- 多单元提交时，每个单元发布前重新校验自己的源快照；不能因为其它单元成功就跳过；
- 源目录只读，不创建临时文件、锁、缓存或标记；
- 失败清理不得删除源目录或已成功单元。
