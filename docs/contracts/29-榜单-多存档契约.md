## 已拍板

1. **比赛不复制，成绩可以多份。** 同一 `arenaPath` 仍只对应一个工坊 `contest`；“第一次 VP / 第二次 VP / 补题后”是该比赛的存档，不是三个比赛对象。
2. **每场只有一份当前草稿。** 中途自动保留录入与计时，离开后可继续；不提供多个中途存档槽，不自动产生历史快照。
3. **训练结束后才正式保存。** 到时或主动结束后可保存；不能因为录过一发、打开回顾页或拖到终榜就认定训练结束。
4. **旧存档只回顾，不续钟。** 查看不改变当前草稿；显式“编辑成绩”后才可修改，保存更新指定档，另存生成新档。
5. **覆盖草稿先询问。** 有未保存修改时提供保存后切换、放弃后切换、取消；保存失败不切换。进行中草稿须先明确结束才能保存。
6. **单份删除可恢复。** 工坊里删除存档先入回收站，清空回收站才永久删除；不增加单项硬删。
7. **榜单使用，工坊管理。** 榜单可查看历史、编辑成绩、保存与另存；工坊管理同一批存档的名称、删除与恢复，不复制一套数据。
8. 本次仅编写契约；创建文档分支不等于授权实现、迁移真实数据、推送或合并。

## 0. 一句话目标

同一场比赛打过几次都能留下成绩，打开旧成绩不会串进正在练的那一份，保存、切换和删除都有明确目标。

例如：第一次过 5 题存为“第一次 VP”，第二次过 7 题另存“第二次 VP”，修正或补录后再另存“补题后”；三份都归同一比赛，榜单一次只展示其中一份“我的成绩”。

## 1. 交付物（Definition of Done）

| 编号 | 可验收结果 |

| D1 | 同场至少保存三份不同成绩，工坊比赛对象仍只有一个，存档有独立稳定 ID |
| D2 | 进行中只能自动保留草稿；到时或主动结束后才能保存正式结果；未录提交也能保存零成绩 |

## 2. 范围与非目标

### 2.1 本片做

- 存档列表、读取、创建、更新成绩、改名、软删除、恢复；自动默认名称可编辑。
- 当前草稿与只读历史视图分离；结束后的保存、再次练习、旧档编辑和另存。
- 旧单份存档和旧浏览器逐发数据的保留与兼容读取，必要转换显式执行。
- 本功能的空态、失败态、保存冲突、草稿切换确认、回收站类型区分。

### 2.2 本片不做

- 不新增工坊对象种类、SQLite 表、训练任务系统或跨设备同步；不改变比赛与题组的关联模型。
- 不做多个进行中草稿、存档内部的版本历史、自动备份每次编辑、自动合并冲突或批量导入历史成绩。
- 不做多条幽灵行同时对比、成绩曲线、掌握图、模板工作流或新评分算法。
- 不保存源代码快照，不为每份成绩自动创建 / 关联题组，不自动标记“首次做题 / 二刷 / 补题”。
- 不做 UI/UX 全面整顿、性能专项、新依赖或通用迁移工具；不顺手处理历史审计长尾。

## 3. 使用规则与状态

### 3.1 三种界面身份

| 身份 | 数据来源 | 可做什么 | 不得做什么 |
|---|---|---|---|
| 当前练习 | 该场浏览器草稿 | 录入、暂停、继续、结束；结束后保存 / 另存 | 进行中保存正式档 |
| 查看历史成绩 | 明确选中的 `recordId` | 拖回顾轴、切封榜视角、看提交；转入“编辑成绩” | 写草稿、续钟、直接改写存档 |
| 编辑历史成绩 | 明确载入当前草稿的那份历史结果 | 修正逐发、保存原档或另存 | 重启该档计时，静默覆盖另一份草稿 |

- 顶栏必须显式区分“当前练习 / 查看：名称 / 编辑：名称”，未保存修改有可见标记。
- 查看 A 档时展示的幽灵只来自 A，不能与本地 B 草稿合并、补缺或交叉使用；时间轴等视图状态也独立。
- 查看历史不暂停后台当前练习：原来正在走的钟按既有真实时钟规则继续；页面提示“当前练习仍在计时”，需要暂停由用户在当前练习操作。
- 单纯离开页面、切到别场或只读查看旧档不替换草稿，不要求正式保存；返回时自动恢复当前草稿，不自动选择“最新存档”。

### 3.2 开始、结束与录入

1. 无草稿时“开始模拟”建立空白进行中草稿；同场已有进行中草稿时默认“继续练习”，明确“重新练一次”才从零开始。
2. 暂停不等于结束。到达比赛时长，或在目录 / 榜单点击“结束本次练习”，才转为已结束；保存动作仍由用户发起，不自动入工坊。
3. 提前结束保留实际停止时间，不强行写成比赛满时长；事后拖动回顾轴不改变这项记录。
4. 已结束后可补录 / 修正逐发成绩；“查看终榜”仍允许不经过模拟计时，显式“录入已结束的成绩”建立补录草稿，不能自动顶掉进行中草稿。
5. 已结束但没有提交仍是可保存的零成绩；“尚未创建草稿”和“结束后零提交”是不同状态。
6. 逐发判名、题序、分钟值、CE 不罚时、一个题第二个 AC 拒收等继续沿用 20；本片不扩大可录入时间范围。称为“补题后”的存档仍是用户手动命名与录入，不表示系统自动判断完成时间。
7. 当前练习的进行中标记与成绩归属用同一份草稿判定；结束不再通过删除唯一计时信息后猜测是否完赛。

### 3.3 保存与另存

- **首次保存**：已结束草稿没有目标档时创建新档；名称默认“本地日期 时间”（例如 `2026-10-29 21:30`），允许修改。
- **保存**：草稿绑定明确的 `recordId` 与读取版本，只更新那份存档；按钮附近显示目标名称。不能按“最新一份”、文件排序、同名或场次唯一旧接口猜目标。
- **另存一份**：生成新 ID；默认名称为“原名称 副本”，允许修改；成功后当前编辑目标切换为新档，原档不变。
- 名称去首尾空白，1–120 字符；可重名，列表用保存时间辅助区分，重名绝不表示覆盖；名称不参与文件路径。
- 保存完整逐发清单和训练结束信息；不把回顾游标当结束时间，不把实时排名 / 奖牌作为持久化真相。排名与罚时仍由既有引擎按所选视角计算。
- 保存成功后草稿保留并标记已保存；继续修正会重新标记未保存。拖时间轴、切封榜视角、“展示我”等展示变化不单独产生未保存成绩标记。
- 正常更新不再要求旧单档式两击“确认覆盖”：明确进入编辑、明确目标、版本校验共同约束；切换草稿和删除仍有各自确认。
- 保存期间锁定本次提交的编辑与替换操作；失败保留草稿和目标，不显示“已保存”。响应回来时若页面已离开，只记录结果，不抢回页面或其它场次选择。

### 3.4 替换当前草稿前的确认

| 被替换内容 | 提供的动作 |
|---|---|
| 没有草稿，或与绑定存档内容一致 | 直接开始新练习 / 进入指定档编辑 |
| 已结束、尚未保存或已有修改 | “保存后切换 / 放弃修改后切换 / 取消” |
| 进行中（含暂停） | “结束并保存后切换 / 放弃本次练习后切换 / 取消” |
| 旧数据只有成绩、结束状态不明 | “确认已结束并保存后切换 / 放弃后切换 / 取消” |

- 进行中即使零提交也不静默丢弃计时。“结束并保存后切换”明确点名是提前结束，不使用含糊的“保存进度”。
- 点击取消、关闭确认层、按 Escape 均不切换；询问期间时钟保持原状态，不因打开询问框隐式暂停。
- 保存失败或命名取消时不应用待切换目标；进行中草稿也不先改成结束态再尝试保存。保存成功后才一次性完成替换；未知结果按 §5.3 对账。
- 只读打开历史不走这套确认；只有“编辑成绩”、重新练一次、恢复旧进度等确实替换草稿的动作才走。
- 离开应用内页面只保留草稿；关闭浏览器不依赖异步确认框写正式档。浏览器存储失败必须有可见警告，不能宣称已自动保留。

## 4. 数据与生命周期

### 4.1 比赛与存档身份

- 比赛身份仍为 `.anvil.json` 的 `contest.id`；官方场次仍为 `arenaPath`，唯一性和回收站同场阻挡沿用 23。
- 每份新存档使用稳定 `recordId`，形状为 `rec_` 加 32 位小写十六进制随机值；改名、更新、回收、恢复不换 ID。
- 存档是比赛内部的受管数据，不是 `WorkKind`，不进入工坊对象 / 标签计数，也不改变比赛 `updatedAt` 或默认模板排序。
- 数据放在比赛目录的 `.anvil-records/<recordId>.json`；目录由服务端定位与创建，前端不传任意文件路径。扫描器排除已识别的存档目录，不能把它列成题组或未登记对象；未知内容必须报错，不能覆盖或悄悄接管。
- 不另外维护持久化存档索引；列表由该比赛的存档文件派生，避免双写。按 `updatedAt` 倒序、ID 作稳定次序；单份损坏显示错误项，其它合法档仍可读。

### 4.2 正式存档 schema 2

| 字段 | 规则 |
|---|---|
| `schema` | 固定 2；不改变工坊对象 `.anvil.json` schema |
| `recordId` | 稳定存档 ID；旧根文件兼容身份见 §7 |
| `contestId` / `arenaPath` | 必须与宿主比赛一致，不允许借更新操作换比赛 |
| `name` | 存档名称，区别于比赛标题 |
| `createdAt` / `updatedAt` | 服务端 ISO 时间；新建时相同，更新不改创建时间 |
| `result.origin` | `timed`（模拟结束）、`manual`（事后补录）、`legacy-review`（旧回顾快照） |
| `result.finish` | `time-limit` / `stopped` / `declared` / `unknown`；与 origin 对应如下 |
| `result.durationMs` | 本场时长；新建为正安全整数，旧数据无法确定时可为 null |
| `result.stoppedAtMs` | 模拟停止位置，0 到 durationMs；补录和旧来源不伪造停止位置，填 null |
| `ghost` | `{ show, subs }`；逐发结构沿用 20，最多 5000 发，保存前排序，非法输入整份拒绝 |

- 合法组合：`timed + time-limit` 的 stoppedAtMs 等于 durationMs；`timed + stopped` 不超过 durationMs；`manual + declared` 的 stoppedAtMs 为 null；`legacy-review + unknown` 两个时间字段可未知。
- `legacy-review + unknown` 只用于旧 review 的只读投影和仅改名升级；新创建或修改成绩不能借此绕过结束声明。旧 review 编辑 / 另存前确认已结束，之后转为 `manual + declared`（时长取缓存榜单，停止位置为 null）；只有旧浏览器逐发的草稿也按同一补录确认转换，不伪造计时完成。
- 新建 / 普通修改接口不接受 `live`、`paused`、`started` 等会话状态；结束声明是个人手工记录，不声称服务端认证了训练用时。
- 对新成绩校验题序与当前已缓存榜单的题数、提交分钟与时长；服务端保存不自动发起上游网络请求，缓存缺失 / 不可解析时拒绝并提示先加载榜单。旧记录原样查看与仅改名不依赖下载成功。
- 读取返回 `revision`（原文件字节 SHA-256）；不落入存档正文。更新、改名、删除都必须携带读取时的版本，手改文件同样会让旧版本失效。
- 历史档默认以终榜回顾打开，封榜视角默认关闭；查看时可拖动，不把历史游标持久化回草稿或存档。早停档仍显示“提前结束于 …”，不改写结束信息。

### 4.3 浏览器当前草稿

- 新格式使用单键 `arena:draft:<arenaPath>`，包含 `schema`、`draftId`、`phase`、`session`、`ghost`、`result`、`target`、`savedBaseline`、`pendingSave`；每场一份，不给每个 recordId 建一个可写草稿。
- `phase` = `running / finished / legacy-unconfirmed`；running 的 session 沿用既有计时数学，finished 不再续钟。结束信息与录入在同一 JSON 中写入，避免新成绩配上旧计时。
- `target` 为 null 或 `{ recordId, revision, name }`；`savedBaseline` 保存最近一次成功保存的成绩 / 结束信息，用于内容比较；显示开关和回顾游标不参与成绩 dirty 判定。
- `pendingSave` 只在本次新建请求待确认时保存拟创建 ID 与提交内容，用于重试对账；不是第二份训练草稿，也不生成自动备份档。
- 写入成功后才清理被取代的旧键；格式未知 / 存储配额失败时保留旧数据并告知用户。清除当前录入只清草稿成绩，不删除任何正式档。
- 同场多个浏览器标签共享一个草稿，不承诺并行编辑：通过 `storage` 变化使旧编辑页面失效，提示重新读取；旧页面不得在收到变化后继续静默写回。正式档写冲突由服务端 revision 强制保护。
- 服务端根目录变更时，目标档必须重新核对宿主与版本；路径相同不代表另一工作区有同一存档，不得把原草稿静默保存到另一档。

### 4.4 归档与整场回收

- 归档比赛保留只读组织结构规则，成绩本身沿用既有独立口径：榜单仍可保存 / 编辑成绩；工坊归档详情可列出存档并只读打开，不出现改名 / 回收 / 恢复的管理动作。
- 存档改名、回收与恢复属于工坊管理：宿主 `effectiveArchived` 时返回 409 `conflict`，提示先取消归档；不能从接口绕过 UI。不扩改归档模板正文等其它已知边界。
- 比赛移入回收站时，比赛目录连同尚未单独回收的存档一起移动；恢复整场时原样回来，不拆成多份条目。
- 已单独回收的存档保持单独条目，不随整场恢复自动复活。其父比赛尚在回收站 / 缺失时禁止恢复，提示先恢复原比赛；不自动新建父对象，也不挂到同场的另一对象。
- 同场比赛在回收站时，新建存档仍返回 409，不绕过既有“先恢复比赛”规则。
- 回收比赛或存档不暗中清浏览器草稿；随后保存发现目标已不存在 / 已回收时明确拒绝，可由用户恢复原档或主动另存，不能自动改为新建。

### 4.5 单存档回收站

- 复用受管根 `.anvil/trash/` 和整站清空入口；记录型条目用独立包装目录，内含普通 `trash.json` 和原存档文件。
- 新记录清单使用 `schema: 2, entryType: 'arena-record'`，保存 `id`（本次回收生成的唯一 trashId）、`recordId`、`contestId`、`arenaPath`、`title`、`trashedAt`、`originalRelPath` 与 `fileName`。trashId 形状为 `tr_` 加 32 位随机十六进制值；文件名只能是 recordId 对应文件或 §7 的旧根文件名，各比赛的 legacy 不共享回收条目身份。
- 既有对象清单 schema 1 不变；回收站 DTO 用明确的 `entryType: 'object' | 'arena-record'` 区分，旧对象响应补 object 标识；记录型条目另外返回 recordId 与 contestId。恢复按类型和回收条目 ID 分派，不把存档当作有 `.anvil.json` 的对象目录。
- 删除前点名存档与所属比赛并确认；只移动这一份，不改变其它档、对象或题组关系。
- 恢复按原 `contestId` 找宿主并核对 arenaPath：普通 ID 只能回到 `<contest>/.anvil-records/<recordId>.json`；legacy 必须回到 `<contest>/record.json`，不得生成 `.anvil-records/legacy.json`。清单 fileName 必须与这两种映射一致，originalRelPath 仅作历史记录与安全校验，不用于直接拼接恢复目标；宿主合法改名后仍按身份定位。目标文件 / 同 ID 已存在 → 409，不覆盖、不自动改 ID。
- 回收站数量按顶层条目计：整场比赛算一项，单独回收的一份成绩算一项；显示类型徽标和所属比赛，避免两个同名“第一次 VP”看不出归属。
- 整站清空同时删除对象与成绩两类合法应用条目；仍要求 `confirm:true`，仍不删除文件、符号链接、没有普通清单的目录等杂项，不提供单份永久删除。
- 移入和恢复必须有失败补偿：中断后原位置或回收位置至少保留一份完整内容；遇两边都有内容、损坏清单或路径冲突时报告错误并保留文件，不自动清理“疑似重复”。

## 5. API / DTO

### 5.1 新接口约定

写请求沿用全局 application/json、本机 Origin / Sec-Fetch-Site 防护，所有存档写入与对象回收 / 恢复使用同一写队列。

| 方法与路径 | 入参 | 成功结果 |
|---|---|---|
| `GET /api/work/arena-records?path=` | arenaPath | `{ contestId, records, legacy, errors }`；无比赛 / 无档返回空列表，不创建目录 |
| `GET /api/work/arena-records/item?path=&recordId=` | 指定场次和 ID | `{ record, revision }`；不得缺 ID 后自行选择最新档 |
| `POST /api/work/arena-records/create` | `{ arenaPath, contestTitle?, recordId, name, result, ghost }` | 首次创建 201、同内容幂等重试 200，均为 `{ record, revision, object }`；必要时创建唯一比赛 |
| `POST /api/work/arena-records/update` | `{ arenaPath, recordId, expectedRevision, result, ghost }` | 200 `{ record, revision }`；不顺带改名称或宿主 |
| `POST /api/work/arena-records/rename` | `{ arenaPath, recordId, expectedRevision, name }` | 200 `{ record, revision }` |
| `POST /api/work/arena-records/trash` | `{ arenaPath, recordId, expectedRevision, confirm: true }` | 200 `{ entryType, trashId, recordId, trashName }` |
| `POST /api/work/arena-records/restore` | `{ trashId }` | 200 `{ restored: 'record', record, revision }` 或旧 live 的 `{ restored: 'legacy-progress', legacy, revision }`；只恢复已有条目，宿主从已校验清单读取 |
| `GET /api/work/arena-records/legacy?path=` | 场次 | 旧 schema 1 原记录、来源类型与 revision；只读，不续钟、不迁移 |
| `POST /api/work/trash/purge` | `{ confirm: true }` | 沿用 `{ removed }`，两类条目合计 |

- 列表摘要包含 `recordId / name / createdAt / updatedAt / result / submissionCount / revision`；不携带完整逐发，不伪称“最好成绩”或自动挑最新结果。
- `records` 包含合法 schema 2 和旧 schema 1 review；后者只读投影为 §4.2 的 legacy-review / unknown，历史成绩数量等于 records.length。`legacy` 仅为旧 schema 1 live 的摘要或 null，不放 review，不计入历史成绩数量；两边不重复列出根文件。损坏文件由 `errors` 披露，不整场伪装无存档。
- item 接口只返回 records 中的成绩（含投影后的旧 review）；旧 live 从 legacy 接口读取原格式。两种读取均不改文件，revision 都按原文件字节计算；旧 review 投影的 createdAt / updatedAt 均沿用原 savedAt。
- 未配置 / 未初始化受管根仍沿用现有明确错误，不将工作区不可用冒充空列表。
- 成绩写接口 bodyLimit 统一为 1 MiB，容纳已有最多 5000 发的上限；其它接口沿用 64 KiB。超限返回 413，不静默截断。
- 缺参数 / 非法枚举为 400；文件不存在为 404；版本过期、同场对象重复、宿主已回收、归档管理冻结、恢复占位等为 409；路径安全沿用 `unsafe-path`；读写异常为 500 且保留可恢复内容。

### 5.2 寻址、更新与外部修改

- 服务端对解码后的 arenaPath 使用既有 `contestPathOk` 白名单；recordId 只接受 `^(rec_[0-9a-f]{32}|legacy)$`，create 只接受前一种；trashId 只接受 `^tr_[0-9a-f]{32}$`。不再二次解码，不接受分隔符、盘符、点段或客户端绝对路径。
- 按 arenaPath 找唯一宿主（含活动 / 归档比赛）；重复或在回收站为 409。完全没有宿主时仅列表返回 `{ contestId: null, records: [], legacy: null, errors: [] }`，item / update / rename / trash 为 404；只有 create 可以创建比赛。恢复按清单 contestId 定位，再核对 arenaPath。
- 普通 ID 只寻址 `.anvil-records/<recordId>.json`，legacy 只寻址根 `record.json`；文件正文 ID / 场次 / 宿主与寻址结果不一致时拒绝，不尝试猜另一个位置。回收扫描按条目类型与宿主区分各场的 legacy。
- 存档目录、回收站根、清单、源文件和目标的每级已存在路径均检查普通文件 / 目录及根内归属；不跟随 symlink / junction。未知或损坏文件不覆盖，写入采用同目录临时文件 + 原子替换，失败保留旧文件并清理本次临时文件。
- 所有写操作进入队列后重新定位宿主；更新 / 改名 / 回收须重新读取原文件并校验 expectedRevision；新建按 §5.3 检查 ID，恢复按已校验的回收清单与目标占位检查执行，不要求客户端虚构 expectedRevision。不在 UI 读取时决定最终写目标。
- 版本冲突返回 409 `conflict`；保留本地修改，提供重新读取或明确另存，不自动重试覆盖。仅改名也推进版本，旧页面需重新读取。
- 工坊旧对象 `restore` 接口不能误接记录型条目的 trashId；记录恢复接口也不能恢复对象，错误类型明确。

### 5.3 新建请求重试

- 首先展示并确认名称（默认值也作为明确 name 发送），取消命名不产生 pendingSave 或请求；确认后生成 recordId，将完整请求体冻结进草稿 pendingSave，持久化成功才发请求。超时 / 断线重试复用此 ID 和完整请求体，不重新取当前时间生成名称或读取已变化的表单；pendingSave 写入失败时不发送创建请求。
- 服务端在该比赛活动档 / 回收档中检查同 ID：不存在则新建；已存在且 name / result / ghost 的规范化内容一致返回已有结果（200，不再改保存时间）；不一致或已在回收站则 409，绝不覆盖或复活。contestTitle 只用于首次创建宿主，不作为存档重试的内容比较项。
- 新建响应未知期间不允许再次另存或替换草稿；先按 ID 查询 / 重试确定结果。确认创建成功后更新 target / savedBaseline 并清 pendingSave；明确拒绝后才解除提交锁。
- 普通更新响应丢失后，先读取当前档比较本次提交内容；已保存则对账成功，否则走 revision 冲突处理，不另建新档。

### 5.4 页面身份与过时请求

- 工坊打开指定档的深链为 `#/arena?path=<encoded>&record=<encoded>`；没有 record 参数的旧场次链接进入该场当前练习 / 目录，不静默打开最新存档。
- 只读历史打开失败时留在错误态并可重试；不能退回本地草稿却仍显示旧档名称。
- 读档、列表、进入编辑、保存结果均绑定场次、recordId 和本次意图；旧成功、旧失败、finally 都不能覆盖新页面或新草稿。
- DOM 复用 key / 状态重置必须同时考虑场次与存档身份，不能只以 arenaPath 区分；沿用 27 最后请求胜出与不抢选择规则。

## 6. 界面与状态

### 6.1 榜单入口

- 目录保留开始 / 继续练习、查看终榜、预拉取；已有结束草稿可“保存成绩”，进行中不出现正式保存入口。
- 每场提供“历史成绩”入口；顶栏也可打开同一存档选择层，不要求先绕去工坊。列表按名称、保存时间、来源 / 结束状态展示；点击仅查看，不载入当前草稿。
- 查看历史时显示“回到当前练习 / 编辑成绩”；没有当前草稿则显示“开始新练习”；不显示“从存档继续计时”。

- 进入历史列表后才读该场存档，不为整个外部目录逐场发请求，不把工坊存档数混进上游目录 DTO。

### 6.2 工坊入口

- 比赛详情增加“历史成绩”区；显示档数、摘要与“查看”，活动比赛中可改名或移入回收站；题组详情不复制此区。
- 存档列表改名、删除、恢复成功后原位刷新；保留用户的新选择，不自动改选最新档。
- 归档比赛存档列表只读；回收站中单档显示所属比赛，父比赛也被回收时给出先恢复父比赛的提示。
- 旧未结束记录单列“旧进度”，提供查看信息与“恢复为当前练习”；不能放进正式成绩列表冒充完赛。

### 6.3 空态、失败与可访问性

- 空态区分“没有历史成绩 / 有未保存的当前结果 / 只有旧进度 / 工作区不可用 / 某份损坏”。
- 断网但缓存榜单存在时，仍可本地查看与保存；缓存榜单缺失时旧档可看名称与逐发摘要，榜体展示取数失败，不自动清掉存档或草稿。
- 原子写失败、草稿持久化失败、版本冲突与恢复冲突都需常驻可见提示和明确重试路径，不能被列表刷新成功覆盖。
- 对话框有可访问名称、初始焦点、焦点圈定、Escape 取消、关闭后焦点归还；删除确认点名档名与比赛。
- 1280 宽度下目标名称可省略但可查看全名，主要动作不挤出；键盘和 reduced-motion 沿用现有约束，不引入 UI 库。

## 7. 旧数据保留

### 7.1 旧根文件 `record.json`

- 读取兼容旧 schema 1，不做启动时批量迁移；GET 和普通浏览不得写文件、重命名、删除或自动覆盖草稿。
- 该比赛根文件在新 API 中使用保留 ID `legacy`；同场只有一份根文件，因此身份稳定，不能由 create 接口新建此 ID。
- `view.mode=review`：作为“旧回顾记录”列在历史成绩中，名称默认“旧存档 + 原 savedAt”；保留逐发和原保存时间。**review 只证明保存时在回顾，不能证明跑满时长或真实停止时间**，result 用 `legacy-review / unknown`，显示“结束时间未知”。
- 旧 review 仅改名时，在原 `record.json` 路径原子升级为 schema 2（recordId 仍为 legacy），保留 `legacy-review / unknown`，不把改名当作结束确认；`createdAt` 沿用原 savedAt，updatedAt 使用本次时间。
- 旧 review 点击“编辑成绩”时先明确确认这份成绩已结束；确认后按补录方式进入 finished 草稿，result 转为 `manual / declared`，stoppedAtMs 为 null，不续钟。保存原档在根路径原子升级 / 更新 schema 2；另存写随机 ID 新文件，旧根文件不动。取消确认不创建编辑草稿，任何升级失败都保留旧文件；不提供携带 unknown 结束状态的新建成绩旁路。
- `view.mode=live`：作为只读“旧进度”披露；不自动转为正式档，不纳入历史成绩数量。“恢复为当前练习”先处理已有草稿，然后复制原成绩与 viewMs，按**暂停态**进入当前练习，明确点击继续后才走钟；原旧文件不删除、不改写。
- 旧 live 恢复后不把 legacy 设为正式保存目标；训练结束时创建一份新成绩，旧进度仍保留。旧 live 不提供改名或直接成绩更新，rename / update 返回 409；可在工坊按原文件 revision 将它单独放入回收站，恢复仍是原 schema 1 live，不转换为正式成绩，不能由保存顺带删除。
- schema 2 根文件同样按其 ID 读取 / 更新 / 软删除；删除和恢复须保留“原位置为根文件”的映射，不能在删除后又因残留兼容读取而重新出现。
- 不可读 / schema 未知 / arenaPath 不一致 / 重复 ID 的旧数据只报错保留；不同 ID 的合法新档仍可操作，涉及冲突的写入拒绝。
- 正式切换实现后，移除旧单份写入口及内部调用，不保留“缺 ID 默认覆盖唯一档”的旁路；仅保留为现有用户数据服务的格式读取能力。

### 7.2 旧 localStorage

- 新 draft 键存在时以新键为准，不回退拼接旧 session / ghost；旧键仍在也不能复活已放弃的练习。
- 新键不存在时只读兼容 `arena:session:<path>` 与 `arena:ghost:<path>`：存在未结束 session → running；存在 ended session → finished；只有逐发或无法证明结束 → legacy-unconfirmed。
- 只有逐发数据时提示“旧成绩未标记结束”，由用户确认已结束后才能正式保存；不能因 session 缺失自动当作完赛或清空。
- 兼容转换先完整构造并成功写入新键，随后才删除已消费的旧键；失败保留原件、显示错误。清空或放弃当前草稿时保留显式空 / 已放弃标记或同时清理已消费的旧键，避免下一次进入重新迁入。
- 不迁移早于逐发格式的聚合 ghost，不新增原本未支持的格式；遇坏数据不主动删除，维持可见提示和人工处理出口。
- 本片不在真实受管根上执行迁移脚本；实现验证只用自造旧数据与临时副本。

## 9. 实现约束与建议落点

- shared：存档 schema / DTO、结束状态、清单判别与版本请求形状；不把 API 原始输入靠类型断言当成已验证。
- server `work/store.ts` / `work/routes.ts`：唯一宿主、文件寻址、写队列、revision、两类回收条目；可按本片需要拆出存档职责，不扩做全仓重构。
