## 0. 一句话目标

把「代码怎么编排」从手工目录变成工作台的受管工作区：**对象由工作台创建与归档，标签由人工维护，编辑器只负责写和跑**。旧目录不迁、不接管；新代码从第一天起按本契约走。

## 1. 交付物（Definition of Done）

1. **受管根**：`vault/config.json` 增加 `workspaceRoot`；工作台可初始化根目录（建 `.anvil/` 与种子词表），不碰根内已有文件。
2. **四类对象**：`contest` / `problem` / `template` / `note`，支持创建、列出、详情、改标题、打标、归档、移入回收站、恢复、登记（adopt）。
3. **受管目录**：创建时按 §5 生成路径；路径不可由用户手输；标题与目录名分离。
4. **标签**：两级树 + `primary`（唯一）/ `related`（多个）+ 自由标签 `labels`；人工为主，v1 不自动写入任何标签。
5. **工作台视图**：对象类型筛选 + 标签树 + 搜索 + 列表 + 详情 + 未登记 + 错误 + 回收站；不依赖 CF / AT / XCPC 是否配置。
6. **打开**：用 VS Code / 资源管理器打开对象文件夹或对象内文件；只允许受管根内路径。
7. **重新扫描**：启动后首次访问、页面加载、手动按钮均可重建索引；外部编辑器 / CPH 新建的文件能被发现。
8. **安全边界**：路径穿越、越界符号链接、非白名单编辑器命令全部拒绝；所有元数据写入原子化。
9. **测试与验收**：§13 全部通过；`npm run verify` 通过；交付报告按 §14 落位。
10. **壳收口**：导航「工坊」解锁（去锁图标与「未解锁」）；`LockedMaster` 删除；冷启动页不再出现「工坊未解锁」卡。
11. **（用户追加）VP 成绩存档**：目录行 / 回放顶栏可把「我的成绩 + 当前回放位置」存进工坊比赛对象的 `record.json`；工坊「回到回放」按存档恢复。口径见 §15.3。

## 2. 管辖边界

**工作台管：**

- 对象的**顶层编排**：放哪、叫什么、属于哪个父对象。
- 对象的**身份**：改名 / 移动文件夹后仍能认回同一个对象。
- **标签、检索、打开、归档、回收站**。

**工作台不管：**

- 代码内容编辑、编译、运行、调试（仍在 CLion / VS Code）。
- 对象文件夹内部的文件怎么建（CPH / 编辑器可直接建，靠重新扫描收编）。
- 旧目录的迁移（后置，见 §15）。
- 文件级重命名 / 删除 / 拖拽（v1 不做）。

一句话：**顶层编排唯一，文件夹内部开放。**

## 3. 受管根

### 3.1 配置

- `vault/config.json` 增加 `workspaceRoot: string`，默认 `''`（未配置）。
- 旧配置没有该键时按 `''` 读，不迁移、不报错。
- `workspaceRoot` 必须是**绝对路径**，且：
  - 不是盘符根（`E:/`）、不是 `C:/Windows`、不是 `C:/Program Files*`；
  - 不在本仓库根内、不在 `vault/` 内；
  - 指向目录或可创建的路径（不是已存在的文件）。
- 校验失败 → 400 `{ error: { kind: 'root-invalid', message } }`。

### 3.2 初始化

- 根目录缺少 `.anvil/root.json` → 未初始化；`GET /api/work/tree` 返回 409 `workspace-uninitialized`。
- 配置了根但路径不存在 / 不是目录 → 409 `root-missing`；设置屏引导重新初始化，读取时不自动创建（避免把删掉的盘符路径静默建回来）。
- `POST /api/work/init` 是幂等入口：
  - 创建根目录（不存在时）与 `.anvil/`；
  - 写 `.anvil/root.json`：`{ "schema": 1, "app": "anvil", "createdAt": "<ISO>" }`；
  - `.anvil/taxonomy.json` 不存在时写入种子词表（§7.5）；已存在则**绝不覆盖**；
  - 保存 `workspaceRoot` 到 `vault/config.json`；
  - 根目录已有内容且未初始化时，请求体必须带 `confirmExisting: true`，否则 409 `root-not-empty`（响应带 `entries` 计数，按 §8.2 忽略规则统计）。初始化只创建 `.anvil/`，不移动、不改名、不删除任何已有文件。
- `.anvil/root.json` 的 `schema > 1` → 409 `root-version`，不写入、不降级。
- 切换根：再次调用 `POST /api/work/init` 传入新路径即可；只切换索引目标，不迁移任何数据；旧根保持原样。

### 3.3 目录

初始化后固定五个顶层：

```
<root>/
  contests/
  practice/
  templates/
  notes/
  .anvil/                  # root.json / taxonomy.json / trash/
```

不创建、不扫描 `inbox/`；旧代码导入的判不准项停在预览（见 `docs/contracts/24-工坊-旧代码导入契约.md`）。

## 4. 对象模型

### 4.1 四类对象

| kind | 用途 | 物理容器 | v1 创建时写入 |
|---|---|---|---|
| `contest` | 模拟场次 / 比赛 | 一场一个文件夹 | `.anvil.json`；可选 `links.arenaPath` |
| `problem` | 旧题目（兼容） | 一题一个文件夹；5a-2 起不再新建，旧数据可挂在 contest 下 | `.anvil.json`；可选 `links.problemKey` |
| `template` | 模板 | 一个模板一个文件夹 | `.anvil.json`；可选 `template.cpp` |
| `note` | 文章 / 笔记 | 一个笔记一个文件夹 | `.anvil.json` 与 `note.md`；**UI 后置** |

### 4.2 `.anvil.json`

每个对象文件夹根上必须有且只有一份 `.anvil.json`：

```json
{
  "schema": 1,
  "id": "obj_7f3a2c9b1d",
  "kind": "problem",
  "title": "Cherry Tree",
  "createdAt": "2026-10-21T02:00:00.000Z",
  "updatedAt": "2026-10-21T02:10:00.000Z",
  "parentId": "obj_1a2b3c4d5e",
  "tags": {
    "primary": "graph/tree",
    "related": ["dp/tree-dp"]
  },
  "labels": ["赛时", "没调出来"],
  "links": {
    "problemKey": "cf:2184:F"
  },
  "archived": false
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `schema` | 必须为 `1`；大于 1 视为不兼容 → 该对象进 `errors`，不改写 |
| `id` | `^obj_[0-9a-f]{10}$`；不可变、不可复用 |
| `kind` | `contest` / `problem` / `template` / `note`；不可变 |
| `title` | trim 后 1–120 字；中文可 |
| `createdAt` / `updatedAt` | ISO 8601 字符串；解析失败视为不合法 |
| `parentId` | `null` 或 `obj_…`；只有 `problem` 可以非空，且父对象必须是 `contest` |
| `tags.primary` | `null` 或词表节点 ID |
| `tags.related` | 节点 ID 数组，去重，不含 `primary` |
| `labels` | 0–20 个，每个 1–24 字，去重，不存前导 `#` |
| `links.problemKey` | 可选，≤ 80 字 |
| `links.arenaPath` | 可选，必须通过既有 `contestPathOk` 白名单 |
| `archived` | 布尔，默认 `false` |

- **可选字段可缺省**：`updatedAt` 缺省取 `createdAt`；`tags` 缺省 `{primary:null, related:[]}`；`labels` 缺省 `[]`；`links` 缺省 `{}`；`parentId` 缺省 `null`；`archived` 缺省 `false`。
- **未知顶层字段必须保留**：读取时 passthrough，更新时以「原 JSON 浅合并已知字段」写回，不得把用户手写的扩展字段洗掉。

### 4.3 身份与权威

1. **身份 = `id`，不是路径。** 文件夹被改名 / 移动（仍在根内）后，扫描按 `id` 认回，标签不丢。
2. **`.anvil.json` 是权威，DB / 内存索引只是缓存。** 删掉索引、重启服务、换机器，扫描一遍即可重建。**5a 不新增 SQLite 表、不做 schema 迁移。**
3. **没有 `.anvil.json` 的文件夹是「未登记」**，不是对象；只能通过 `adopt` 登记，不自动接管。
4. 身份不写入文件内容，不要求改 `.cpp`；标签也不写进 `.cpp`。

### 4.4 父子关系

- 只有 `contest → problem` 一层父子；`template` / `note` 的 `parentId` 必须为 `null`。
- 子对象的物理路径在父对象文件夹内；父对象详情不把子对象目录算进自己的文件列表。
- 归档父对象时，所有后代**隐式**视为归档（`effectiveArchived`）；子对象自己的 `archived` 字段不变。
- 移入回收站父对象时，整个文件夹（含子对象）一起移走；恢复时一起回来。
- `parentId` 指向不存在的对象 → 保留该对象，进 `errors`（`parent-missing`），不丢弃。

### 4.5 元数据校验

- 校验在服务端做；不合法 → 该对象进 `errors`，**不参与列表 / 计数**，文件不改写。
- 词表里找不到 `tags.primary` / `related` → 保留对象，进 `errors`（`tag-missing`），对应标签不计入树计数。
- 同一 `.anvil.json` 在扫描时只读一次；更新走原子写（复用 `packages/server/src/atomic.ts` 的 `writeFileAtomic`），2 空格缩进 + 末尾换行。

## 5. 路径与命名

### 5.1 生成规则

| kind | 路径 |
|---|---|
| `contest` | `contests/<YYYY-MM-DD>_<slug>/` |
| `problem`（无父） | `practice/<YYYY-MM>/<slug>/` |
| `problem`（有父） | `<父对象相对路径>/<slug>/` |
| `template` | `templates/<topId>/<slug>/`；无 `topId` 时用 `templates/_unsorted/<slug>/` |
| `note` | `notes/<YYYY>/<MM>/<YYYY-MM-DD>_<slug>/` |

- 日期取**服务端本地日期**（与全站时区口径一致），不是比赛日期。
- 路径最多 4 层；对象路径（相对根）≤ 160 字符，slug ≤ 40 字符。
- 目录名只允许 `[a-z0-9_-]`；中文、空格、点、括号一律不进目录名。

### 5.2 slug

- 来源优先级：`title` → `links.problemKey` → `links.arenaPath` 末段 → `kind + 日期`。
- `title` 转 slug：小写、去变音、非 `[a-z0-9]` 折叠为 `-`、去首尾 `-`、压缩连续 `-`。
- 中文 / 纯符号标题得到空 slug 时按来源回退；例如 `CF2184F` → `cf-2184-f`；没有 `problemKey` / `arenaPath` 的纯中文标题 → `<kind>-<YYYY-MM-DD>`，标题仍完整保留在 `title`。
- Windows 保留名（`CON` `PRN` `AUX` `NUL` `COM1-9` `LPT1-9`）加 `-obj` 后缀；结尾的 `.` 与空格剔除。
- 冲突：`<slug>` → `<slug>-2` → `<slug>-3`，最多 50 次；仍冲突则 `<slug>-<4hex>`。

### 5.3 不可变

- **物理路径在 v1 不可改**；可改的是 `title`。理由：编辑器 tab、CPH 配置、`.idea`、编译产物都绑在路径上。
- 外部改名 / 移动对象文件夹：重新扫描按 `id` 认回，更新索引里的 `relPath`；不自动移回、不报错。
- 外部把对象移出根目录：视为消失，从索引移除；标签随 `.anvil.json` 一起离开，不在 DB 留墓碑。

## 6. 生命周期

所有写操作串行化（单进程内一个 Promise 队列），`rescan` 等待进行中的写操作完成。所有 `.anvil.json` / `root.json` / `taxonomy.json` / `trash.json` 写入必须原子。

### 6.1 create

请求体：

```ts
{
  kind: 'contest' | 'problem' | 'template' | 'note';
  title?: string;            // 可空仅当 problemKey 能补出标题，见下
  parentId?: string;         // 仅 problem；必须是 contest
  problemKey?: string;       // 仅 problem；可选
  arenaPath?: string;        // 仅 contest；可选
  topId?: string;            // 仅 template；可选，必须是一级词表节点
  templateId?: string;       // 仅 problem；可选，来源模板对象
}
```

- `title` 为空且 `problemKey` 存在：查 `submissions.problem_name`（按 `problem_key`）补标题；查不到则用 `problemKey` 本身。仍为空 → 400。
- `contest` / `template` / `note`：`title` 必填。
- `problem` + `parentId`：父对象必须存在、`kind=contest`、未归档、未在回收站；路径落在父文件夹内。
- `templateId`：来源对象必须 `kind=template`；把 `template.cpp`（没有则第一个 `.cpp`）复制为 `solution.cpp`，把 `test.cpp` 复制为 `test.cpp`；不复制其它文件。
- `note`：创建空 `note.md`，内容为 `# <title>\n`。
- 创建流程：分配路径 → 建目录 → 写 `.anvil.json`；若 meta 写失败，只删除本次新建且仍为空的目录，绝不删除已有内容。
- 成功后返回对象详情。

### 6.2 adopt

请求体：`{ relPath: string; kind: WorkKind; title?: string }`。

- `relPath` 必须是根内已存在的目录，不能是根目录本身、顶层桶（`contests` / `practice` / `templates` / `notes`）、`.anvil/`、`.git/`、忽略目录，不能已含 `.anvil.json`（409 `conflict`）。
- 不移动、不改名、不改文件；只在目标文件夹写 `.anvil.json`，`title` 缺省取文件夹名。
- 允许登记任意层级的目录（不强制符合 §5.1 的路径形状）；登记后该对象参与列表与标签，路径保持不变。
- 若目标目录的最近祖先已有对象：父对象是 `contest` 且本次 `kind=problem` → 写入 `parentId`；其它组合 → 400（先改 kind 或放到别处）。
- 若目标文件夹内部已有子对象的 `.anvil.json`，只登记父对象，子对象保持独立。

### 6.3 retitle

- 只改 `title`，同时更新 `updatedAt`；目录不动。
- trim 后 1–120 字；空 → 400。

### 6.4 tag

- 更新 `tags.primary` / `tags.related` / `labels`；同时更新 `updatedAt`。
- `primary` 必须是词表节点 ID 或 `null`；`related` 去重且不含 `primary`；`labels` 按 §4.2 清洗。
- 人工为主：**5a 不根据 CF / AT / 文件名自动写入任何标签**；`problemKey` 只用于补标题，不用于打标。

### 6.5 archive

- `archived: true` 写入 meta；`archived: false` 即恢复。
- 归档对象默认不出现在列表与计数；`GET /api/work/tree?archived=1` 可查看。
- 归档不移动路径；归档父对象隐式归档后代（§4.4）。

### 6.6 trash / restore

- `trash`：把整个对象文件夹移动到 `.anvil/trash/<YYYYMMDD-HHmmss>_<id>/`，并在该目录写 `trash.json`：

```json
{
  "schema": 1,
  "id": "obj_7f3a2c9b1d",
  "title": "Cherry Tree",
  "originalRelPath": "practice/2026-10/cherry-tree",
  "trashedAt": "2026-10-21T02:20:00.000Z"
}
```

- 回收站不再出现在对象列表 / 计数；`trash` 列表由扫描 `.anvil/trash/` 得出。
- `restore`：按 `id` 找到 `trash.json`，目标路径 = `originalRelPath`；目标已存在 → 409 `path-occupied`（不自动改名）；父路径不存在 → 409 `parent-missing`；成功则移回并删除对应 trash 目录。
- **v1 不做永久删除**，不提供 `DELETE` 语义的硬删。

### 6.7 open

请求体：`{ id: string; relPath?: string }`。

- 无 `relPath`：打开对象文件夹；有 `relPath`：打开对象内文件或子目录。
- `relPath` 解析后必须仍在对象文件夹内；符号链接拒绝。
- 编辑器解析顺序（2026-10-21 用户真机反馈后调整）：**文件夹 → `explorer.exe`**；**文件 → `code`（VS Code）**；失败再走另一条，二者都不可用 → 502 `editor-unavailable`。文件用 `/select,<path>` 时走 Explorer。
- Windows 上 `code` 通常是 `code.cmd`：实现需解析到 `Code.exe`（或用 `where.exe` 校验后再 spawn 可执行文件），**不得为此打开 `shell:true`**；CLion 不在 5a 白名单。
- `spawn` 必须用参数数组、`shell: false`；禁止拼接命令行字符串。
- 测试注入 `spawn`，不启动真实编辑器。

### 6.8 rescan

- 首次访问 `GET /api/work/tree` 时构建索引；页面加载时前端带 `?rescan=1`；另有 `POST /api/work/rescan` 手动入口。
- 返回摘要：`{ scannedAt, objects, added, removed, unregistered, errors }`。
- 扫描不跟随符号链接；忽略目录见 §8.2。
- 外部改名 / 移动：按 `id` 认回；外部删除：移出索引；外部新增目录：进 `unregistered`。
- 没有文件监视（技术锁不引 `chokidar`）；外部改动靠「加载时 + 手动」刷新。这是 5a 的明确取舍。

## 7. 标签契约

### 7.1 `.anvil/taxonomy.json`

```json
{
  "schema": 1,
  "version": 1,
  "nodes": [
    {
      "id": "graph",
      "name": "图论",
      "children": [
        { "id": "graph/shortest-path", "name": "最短路" },
        { "id": "graph/tree", "name": "树" },
        { "id": "graph/hld", "name": "树链剖分" }
      ]
    }
  ],
  "aliases": {
    "树剖": "graph/hld",
    "最短路": "graph/shortest-path"
  }
}
```

约束：

- `schema=1`；`version` 为正整数；**最多两级**（一级 + 二级），第三级不做。
- 节点 ID：`^[a-z0-9-]+(/[a-z0-9-]+)?$`，全表唯一、不可变；改名只改 `name`。
- `name` 1–24 字；`children` 只允许出现在一级节点；一级节点可以没有子节点。
- `aliases`：显示名 / 常用简称 → 节点 ID；键唯一。5a 不自动打标；检索只覆盖标题 / labels / 节点名 / 路径，**别名检索放 5b**（与导入建议一起做）。
- 词表是**人工可编辑文件**；5a 提供只读加载与校验，**不做词表编辑 UI**（编辑 JSON 后 `rescan` 生效）。增删节点 / 改名的 UI 放 5b。
- 词表不合法：`taxonomy` 返回 `null` + `taxonomyError`；对象照常列出，标签编辑禁用；不因词表坏掉整个工作台。
- 被对象引用后删除节点：对象保留，`tag-missing` 警告；计数忽略悬空标签；不静默改写对象。

### 7.2 primary / related / labels

- `primary`：0 或 1 个，进树、进计数、进后续掌握图；可以是一级或二级节点。
- `related`：0..n 个，只做导航与详情展示，**不进计数**，避免同一对象在多个节点重复计数。
- `labels`：自由标签，离散、无层级、不进树、不进统计；只做筛选。
- 一个对象可以没有 `primary`（未分类是合法终态）。

### 7.3 计数

- 默认列表（`archived=0`）的树节点 `count` = 非回收站、非隐式归档、`primary` 落在该节点或其子节点上的对象数。
- 归档视图（`archived=1`）的计数按**归档对象**算，和该视图列出的对象一致；两种视图不混合。
- 一级节点计数包含其二级子节点；`related` 不计；`labels` 不计。
- 对象列表筛选：kind / 标签节点（含子节点）/ label / 搜索词，条件 AND。

### 7.4 人工为主

- v1 不自动写入标签；不做「根据 CF tags 自动打标」。
- 自动补标题（§6.1）不算打标。
- 未来的「建议标签」必须是显式确认后才写入，且不能覆盖已有 `primary`。

### 7.5 种子词表

- 首次初始化写入一级 13 轴 + 二级起步集（附录 A）；`version=1`。
- 种子是**自写内容**，不复制 heimaom / QOJ 的映射文件；若后续引用第三方词表，先做许可证核验（与 srk 的纪律一致）。
- 初始化后词表归用户所有；服务端不覆盖、不合并、不回写。

## 8. 扫描与索引

### 8.1 索引

- **5a 不新增 SQLite 表，不改 `anvil.db` schema。** 索引是 `WorkStore` 的内存结构，从磁盘重建。
- 服务端启动后首次 `GET /api/work/tree` 时构建；`rescan` 重建；切换根时重建。
- 索引内容：对象（meta 字段 + `relPath` + 文件列表摘要）、词表、未登记、错误、回收站、`scannedAt`。
- 根目录本身与 `.anvil/` 永远不是对象；扫描从根的下一层开始。
- 同一 `id` 出现在多个目录 → 全部进 `errors`（`meta-invalid`：duplicate id），不猜哪个是真的。
- 对象数量按个人使用量级设计（百级对象、千级文件）；v1 不分页、不做全文索引。

### 8.2 忽略目录 / 文件

扫描与文件列表跳过：

```
.anvil  .git  node_modules  .venv  venv  __pycache__
.idea  .vscode  dist  build  .next  out
*.exe  *.o  *.obj  *.class  *.pyc
.DS_Store  Thumbs.db
其它以 . 开头的文件 / 目录（.anvil.json 单独作为元数据读取）
```

- 符号链接不跟随；对象目录本身是符号链接 → 不登记，进 `errors`（`symlink`）。
- 文件列表：相对对象目录的 POSIX 路径、size、mtime（epoch 秒）、ext；按路径升序；最多 500 条，超出置 `filesTruncated: true`。
- 文件列表**不进入**子对象目录（子对象单独列出）。

### 8.3 未登记

- 候选父目录（只在这里找）：
  - `contests/` 的直接子目录；
  - `practice/<YYYY-MM>/` 的直接子目录；
  - `templates/<topId>/` 的直接子目录；
  - `notes/<YYYY>/<MM>/` 的直接子目录。
- 候选目录没有 `.anvil.json` → 进 `unregistered`，带 `kindHint`（由父目录推断）。
- 对象内部没有 meta 的子目录是附件，不报未登记。
- 不在上述位置的、带 meta 的目录仍会被索引为对象（外部移动容错），但不作为未登记候选。

### 8.4 错误

- `meta-invalid`：JSON 解析失败、schema 不符、字段不合法、`id` 形状不对。
- `parent-missing`：`parentId` 找不到。
- `tag-missing`：`primary` / `related` 指向不存在的节点。
- `symlink`：对象目录是符号链接。
- `scan`：其它读取错误（权限、路径过长等）。
- 错误只影响对应对象；扫描继续。错误文案进 `tree.errors`，服务端异常再记 `vault/anvil-server.log`（沿用现有 `life()`）。

## 10. 安全边界

1. **路径解析**：`path.resolve(root, rel)` 后必须满足 `path.relative(root, abs)` 不以 `..` 开头、不是绝对路径；对已存在路径取 `realpath` 再校验；**禁止用字符串 `startsWith` 做前缀判断**。
2. **符号链接**：不跟随；对象目录是链接 → 拒绝；`open` 的目标是链接 → 拒绝。
3. **用户输入路径**：只出现在 `adopt.relPath`、`open.relPath` 与回收站 `trash.json.originalRelPath`；`create` 路径由服务端生成；`update` / `trash` / `restore` 的 `id` 只用来查索引。`trash.json` 是用户可手改的文件，恢复前必须按同一套根内路径规则校验。
4. **编辑器**：白名单为 VS Code 的 `Code.exe`（由 `code` / `where.exe` 解析）与 `explorer.exe`；`spawn(cmd, args, { shell: false })`；路径作为独立参数；不读 shell 配置；失败返回 `editor-unavailable`。
5. **写入**：所有元数据写入走 `writeFileAtomic`；写前校验父目录在根内；不在根外创建任何文件。
6. **只读边界**：工作台不读取、不返回、不代理文件内容；只做 `stat` 与路径列表。
7. **服务**：仍只听 `127.0.0.1`；不新增外网请求；不新增依赖。
8. **保留名 / 长路径**：Windows 保留名与结尾点 / 空格按 §5.2 处理；对象路径超长直接 400，不静默截断到不可预测的位置。

- 工坊比赛对象详情出现「回到回放」，深链 `#/arena?path=<arenaPath>` 读回存档；`review` 停在保存位置，`live` 从保存位置接钟。
- 存档是**手动快照**：保存后继续改成绩 / 拖进度要再点一次保存，不做自动同步。
- 已知边界：手改或复制文件夹造成 `record.json` 的 `arenaPath` 与场次不一致 → 409；同一 `arenaPath` 多个 contest → 409；用户手放同名 `record.json` 会被覆盖。

### 15.4 掌握图（5d）

- 吃 5a–5c 的 primary 标签 + 本地记录 + 可选难度；颜色语义、样本量、置信度另开契约。
- 本契约只保证：primary 唯一、related 不计数、标签可解释。
