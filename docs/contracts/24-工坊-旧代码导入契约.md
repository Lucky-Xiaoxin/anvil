## 已拍板

1. **题组就是比赛文件夹里的源码集合。** 一个 `contest` 文件夹既是比赛，也是题组；不再为「题组」新增对象类型。
2. **一个源目录 = 一个题组。** 导入只生成一个 `contest`，整个目录的非忽略文件原样复制；不拆题目、不生成子 `problem` 对象。
3. **不再新建 `problem` 对象。** 新建里没有「题目」；导入也不会产生。旧的 `problem` 对象保留可查看、打标、归档、移入回收站，不迁移、不删除。
4. **新建「题组」与「比赛」都落成 `contest`。** 区别只是表单意图：题组默认用于放源码，不填榜单路径；比赛可选 `links.arenaPath`。
5. 旧代码导入采用**手动入口、先预览后确认、只复制不移动**；原件永不改写或删除。
6. 一个目录内的文件全部属于同一个题组；没有「未判定项」这种新候选。目录为空（没有非忽略普通文件）时不产生候选。
7. **题组详情和旧题目详情都提供「打开文件夹」与「用 VS Code 打开」；** 模板 / 笔记仍只有「打开文件夹」。
8. 扫描、提交、恢复共用工坊写队列；**提交时要在写队列内重新核对同源重复**，旧 plan 不能重复搬运。

## 0. 一句话目标

把散落在旧目录里的比赛代码，经过可解释的只读扫描与人工确认，安全复制成工坊里的一个题组（`contest` 文件夹）；重复执行不重复搬运，失败不留下可见半成品。

## 1. 交付物（Definition of Done）

1. **导入入口**：工坊工具栏提供「导入旧代码」，进入独立的选源 / 预览 / 结果三步视图。
2. **只读扫描**：输入本地绝对目录后，服务端返回候选、识别理由、文件统计、忽略统计、重复状态与建议目标；扫描阶段不写受管根。
3. **单目录题组**：识别成功时只生成一个 `contest` 候选；整目录文件归入该题组，不生成 `problem`。
4. **人工确认**：用户可修改标题、是否导入；潜在重复需要明确「仍导入副本」；未确认项零写入。
5. **安全复制**：源文件只读；先复制到 `.anvil/import-staging/`，校验后在同一受管根内原子发布；不覆盖任何已有目录或文件；目标 / 暂存 / manifest 路径逐级拒绝符号链接和 junction。
6. **幂等与去重**：以真实源路径 + 内容指纹识别重跑；同一来源已导入且历史目标可用时自动跳过；不同源路径的同内容只提示潜在重复；**扫描后、提交前另一 plan 已导入同一来源时，本次提交也要自动跳过**。
7. **导入清单**：每批写入 `.anvil/imports/<batch>.json`，记录来源、指纹、选择、对象 ID、最终路径与结果；它同时是崩溃恢复 journal。
8. **对象模型不变**：继续使用四类对象与 `.anvil.json schema=1`；不新增 SQLite 表，不给 meta 增加导入专用字段。
9. **VS Code 打开**：`contest` 与旧 `problem` 的详情都可显式用 VS Code 新窗口打开；找不到 VS Code 或启动失败时明确返回 502，不回退资源管理器。
10. **列表语义**：按「比赛」分区；有源码的比赛显示「题组」徽章；旧题目对象只出现在兼容区 / 旧折叠组；不再出现新建的题目行。
11. **测试与验收**：§14 通过；`npm run verify` 全绿；交付报告包含完成度、测试数字、截图与已知问题。

## 2. 领域语义：比赛文件夹即题组

### 2.1 一个题组就是一个 `contest` 文件夹

- 题组标题、标签、归档、回收站、打开入口都由这个 `contest` 对象承载。
- 题组里的 `.cpp` / `.py` / `.c` 等源码文件就是题目；工作流是「新建题组 → 打开文件夹 → 放源码 → 重新扫描」。
- 没有「题组对象」与「比赛对象」两条独立的树；它们只是同一 `contest` 类型的两种表单意图。

### 2.2 旧 `problem` 的兼容位置

- 5a / 5a-2 早期版本创建过的 `problem` 对象继续有效：可查看、打标、归档、回收站、打开。
- 新导入 / 新建不再产生 `problem`；不在本片迁移旧对象，也不自动合并进题组。
- 旧「比赛 + 子 problem」数据仍按折叠组显示，只用于兼容。

### 2.3 列表用语

中间列表固定使用：

- **比赛**：列表分区标题；新模型下所有题组都在这里。
- **题组**：比赛行上的徽章；当 `sourceCount > 0`（或旧数据有子题目）时显示。
- **旧题目对象**：没有父对象的旧 `problem`；只有存在旧数据时出现。
- **模板** / **笔记**：各自分区。
- 旧 `problem` 行保留常驻「题目」徽章；新模型不再产生题目行，因此不出现新的「未分组题目」区。

左侧「题目」筛选只在当前视图存在旧 `problem` 时出现，避免新用户看到空的旧分类。

### 2.4 导入后的目录示例

旧目录：

```text
2024-regional/
  README.md
  A.cpp
  B.cpp
  C/
    solution.py
  data/
    test.in
```

导入后：

```text
contests/2026-10-22_2024-regional/
  .anvil.json                 # contest，即题组
  README.md
  A.cpp
  B.cpp
  C/
    solution.py
  data/
    test.in
```

源文件名与相对结构保留；不生成 `A/`、`B/`、`C/` 这类子题目录和子 `.anvil.json`。

### 2.5 `sourceCount`

`WorkObjectDto.sourceCount` 是派生字段：对象自身文件树里主源码扩展名（`.cpp .cc .cxx .c .py .java .kt .go .rs`）的数量。它只用于列表「题组」徽章 / 计数，不写 meta、不新增表。子对象目录不计入父对象。

## 3. 范围

### 3.1 本片做

- 手动选择一个旧代码源目录；
- 只读扫描与内容 SHA-256；
- 整个目录生成一个 `contest` 候选；
- 预览、改标题、确认导入、潜在重复确认；
- 暂存、原子发布、manifest、去重、失败恢复；
- 题组 / 旧题目用 VS Code 打开；
- 列表按比赛分区、题组徽章、旧题目对象兼容。

### 3.2 本片不做

- 启动时扫描、目录监听、`chokidar`、自动导入；
- 与旧目录持续同步、覆盖更新、双向同步；
- 删除、移动、重命名源文件；
- 源码语义分析、AI 分类、编译、运行、判题、模板验证；
- 自动建议或写入标签；
- template / note 导入；本片导入只生成 `contest`；
- 把一个目录拆成多个题组，或一次选多个目录；
- 持久 inbox、inbox 整理 / 晋升状态机；
- 导入历史管理 UI、撤销整批、永久删除；
- SQLite 表、`.anvil.json` schema 变更；
- 多受管根、git 操作、CLion 专用启动；
- 旧 `problem` 对象迁移 / 合并 / 删除；
- 保留空目录（只复制非忽略普通文件）；
- 5a.1 模板编辑器的未保存拦截与其它无关重构。

## 4. 源目录安全边界

### 4.1 源路径

`sourceRoot` 必须：

- 是存在的绝对路径；
- 是普通目录，不是文件、符号链接或 junction；
- 不是盘符根、UNC 路径、`C:/Windows`、`C:/Program Files*`；
- 与受管根不存在祖先 / 后代关系；
- 真实路径与输入路径都不落入受管根。

扫描每个已存在路径组件；任何组件是符号链接 / junction 时拒绝整次扫描。不得通过 `realpath` 跟到别处继续读取。源根的规范真实路径使用 Windows native realpath，保证同一目录换大小写输入仍是同一来源。

### 4.2 只读保证

导入服务对源目录只允许：

- `lstat` / `realpath`；
- 枚举目录；
- 读取普通文件；
- 计算 hash。

禁止在源目录创建锁文件、缓存、manifest、临时文件或标记文件。

### 4.3 忽略规则

目录与文件沿用 5a 忽略表：

```text
.anvil  .git  node_modules  .venv  venv  __pycache__
.idea  .vscode  dist  build  .next  out
*.exe  *.o  *.obj  *.class  *.pyc
.DS_Store  Thumbs.db
其它以 . 开头的文件 / 目录
```

符号链接、junction、socket、设备文件等非普通文件不复制，并进入忽略统计。

### 4.4 扫描上限

单次扫描固定上限：

- 目录深度 ≤ 16；
- 普通文件 ≤ 10,000；
- 总字节数 ≤ 1 GiB；
- 单文件 ≤ 128 MiB。

任一上限超出即返回 `import-limit`，不截断后假装扫描完整。新模型一次只产生一个候选，候选上限不再有实际分流作用，但保留常量与校验。

## 5. 候选与识别

### 5.1 唯一候选

扫描结果最多产生一个候选：

- `shape: 'contest-group'`
- `role: 'contest'`
- `parentItemId: null`
- `childItemIds: []`
- `sourceRelPath: ''`
- 标题取源目录名（最多 120 字）
- `files` = 全部非忽略普通文件；`targetPath` = 源根相对路径
- 指纹 = 整个目录的文件集合指纹
- 理由：`整目录导入：N 个文件`、`主源码 M 个；题目就是题组里的源码文件，不单独建对象`

目录没有非忽略普通文件时 `items: []`，不产生空题组候选。

### 5.2 文件与附件

- 所有非忽略普通文件都复制；源码、`.in` / `.out` / `.ans`、Markdown、文本、JSON、YAML、PDF 一视同仁。
- 源文件名、大小写、相对目录结构逐字节保留。
- 空目录不复制。
- `.h` / `.hpp` 等头文件照常作为文件复制，但不影响 `sourceCount`。
- 扩展名匹配不区分大小写。

### 5.3 旧分类器

`classifyImportTree()` 等多候选 / 题号识别函数保留在 shared 供旧用例使用，生产导入路径不调用。新代码不得依赖它生成候选；后续可单独清理。

## 6. 导入流程

### 6.1 第一步：选择来源

工坊工具栏「导入旧代码」进入全宽导入视图，不挤进现有三栏。页面提供：

- 源目录绝对路径输入；
- `/`、`\` 与资源管理器带引号路径兼容；
- 「扫描」按钮；
- 只复制、不删除、不持续同步的固定说明。

### 6.2 第二步：预览确认

预览按来源树展示一个题组候选：

- 标题可改（1–120 字）；
- 勾选 / 取消是否导入；
- 潜在重复（`same-content`）默认不选；选中后必须勾「仍导入副本」；
- 同一来源已导入（`same-source` + 指纹一致）默认勾选，提交时自动跳过；
- 同源指纹变化标「来源有新版本」，默认不选；
- 无子题树、无「未判定」项；
- 文件摘要、识别理由、忽略统计、计划过期时间可见；
- 每项复选框、标题输入可键盘完成；1280 宽度不产生横向页面滚动；长路径中段省略并保留 tooltip。

### 6.3 第三步：执行与结果

结果页显示：

- 成功对象数（0 或 1）；
- 自动跳过数 / 用户跳过数；
- 失败原因；
- 新建题组入口；
- manifest 路径。

完成后刷新工坊树；若存在成功对象，默认选中它。返回工坊只清前端状态；服务端 plan 按 §6.4 生命周期过期。

### 6.4 计划生命周期

扫描结果生成服务端内存 plan：

- `planId` 使用不可预测随机值；
- 有效期 30 分钟；
- 单进程最多保留最近 3 个 plan；
- 重启服务后 plan 失效；
- plan 只保存扫描结果与源快照，不保存到受管根；
- plan 绑定扫描时受管根的真实路径与 `.anvil/root.json.createdAt`；commit 必须在 WorkService 写队列内重新核对，切换根后旧 plan 失效；
- plan 单次提交但结果幂等：首次 commit 进行中时重复请求复用同一 Promise，完成后在 plan 到期前重复请求返回同一结果，不再次复制；
- **提交时重查历史**：同一真实源路径 + 同一指纹 + 历史目标可用时，即使扫描时还没有历史，也自动跳过；
- 扫描后历史目标消失时，提交重新核对后允许重新导入。

过期 / 不存在返回 409 `import-plan-expired`；受管根身份变化返回 409 `import-root-changed`，都要求重新扫描。

### 6.5 显式状态

至少覆盖：未选择来源、扫描中、空目录 / 无候选、超过上限、plan 过期、源变化、全部重复、失败、manifest 警告、VS Code 不可用。

## 7. 指纹、重复与冲突

### 7.1 文件指纹

普通文件 hash = 对原始字节计算 SHA-256：

- 不做 CRLF / LF 归一化；
- 不去 BOM；
- 不按文本解码；
- hash 使用小写十六进制。

### 7.2 对象指纹

对象指纹对将复制的文件按 POSIX 相对路径排序，再对以下序列计算 SHA-256：

```text
<relativePath> NUL <size> NUL <fileSha256> LF
```

单目录题组的相对路径相对源根；整个目录算一个对象指纹。

### 7.3 重复矩阵

| 情况 | 默认行为 |
|---|---|
| 同真实源路径 + 同指纹，历史目标仍存在且 objectId 可找到 | 自动跳过，链接到已有对象 |
| 同真实源路径 + 同指纹，但历史目标已消失 | 允许重新导入 |
| 同真实源路径 + 指纹变化 | 标记「来源有新版本」，默认不选；用户可导入新副本 |
| 不同真实源路径 + 同指纹 | 标记「潜在重复」，默认不选；用户可明确保留副本 |
| 目标路径重名 | 复用既有 `-2` / `-3` / 随机后缀分配，绝不覆盖 |

Windows 路径大小写不敏感：同一目录换盘符 / 路径大小写输入必须识别为同一真实源路径。历史 manifest 中的来源键在 Windows 上做大小写归一，扫描真实路径使用 native realpath。

内容相同不等于题目相同；hash 只提供重复证据，不替用户做语义合并。

### 7.4 提交前复核

commit 对选中原子单元重新检查：

- 源路径仍在原真实根内；
- 文件集合未变；
- 每个文件 size / mtime 快照未变；
- 重新计算的指纹与 plan 一致；
- 同源历史在写队列内再查一次（§6.4）。

源变化只拒绝该对象；新模型一次导入只有一个单元，因此不会出现同一批里「半场比赛」的问题。

## 8. 复制与原子发布

### 8.1 原子单元

- 一个源目录 = 一个 `contest` = 一个原子单元；
- 源目录没有非忽略普通文件时不能选中（空题组不合法）；
- 新模型一次提交只有一个 unit；结果 DTO 仍保留 `units[]`，兼容旧结果渲染。

### 8.2 暂存

每个单元先复制到：

```text
<root>/.anvil/import-staging/<batchId>/<unitId>/
```

暂存目录内先写源文件，再写对象 `.anvil.json`。`.anvil/` 本来就不参与对象扫描，因此暂存内容不得出现在工坊列表。

**路径安全**：暂存目录、`.anvil/imports`、最终目标及其父级都必须逐级拒绝符号链接 / junction；任何一级是链接时报 `unsafe-path`，不得写到受管根外。

### 8.3 发布

commit 进入 WorkService 写队列并完成全部批级校验后，按以下顺序执行：

1. 为对象预分配 id、标题和标准目标路径（`contests/<日期>_<slug>`）；
2. 在 `.anvil/imports/` **先原子写入 `status:running` 的 manifest**，记录 unit、objectId、目标路径与 `state:planned`；它同时是崩溃恢复 journal；
3. 复制到 staging、重新校验指纹并写 `.anvil.json`；manifest 把该 unit 更新为 `state:staged`；
4. 在受管根同一卷内把完整原子单元 `rename` 到最终路径；manifest 把该 unit 更新为 `state:published`；
5. 索引能够按预分配 objectId 找回该单元后，manifest 把 unit 更新为 `state:success`；
6. 当前批全部结束后重建一次索引，并把 manifest 总状态写为 `completed | partial | failed`。

每次 manifest 状态变化都走 `writeFileAtomic`。源目录可位于其它盘；跨盘只发生 source → staging 的 copy，最终发布始终是受管根内部 rename。

### 8.4 时间与字节

- 文件内容与相对文件名必须逐字节保留；
- `.anvil.json.createdAt / updatedAt` 取导入时服务端时间；
- 目标文件 mtime 允许是复制时间；源 mtime 记录进 manifest，不伪装成对象创建时间；
- 空目录不保留。

### 8.5 失败与恢复

- manifest `planned/staged` 且最终路径不存在：删除本单元由 ANVIL 创建的 staging，标为 failed；
- manifest `staged` 但最终路径已存在：按 manifest 中该 unit 的**全部 objectId** 对账；全部存在则补写 `published/success`，否则报 `import-conflict`，不继续复制；
- manifest `published`：按全部 objectId 和目标路径对账，成功则补写 success，缺任一对象则保留现场并报错；
- manifest 已有 success：重试只返回原结果，不再次复制；
- 只允许清理带合法 `staging.json schema=1`、batchId 与 manifest 一致且位于固定 staging 根下的目录；
- 源目录和已成功的其它单元永不因恢复流程被删除或回滚。

所有 commit / 恢复 / rescan 与现有对象写操作共用同一 Promise 队列。

## 9. Import Manifest / Journal

每批清单路径：

```text
<root>/.anvil/imports/<YYYYMMDD-HHmmss>_<batchId>.json
```

它既是迁移审计，也是批次发布 journal；必须在复制前创建。

形状（新模型通常只有一个 unit / item）：

```json
{
  "schema": 1,
  "batchId": "imp_7f3a2c9b1d",
  "sourceRoot": "D:/old-icpc-code",
  "workspace": {
    "realPath": "E:/ANVIL-Work",
    "rootCreatedAt": "2026-10-21T02:00:00.000Z"
  },
  "createdAt": "2026-10-22T02:00:00.000Z",
  "finishedAt": null,
  "status": "running",
  "units": [
    {
      "unitId": "unit_1",
      "state": "planned",
      "objectIds": ["obj_7f3a2c9b1d"],
      "targetRelPaths": ["contests/2026-10-22_2024-regional"],
      "itemIds": ["item_1"]
    }
  ],
  "items": [
    {
      "itemId": "item_1",
      "unitId": "unit_1",
      "sourceRelPath": "",
      "sourceMtime": 1700000000000,
      "fingerprint": "<sha256>",
      "action": "import",
      "kind": "contest",
      "title": "2024-regional",
      "parentItemId": null,
      "objectId": "obj_7f3a2c9b1d",
      "targetRelPath": "contests/2026-10-22_2024-regional",
      "status": "pending"
    }
  ]
}
```

约束：

- 批次 `status`: `running | completed | partial | failed`；
- unit `state`: `planned | staged | published | success | failed`；
- item `action`: `import | skip-user | skip-duplicate`；
- item `status`: `pending | success | skipped | failed`；
- 一个 contest unit 记录 contest 的 objectId / targetRelPath；旧多 objectId unit 的恢复逻辑保留兼容；
- 失败 unit / item 可带 `errorKind` / `message`；
- manifest 用 `writeFileAtomic`，2 空格缩进 + 末尾换行；
- 读取历史时坏 manifest 只产生导入警告，不影响工坊对象树；
- manifest 不取代 `.anvil.json` 的对象权威；它只负责导入来源、幂等与发布恢复；
- manifest 中 `sourceRoot` 只作历史，不要求换机器后仍存在。

## 10. API 与 DTO

共享 DTO 落在 `packages/shared/src/work-import.ts`，由 `shared/src/index.ts` 导出；server / web 不各定义一套。

### 10.1 扫描

```http
POST /api/work/import/scan
```

```ts
interface WorkImportScanInput {
  sourceRoot: string;
}

interface WorkImportPlanDto {
  planId: string;
  sourceRoot: string;
  expiresAt: string;
  totals: {
    files: number;
    bytes: number;
    candidates: number;
    ignored: number;
  };
  items: WorkImportCandidateDto[];
  warnings: string[];
}
```

候选至少包含：

```ts
interface WorkImportCandidateDto {
  itemId: string;
  unitId: string;
  sourceRelPath: string;          // 新模型为 ''
  shape: 'contest-group' | 'problem-dir' | 'problem-file' | 'undecided';
  role: 'contest' | 'problem' | 'undecided';
  parentItemId: string | null;    // 新模型为 null
  confidence: 'high' | 'low';
  suggestedTitle: string;
  reasons: string[];
  files: number;
  bytes: number;
  filePreview: string[];
  filesTruncated: boolean;
  fingerprint: string;
  duplicate: null | {
    kind: 'same-source' | 'same-content';
    state?: 'same' | 'new-version';
    objectId?: string;
    targetRelPath?: string;
  };
  selectedByDefault: boolean;
}
```

新模型候选固定 `shape=contest-group`、`role=contest`、`parentItemId=null`、`childItemIds` 不在 DTO 中。DTO 中的 problem / undecided 字段与取值保留用于历史 plan 兼容，新扫描不会产生。

扫描成功返回 200；扫描本身不分配 objectId，不创建目录。

### 10.2 提交

```http
POST /api/work/import/commit
```

```ts
interface WorkImportCommitInput {
  planId: string;
  items: Array<{
    itemId: string;
    selected: boolean;
    title?: string;
    parentItemId?: string | null;
    confirmUndecidedAsProblem?: boolean;
    keepDuplicate?: boolean;
  }>;
}
```

提交选择必须先整体校验，任一不合法则返回 400 且不创建 manifest：

- `itemId` 必须属于 plan，不能重复；plan 中未回传的项按 `selected:false`；
- 角色不可修改；新模型候选是 contest，不能带父对象；
- 潜在重复（`same-content`）只有 `keepDuplicate:true` 才能选中；
- 标题 1–120 字；
- 没有选中任何项 → 400；
- 空题组（没有文件）不合法。

`parentItemId` / `confirmUndecidedAsProblem` 为历史 plan 兼容字段；新模型不产生 problem / undecided。服务端不信任客户端回传的源绝对路径、指纹、目标路径、文件清单与识别理由；这些必须从服务端 plan 读取并复核。

返回：

```ts
interface WorkImportResultDto {
  batchId: string;
  manifestRelPath: string;
  units: Array<{
    unitId: string;
    status: 'success' | 'failed';
    objects: Array<{ itemId: string; objectId: string; relPath: string }>;
    itemIds: string[];
    error?: { kind: string; message: string };
  }>;
  skipped: Array<{ itemId: string; reason: string; objectId?: string; kind?: 'duplicate' | 'user' }>;
}
```

批级校验错误使用 4xx 且不开始导入；一旦合法批次开始执行，即使单元因源变化或复制失败，接口也返回 200 `WorkImportResultDto`，由 unit 状态表达部分成功。

### 10.3 错误

新增错误 kind：

- `import-source-invalid`：源目录不合法；
- `import-limit`：扫描超过上限；
- `import-plan-expired`：plan 不存在或过期；
- `import-root-changed`：扫描后切换了受管根；
- `import-source-changed`：提交时源内容变化；
- `import-conflict`：选择关系、恢复对账或发布目标冲突；
- `unsafe-path`：目标 / 暂存 / manifest 路径含符号链接或越界。

批级错误沿用 `{ error: { kind, message } }`；`import-source-changed` 若发生在合法 commit 的单元，写入 200 结果的 unit error。路径与文件读取细节不得把受管根以外的无关绝对路径泄漏到日志以外。

### 10.4 打开

```http
POST /api/work/open
```

```ts
type WorkOpenApp = 'auto' | 'vscode' | 'explorer';

interface WorkOpenInput {
  id: string;
  relPath?: string;
  app?: WorkOpenApp;
}
```

- 缺省 / `auto`：保持 5a 行为，文件夹 Explorer 优先、文件 VS Code 优先，失败互相回退；
- `vscode`：只尝试 VS Code；目录使用 `Code.exe --new-window <absPath>`；失败返回 502 `editor-unavailable`；不回退 Explorer；
- `explorer`：只尝试资源管理器；失败返回 502；
- 任一模式都先走既有根内路径与符号链接校验；
- spawn 必须参数数组、`shell:false`，不得拼字符串或打开 shell；
- 显式 `vscode` 在启动后进入短退出码观察窗口：进程以非零码提前退出视为启动失败（502）；窗口内未退出则按成功处理。

### 14.2 服务端

## 15. 实现约束与建议落点

- 不新增依赖；使用 Node `crypto`、`fs`、`path`。
- 复用 `writeFileAtomic`、WorkService 写队列、既有 slug / 路径分配与错误形状。
- 外部源路径校验必须单独实现，不能拿只接受受管根内相对路径的 `resolveInside()` 硬套源目录；但**导入的目标 / 暂存 / manifest 路径必须复用 `resolveInside()` / `assertNoSymlinkComponents()`**。
- 文件 hash 使用流式读取，禁止把 128 MiB 文件整体读进字符串。
- 扫描 / commit 的纯判据尽量放 shared；IO、realpath、copy、rename 留 server。
- Windows 源路径去重使用 native realpath + 来源键大小写归一；不要依赖 `realpathSync` 的输入大小写。
- 提交时去重必须在写队列内重查历史，不能只依赖扫描时的 `duplicate` 字段。
- 建议落点：
  - `packages/shared/src/work-import.ts`：DTO、单目录候选、指纹组合、常量与旧分类器；由 shared index 导出；
  - `packages/server/src/work/import.ts`：源扫描、plan、manifest、staging、恢复、提交时去重；
  - `packages/server/src/work/paths.ts`：外部源安全校验；
  - `packages/server/src/work/store.ts`：写队列接入、对象路径与 meta 生成复用；
  - `packages/server/src/work/routes.ts`：scan / commit 与 open app；
  - `packages/server/src/work/open.ts`：显式 app 模式与短退出码观察；
  - `packages/web/src/components/work/WorkImport.tsx`：三步导入视图；
  - `Workbench.tsx` / `WorkList.tsx` / `WorkDetail.tsx` / `derive.ts`：入口、比赛 / 题组用语、VS Code 按钮、关闭导入后的树刷新；
  - 对应 shared / server / web 测试文件。
- 若为复用 create 而需要拆出「分配路径 / 构造 meta」内部函数，只做最小提取，不顺手重写 WorkService。
