## 已拍板

1. **比赛和题组是两个对象。** `contest` 只表示比赛；新增 `problemset` 表示题组。二者不再共用 `contest` 业务角色。
2. **题组是一个一等对象。** `problemset` 有自己的文件夹、标题、标签、归档、回收站和文件列表；它管辖的是一组散题代码文件，不生成子 `problem` 对象。
3. **题组可以独立存在。** 题组和比赛的关系是可选的「关联比赛」，不是硬性挂载；独立题组是正常状态，不叫「未挂载题组」。
4. **关联是逻辑关系，不搬目录。** `problemset.parentId` 指向一个 `contest`；题组文件夹仍在自己的位置，不移动到比赛文件夹内。
5. **一个比赛最多关联一个题组（0..1）。** 一个题组最多关联一个比赛；不允许一个比赛同时挂多个题组。
6. **生命周期独立。** 比赛归档 / 移入回收站不隐藏、不归档、不移动关联的题组；题组归档 / 回收也不影响比赛。关联只用于浏览和组合展示。
7. **来源路径仍是 provenance。** `sourcePath` 只记录导入来源，不决定对象是否为题组；`arenaPath` 只属于比赛；`sourceCount` 只用于展示源码数量。
8. **旧数据一次性迁移。** 现有 5a-3 导入的 `contest` 源码题组迁移为 `problemset`，不移动文件夹；迁移必须先预览、后确认，不静默改写。
9. **列表不再出现「无来源路径」「未挂载题组」等负向标签。** 无 `sourcePath` 的题组是普通题组，直接列出；无 `parentId` 的题组也是普通题组。

## 0. 一句话目标

把工坊从「一个 `contest` 同时扮演比赛和题组」改成「比赛是比赛、题组是题组」的清晰组合：题组可作为独立对象管理代码集合，也可选地关联一个比赛；旧数据可预览迁移，不做物理搬家。

## 1. 交付物（Definition of Done）

1. **新对象类型**：`WorkKind` 增加 `problemset`；`contest` 只表示比赛。`.anvil.json` 的 `schema` 仍为 1。
2. **对象身份**：每个题组有独立文件夹与 `.anvil.json`；文件夹内是散题代码集合，不生成子 `problem`。
3. **可选关联**：题组可在创建、登记或详情中关联一个比赛；也可以没有任何关联。一个比赛最多关联一个题组。
4. **逻辑组合**：关联不移动题组目录；比赛和题组各自保持原路径、文件计数和回收站行为。
5. **生命周期独立**：比赛归档 / 回收不影响题组；题组归档 / 回收不影响比赛。比赛不可用时，题组只显示「关联比赛不可用」，仍正常可用。
6. **旧数据迁移**：提供只读预览 + 显式确认的迁移；现有源码题组从 `contest` 改为 `problemset`，旧路径不变，旧 `problem` 不迁移。
7. **列表分区**：比赛、题组、模板、笔记、旧题目对象各自独立；不再按 `arenaPath` / `sourcePath` 推断分类。
8. **列表显示**：比赛行显示可选关联的题组；题组行显示可选关联的比赛；无关联的题组正常显示，不加「未挂载」「无来源」等标签。
9. **来源视图**：来源树只用于导入题组的来源分组；手动题组没有 `sourcePath` 时直接作为普通题组行出现，不进入「缺来源」区。
10. **创建 / 登记**：新建题组可选题组类型与关联比赛；新建比赛不再生成题组；登记目录时必须明确选择比赛 / 题组（模板 / 笔记保持原类型）。
11. **导入**：批量导入生成 `problemset`，可保留 `sourcePath`；不再生成 `contest` 题组。导入后的题组可独立存在，也可后续关联比赛。
12. **测试与验收**：§9 通过；`npm run verify` 全绿；旧 5a-3 测试兼容或明确改写；交付报告包含角色迁移、关联比赛、独立生命周期和来源视图截图。

## 2. 对象与字段

### 2.1 对象表

| kind | 业务含义 | 路径 | 关键字段 |
|---|---|---|---|
| `contest` | 比赛 / 场次 | `contests/<YYYY-MM-DD>_<slug>/` | `links.arenaPath`、`record.json` |
| `problemset` | 题组 / 散题代码集合 | `practice/<YYYY-MM>/<slug>/` | 可选 `parentId`（指向 contest）、可选 `sourcePath` |
| `problem` | 旧题目兼容 | 原路径不变 | 旧 `parentId` / `problemKey`，不新建 |
| `template` | 模板 | 原路径不变 | 模板文件 |
| `note` | 笔记 | 原路径不变 | `note.md` |

- `problemset` 是本次新增的唯一对象类型；不新增 `role` 字段。
- 现有 `.anvil.json schema=1` 不升版本；`kind` 增加 `problemset` 是兼容扩展。
- `problem` 仍然是历史兼容类型，不参与新题组关系。

### 2.2 题组文件

`problemset` 文件夹内：

- 所有非忽略源码 / 数据 / 文档都是内容；
- 不要求 `solution.cpp`，不改名源文件；
- 不创建子 `.anvil.json`；
- `fileCount` 统计自身文件；`sourceCount` 统计主源码数量。

### 2.3 关联比赛

`problemset.parentId`：

- `null`：独立题组，正常状态；
- `obj_…`：关联一个 `contest`；
- 父对象必须存在、`kind=contest`；旧 `problem` 不计入 0..1，它只是兼容数据；
- 一个 `contest` 最多被一个 `problemset` 引用；
- 父比赛在回收站时，题组仍保留 `parentId`，界面显示「关联比赛不可用」，不自动清空；
- 关联不改变路径、不改变文件计数、不改变归档 / 回收语义；
- 父比赛被移入回收站时，题组不隐藏；扫描允许 `parent-missing` 为**警告**（对象保留，可继续使用）；
- 父比赛恢复后，关联自动恢复显示；
- 题组被移动 / 改名时，`parentId` 不变（如果路径可变，沿用现有路径规则；本片不新增移动）。

### 2.4 字段职责

| 字段 | 只属于 | 用途 |
|---|---|---|
| `links.arenaPath` | `contest` | 回放 / 目录关联；不再用于判断业务角色 |
| `record.json` | `contest` | 保存的 VP 成绩；不参与分类 |
| `sourcePath` | `problemset` | 导入 provenance；不决定是否题组 |
| `sourceCount` | `contest` / `problemset` | 展示源码数量；不决定分类 |
| `parentId` | `problemset` / 旧 `problem` | 题组关联比赛 / 旧题目父子；不用于 `contest` |

## 3. 旧数据迁移

### 3.1 迁移原则

- **只改 meta 的 `kind`，不移动文件夹，不改文件名，不改路径。**
- 只迁移 `contest`，不迁移 `template` / `note` / 旧 `problem`。
- 迁移前必须只读预览；用户确认后逐对象原子写 `.anvil.json`。
- 迁移后 `kind` 恢复不可变；不提供回滚 UI（可在预览阶段取消）。
- 旧 manifest 保持历史记录，不因迁移重写；manifest 中的旧 `kind` 只作为历史事实。

### 3.2 提议规则

| 现有对象 | 提议 | 理由 |
|---|---|---|
| `contest` 有 `record.json` | 保持 `contest` | 已保存成绩，明确是比赛 |
| `contest` 有 `links.arenaPath` | 保持 `contest` | 比赛表单意图 / 榜单关联 |
| `contest` 有旧子 `problem` | 保持 `contest` | 5a 旧比赛结构 |
| `contest` 有 `sourcePath` | `problemset` | 5a-3 导入的独立源码集合 |
| `contest` 无 `arenaPath` / `record.json` / 旧子 `problem` / `sourcePath` | **待确认**：提议 `problemset` | 多为 5a-2 旧导入；手动创建比赛无榜单路径时会歧义，需用户确认 |
| `template` / `note` / `problem` | 不迁移 | 不属于本次角色收口 |

- 预览显示 `id`、标题、路径、当前 kind、提议 kind、命中的规则、是否歧义。
- 对「待确认」对象，用户可改为 `contest`、保持 `contest` 或跳过；不能默认静默归类。
- 迁移接口不接收客户端目标路径；路径永远由现有 `relPath` 保持不变。

### 3.3 迁移 API

建议：

```http
GET /api/work/migrate/preview
POST /api/work/migrate/apply
{ "ids": ["obj_…"], "confirm": true }
```

- `preview` 只读，返回候选、规则、计数和歧义项；
- `apply` 只接受 `contest → problemset`，不接受任意 kind 改写；
- 任一对象并发变化 / 已迁移 / 路径不可用 → 该项失败，其他项可成功；
- 迁移与现有写操作共用 WorkService 队列；
- 迁移完成后重建索引，刷新工坊。

### 3.4 当前数据预期

- 2 个有 `record.json` 的比赛 → 保持 `contest`；
- 48 个有 `sourcePath` 的来源题组 → `problemset`；
- 3 个 5a-2 旧导入无 `sourcePath`、无榜单证据 → 预览中待确认，默认可提议 `problemset`；
- 旧 `problem` / 模板 / 笔记 → 不迁移。
- 迁移后所有旧路径保持在原位置；列表按新 `kind` 分区。

## 4. API 与 DTO

### 4.1 共享类型

```ts
export type WorkKind = 'contest' | 'problemset' | 'problem' | 'template' | 'note';
```

- `WORK_KINDS`、`isWorkKind`、`KIND_NAME`、筛选、计数、扫描错误全部同步；
- `problem` 仅保留兼容，不新增；
- 不增加 `role` 字段。

### 4.2 创建 / 登记 / 更新

`WorkCreateInput`：

```ts
{
  kind: 'contest' | 'problemset' | 'problem' | 'template' | 'note';
  title?: string;
  parentId?: string;      // problemset 可选；problem 旧语义
  arenaPath?: string;     // 仅 contest
  sourcePath?: never;     // 只能由导入器写
  // template / problem 旧字段保留
}
```

- `contest`：`parentId` 必须为 `null`；可写 `arenaPath`；
- `problemset`：`parentId` 可选，必须是未删除（不在回收站）的 `contest`；不能写 `arenaPath`；路径 `practice/<YYYY-MM>/<slug>/`；
- `problem`：旧兼容，保持原规则；
- `template` / `note`：保持原规则。

`WorkAdoptInput`：

```ts
{ relPath: string; kind: WorkKind; title?: string; parentId?: string | null }
```

- 登记时明确选择比赛 / 题组；
- `problemset` 可带 `parentId`，也可以不带；
- 不根据目标目录位置自动推断关联比赛。

`WorkUpdateInput`：

- `problemset` 增加 `parentId?: string | null`；只允许一个比赛；
- 比赛 / 模板 / 笔记不允许修改 `parentId`；
- 旧 `problem` 的 `parentId` 保持旧规则。

### 4.3 导入

- `scan` 候选仍是叶子 / 容器 / 散题；
- `commit` 生成对象从 `contest` 改为 `problemset`；
- `sourcePath` 写入题组；
- 导入不自动关联比赛；导入后可在题组详情中关联一个比赛；
- 旧 5a-3 导入机制、manifest、staging、去重继续复用；
- 迁移 manifest 的旧 `kind` 不重写。

### 4.4 扫描

- 新增 `practice/<YYYY-MM>/` 的 `problemset` 未登记候选；
- `parentId` 校验：
  - `problemset` 指向不存在的 contest → 对象保留，警告 `parent-missing`，不丢弃；
  - 多个 problemset 指向同一个 contest → 全部进错误 / 冲突，不自动选择；
  - `problemset` 的 `parentId` 指向非 contest → `meta-invalid`；
- 归档 / 回收不跟随关联父对象；`effectiveArchived` 对 `problemset` 只取自身；
- 旧 `problem` 的父子归档规则不变。

### 4.5 Arena 记录

- `arenaPath` / `record.json` 只允许 `contest`；
- 回放页保存成绩只能创建 / 复用 `contest`；
- 题组不能有 `record.json`，不能出现在回放路径选择器中；
- 比赛关联的题组通过 `problemset.parentId` 展示，不进入 `record.json` 结构。

## 5. 生命周期与关联

### 5.1 独立

- 比赛归档：题组不归档；比赛列表隐藏，题组仍显示；
- 题组归档：比赛仍正常显示；
- 比赛移入回收站：题组仍显示，关联状态标「关联比赛不可用」；不阻断题组打开 / 打标 / 归档；
- 题组移入回收站：比赛仍显示；恢复后关联恢复；
- 比赛永久删除：本片没有硬删；若以后新增，题组保留、关联变为不可用；
- 题组恢复只按自己的 `trash.json`，不要求比赛存在。

### 5.2 关联

- 新建 / 编辑题组时，可选「关联比赛」；
- 选择列表只列出未被其它题组关联的 `contest`（0..1）；
- 比赛详情显示「关联题组: …」，提供跳到题组详情；
- 题组详情显示「关联比赛: …」，提供清除关联；
- 清除关联不移动目录；
- 关联被清除后，题组仍是普通题组，不显示负向标签。

## 6. 界面

### 6.1 列表分区

```text
比赛
  2024-05-02 武汉邀请赛       # contest
  西安邀请赛                  # contest

  2026

      ...
  手写题组                     # 无 sourcePath 也正常显示

```

- 比赛区只列 `kind=contest`；
- 题组区只列 `kind=problemset`；
- 来源树只组织有 `sourcePath` 的题组；
- 无 `sourcePath` 的题组不放进「无来源路径」「未挂载」区，直接作为普通题组行；
- 无 `parentId` 的题组不显示「未挂载」标签；
- 比赛行有关联题组时显示「关联题组」链接；题组行有关联比赛时显示「比赛」关联文本；
- 比赛文件夹内的源码不再被叫作题组；如存在源码，显示「含源码」计数，不使用「题组」徽章；
- 旧 `problem` 区继续只做兼容。

### 6.2 详情

- `contest`：类型「比赛」；显示榜单路径 / 回到回放 / 关联题组；不显示来源树；
- `problemset`：类型「题组」；显示来源路径（如果有）、关联比赛、文件列表；不显示榜单存档；
- `problem`：旧题目文案与父子关系不变；
- 详情中的「打开文件夹」「用 VS Code 打开」：`contest` 与 `problemset` 都提供；
- 题组详情的「关联比赛」是一个可清除的单选选择器；
- 比赛详情的「关联题组」只读 + 跳转，不在这里制造第二个编辑入口。

### 6.3 新建 / 登记

- 新建类型：比赛 / 题组 / 模板 / 笔记；
- 新建比赛：标题 + 可选榜单路径；不产生题组；
- 新建题组：标题 + 可选关联比赛；不产生比赛；有默认模板时自动放入 `solution.cpp`（只放主文件，不带模板的其它文件）。
- 登记：明确选择类型；题组可填关联比赛；
- 不再用「题组 = 比赛文件夹里的源码集合」作为表单提示。

### 6.4 筛选 / 计数

- 左栏对象类型：全部 / 比赛 / 题组 / 旧题目 / 模板 / 笔记；
- 计数按 `kind`；
- 比赛计数与题组计数互不包含；
- 关联不合并计数；
- 搜索覆盖标题 / 标签 / 路径；来源路径显示在详情和来源树，不用于分类。

## 8. 安全

- 沿用 5a-2 / 5a-3 的受管根、源路径、符号链接、staging、manifest、上限与原子写规则；
- `parentId` 只存对象 ID，不拼接路径；关联不改变文件夹位置；
- 迁移只改 `kind`，不读写路径，不移动文件；写 meta 用原子写；
- 迁移不能把 `problemset` 改回 `contest`，也不能改模板 / 笔记 / 旧题目；
- 列表 / API 不能通过 `arenaPath` 或 `sourcePath` 推断 kind；
- 旧 `record.json` / `sourcePath` 的未知字段保留；
- 关联缺失只警告，不删除、不隐藏题组。
