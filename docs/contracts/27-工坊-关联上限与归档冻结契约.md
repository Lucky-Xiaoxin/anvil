## 已拍板

1. **取消「一个比赛最多关联一个题组」。** 一个比赛可以关联 0..n 个题组；一个题组仍然最多关联一个比赛。
2. **归档 = 定格。** 归档对象只出现在归档列表；归档视图只读；工作台内不提供标题 / 标签 / 关联 / 回收站等编辑入口，只保留「取消归档」。
3. **活动视图只处理活动对象。** 活动列表、活动关联选择器、活动计数不出现归档对象。
4. **关联不搬目录、不继承生命周期。** 比赛和题组仍各自归档 / 回收；`parentId` 只是逻辑关联。
5. **跨归档关联只读展示。** 活动对象关联归档对象时显示「已归档」状态，不显示为「不可用 / 缺失」；不能在另一方归档期间修改关联，需先取消归档。
6. **不新增对象类型、不升 schema、不新增表。** `problemset` / `contest` 的对象模型不变，只调整关联上限与归档 UI / 校验。
7. **P2-3 的关联查找复杂度优化不在本片范围。** 已记入项目记忆，等对象量或真实卡顿触发。

## 0. 一句话目标

让比赛可以自然拥有多个题组，同时把归档变成真正的「打包定格」：归档对象只在归档视图出现且只读，活动视图不显示、不可挂载、不会被误判为缺失。

---

## 1. 交付物（Definition of Done）

1. **0..n 关联**：删除 create / adopt / update 的「比赛已被其它题组占用」校验；扫描不再把多个题组关联同一比赛报为冲突。
2. **单题组单比赛**：`problemset.parentId` 仍只能指向一个 `contest`；一个题组不能同时挂多个比赛。
3. **比赛侧展示**：比赛详情显示 0..n 个关联题组；比赛列表行显示题组数量或摘要，不再假定只有一个。
4. **归档只读**：归档视图的详情不出现可编辑动作（标题、标签、关联、移入回收站等）；只保留「取消归档」和只读查看。
5. **归档不出现在活动视图**：活动列表、活动关联选择器、活动计数不包含归档对象。
6. **跨归档关联状态**：活动题组关联归档比赛时显示「关联比赛已归档」；不显示「关联比赛不可用」。归档题组关联活动比赛时，归档详情只读显示对方状态。
7. **跨归档不可编辑**：关联任一方处于归档时，不能新建 / 修改 / 清除这条关联；先把归档方「取消归档」，再回活动视图操作。
8. **列表行修复**：没有旧 `problem` 子题的比赛行也必须显示关联题组（数量 / 链接），不能只在旧折叠组头显示。
9. **关联查找收口**：为所有关联展示提供一致的 byId 查找；不改组件树，不做独立性能重构（P2-3 仍为 TODO）。
10. **测试与验收**：§7 通过；`npm run verify` 全绿；补多题组、归档只读、跨归档关联和空比赛行回归。

## 2. 关联规则

### 2.1 比赛 → 题组 0..n

- `contest` 可以被任意数量的 `problemset.parentId` 指向。
- 删除：
  - create 的 `taken` 检查；
  - adopt 的 `taken` 检查；
  - update 的 `taken` 检查；
  - 扫描的「多个题组关联同一个比赛」冲突。
- 保留：
  - 题组只能指向一个 `contest`；
  - 父必须存在且 kind=contest；
  - 父缺失只警告，题组保留；
  - 关联不改变路径、文件计数、标签和回收站。

### 2.2 比赛详情

- 显示所有关联题组（0..n）的标题与状态；活动视图只列活动题组。
- 归档题组的数量可以作为只读文本显示，但不在活动视图提供可跳转 / 可编辑列表；它们只在归档列表中管理。
- 比赛列表行显示「题组 N」或摘要，不再使用单选假设。

### 2.3 题组详情

- 仍可选一个比赛；选择器只列活动比赛。
- 当前关联比赛已归档时：
  - 显示「关联比赛已归档」；
  - 不提供跳转、清除或改选；
  - 要调整，先到归档列表取消比赛归档。
- 当前关联比赛被回收 / 缺失：仍按 5a-4 的「关联比赛不可用」处理，题组保留。

### 2.4 归档期间

- 关联任一方归档时，关联只读。
- 不自动清空 `parentId`；恢复活动后关联自动恢复显示。
- 归档 / 回收题组不改变比赛；归档 / 回收比赛不改变题组。

## 3. 归档冻结

### 3.1 活动视图

- 只列出、只计数活动对象。
- 关联选择器只列活动比赛。
- 不把归档对象显示为活动对象，也不显示为「缺失」；如果当前对象本身活动且关联目标是归档，显示「已归档」状态。

### 3.2 归档视图

- 只列出归档对象；不混入活动对象。
- 详情只读：
  - 不显示标题编辑、标签编辑、关联编辑、移入回收站；
  - 只保留「取消归档」；
  - 文件列表、来源路径、关联标题可只读查看。
- 取消归档后：
  - 对象回到活动视图；
  - 才允许编辑和调整关联。

### 3.3 回收站

- 归档对象不能直接移入回收站；先取消归档（回到活动），再按现有回收站规则操作。
- 活动对象仍按 5a-4 的回收站规则；题组关联不随回收传播。

### 3.4 文件打开

- 「打开文件夹 / 用 VS Code 打开」仍可查看归档对象；工作台无法限制外部编辑器写入，但工作台内不提供编辑入口。
- 归档对象不提供重命名、标签、关联等修改入口。

## 4. API / 数据

- `WorkObjectDto` / `.anvil.json` 不新增字段；`parentId` 仍是单值。
- `create` / `adopt` / `update` 删除 0..1 的 `taken` 校验；保留父 kind / 存在性校验。
- 扫描删除多题组同父冲突；保留父缺失警告。
- 现有 `problemset` 路径、`sourcePath`、manifest、staging、去重不变。
- 归档只读是 UI + 服务端写操作约束：
  - **冻结判据是 `effectiveArchived`**（自己的 `archived` 或从父对象继承来的）：服务端在归档态下拒绝 retitle / tag / labels / parentId / trash 等修改，旧 `problem` 随父比赛定格时同样只读；
  - 取消归档（`archived=false`）是唯一允许的写操作；继承归档的对象，其解冻入口在父对象上；
  - 归档类拒绝统一 **409 `conflict`**（含「关联 / 挂到归档比赛」「往归档比赛建题」），`400 invalid` 只留给形状 / 值域错误；错误形状沿用现有 WorkError。
- 不增加迁移工具；现有数据已完成 5a-4 迁移。

## 5. 界面

### 5.1 比赛

- 比赛列表行显示关联题组数量；没有关联时显示「无题组」或不显示徽章。
- 比赛详情「关联题组」改为列表：
  - 活动视图：活动题组可点击跳转；
  - 归档题组只显示数量 / 已归档，不提供活动跳转。
- 不再出现「一个比赛最多关联一个题组」的提示。

### 5.2 题组

- 题组详情「关联比赛」选择器只列活动比赛。
- 关联比赛归档时显示「关联比赛已归档」，不可改选 / 清除。
- 归档题组详情只读，不显示选择器。

### 5.3 列表 / 计数

- 活动列表和归档列表互斥；不使用当前视图缺项判断「对象不存在」。
- 关联展示统一通过一份全量 byId / association map 派生；不要求本片做 P2-3 的性能优化。
- 空比赛行（无旧 problem）也必须显示关联题组数量 / 链接。

## 7. 测试与验收

### 7.1 服务端

- 一个比赛关联两个 / 三个题组成功；扫描不再报多父冲突。
- 一个题组仍只能一个父；父缺失仍警告。
- 归档对象 retitle / tag / labels / parentId / trash 被拒绝；取消归档后可编辑。
- 删除 / 归档 / 回收关联任一方，另一方保留，关联按状态显示。
- 旧 `problem` 兼容不回归。
- `npm run verify` 基线 556；新增用例只增不减（除旧死路径测试改写的合理减少）。

### 7.2 前端纯逻辑

- 比赛 → 题组多选展示；无关联 / 一个 / 多个。
- 归档视图只读状态；活动视图不出现归档对象。
- 关联选择器只列活动比赛。
- 跨归档关联状态：活动 → 归档、归档 → 活动、缺失三种文案。
- 空比赛行显示关联题组。
- 不重新引入 `arenaPath` / `sourcePath` 角色推断。

### 7.3 手测

1. 一个比赛关联 3 个题组 → 比赛详情列表 3 个，题组详情各自显示同一比赛。
2. 归档其中一个题组 → 它只在归档列表；活动比赛只显示活动题组计数。
3. 归档比赛 → 活动题组显示「关联比赛已归档」，不能改选；取消归档后关联恢复。
4. 归档题组详情只读；取消归档后可改标题 / 标签 / 关联。
5. 空比赛行（无旧 problem）能看到关联题组。
6. 回收 / 归档不互相传播；题组仍可用。
7. 1280 宽、键盘、reduced-motion 无异常。

### 7.4 验收

- `npm run verify`：typecheck / 全部 vitest / build 全绿。
- 现有 556 条不因本片回归；新增用例覆盖 0..n、归档只读、跨归档状态和空比赛行。
- 交付报告包含完成度、测试数字、截图和已知问题。
