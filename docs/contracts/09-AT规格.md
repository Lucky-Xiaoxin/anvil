## 2. 数据源（2026-10-04 实测，照抄）

**AT 提交明细（社区 kenkoooo）**：

```
GET https://kenkoooo.com/atcoder/atcoder-api/v3/user/submissions?user={h}&from_second=0
→ [{id, epoch_second, problem_id, contest_id, user_id, language, point, length, result, execution_time}]
```
**每请求最多 500 条、按 `from_second` 升序**（2026-10-05 实测修正：原"单请求全量、无分页"不成立 —— chokudai 全量 = 5 页 2230 条；只打一次只会留下最早的 500 条，格子 / 总过题全读错）。翻页口径：沿时间前沿推进（下一页 `from_second` = 本页最大 `epoch_second`，含端点 ⇒ 页边界重叠、靠 `(source,id)` 主键去重），不足 500 条即末页，同一秒挤满一页停手，`MAX_PAGES=200` 兜底；每页立即落库。单页响应不小 → 超时放宽（≥60s）。**官方 `history/json` 才是真·单请求全量**。

**AT 参赛 / rating 史（官方）**：

```
GET https://atcoder.jp/users/{h}/history/json
→ [{IsRated, Place, OldRating, NewRating, Performance, InnerPerformance,
    ContestScreenName, ContestName, ContestNameEn, EndTime}]
```

**坑（照抄处理）**：

- `history/json` 对**不存在的 handle 返回 200 + `[]`** → 不可用于存在性校验；校验用 `GET https://atcoder.jp/users/{h}` 的页面状态码（200/404）。
- `ContestScreenName` 形如 `agc078.contest.atcoder.jp` → `contest_key` = 去掉 `.contest.atcoder.jp` 后缀（`agc078`）。
- `IsRated:false` 条目 OldRating==NewRating、Performance=0 → **主曲线只收 `IsRated:true`**；非 rated 只计入"参赛 N 场"。
- kenkoooo 是**社区 best-effort 源（无 SLA）**：失败不得阻塞 CF；重试 = 串行、429/5xx 退避 ≤2 次；成功结果缓存本地。
- ⚠️ 端点主机是 `kenkoooo.com/atcoder/…` 这条路径；`atcoder-api.kenkoooo.com` 等旧子域已死，别用（详见 `docs/reports/08` 复验注记）。
- 限流：kenkoooo ≈ 1 req/s、官方同低频；**全程串行，不并发**。`history/json` 属官方 robots 灰色口径 → **仅用户点击触发**。

## 3. 基建：多源化

### 3.1 Schema v2（`vault/anvil.db`，v1→v2 事务内重建 + 幂等）

```sql
-- submissions：加 source 列，主键改 (source, id)（重建表迁移）
CREATE TABLE submissions (
  source TEXT NOT NULL DEFAULT 'cf',
  id INTEGER NOT NULL,              -- CF 提交 id / kenkoooo 提交 id（不同命名空间，勿混）
  contest_id INTEGER,
  problem_key TEXT NOT NULL,        -- 'cf:{contestId}:{index}' / 'at:{problem_id}'
  problem_name TEXT, problem_rating INTEGER, problem_tags_json TEXT,
  verdict TEXT, language TEXT, participant_type TEXT,
  created_ts INTEGER NOT NULL, relative_ts INTEGER,
  PRIMARY KEY (source, id)
);
-- rating_history：重建为 source 化
CREATE TABLE rating_history (
  source TEXT NOT NULL, contest_key TEXT NOT NULL,   -- CF: "2268" / AT: "abc300"
  contest_name TEXT, rank INTEGER,
  old_rating INTEGER, new_rating INTEGER,
  is_rated INTEGER NOT NULL DEFAULT 1,
  performance INTEGER,                -- AT tooltip 用；CF 行 NULL（2026-10-05 实现补充）
  updated_ts INTEGER,
  PRIMARY KEY (source, contest_key)
);
```

- CF 迁移：`source='cf'`、`contest_key = CAST(contest_id AS TEXT)`、`is_rated=1`。
- `sync_state` 键按源命名（`cf:last_sync_at`、`at:last_sync_at`）。

### 3.2 配置与校验

- `vault/config.json` → `{ cfHandle, atHandle?, port }`。
- AT handle 校验：宽松字符集 `[A-Za-z0-9_\-\.]{1,64}`，**存在性走 `/users/{h}` 页面状态码**（§2）。
- 设置页两行：CF / AT，各含 handle 输入、校验、源状态、上次同步、单源同步按钮。

### 3.3 SyncSource 接口（冻结，供本切片 + 未来 XCPC 用）

```ts
interface SyncSource {
  id: 'cf' | 'at'
  checkHandle(handle: string): Promise<{ ok: true } | { ok: false; message: string; kind?: 'not-found' | 'unavailable' }>
  // kind 为 2026-10-05 实现补充：接口层要把「查无此人」和「上游不在线」分给 404 / 502
  sync(handle: string, onProgress: (p: SyncProgress) => void): Promise<SyncResult>
}
```

**必须**：按源域清空/重建（换 AT handle 只清 `source='at'`）；单源失败不影响其它源；进度按源上报。

## 4. API 变化

```
GET  /api/status    -> 顶层保持兼容 + sources: { cf: {configured, handle, lastSyncAt, counts, status}, at: {...} }
POST /api/config    { cfHandle?, atHandle? }        # 分源校验；换 AT handle 只清 AT 数据
POST /api/sync      { source: 'cf' | 'at' }          # 默认 cf
GET  /api/sync/state -> { cf: {...}, at: {...} }     # CF 字段保持切片 1 语义；AT 无 pages/offsite 概念
GET  /api/dashboard?source=cf|at                     # 默认 cf；与切片 1 同构 payload；source=xcpc → 501
```

- AT payload 增量：`rating.series[]` 附 `place? / performance? / isRated`（tooltip 用）；`stats.entryCount`（"参赛 N 场"）。

## 5. AT 卡口径（诚实标注）

- 4 统计卡与 CF 同构：总过题（`distinct problem_id` 首次 AC）/ 当月过题（+ 近 6 月柱）/ AT Rating / 连续训练——**聚合函数直接复用 `packages/shared`，输入换成 AT 提交**。
- rating 卡：`rankLabel` = **AT 原生色名**（Gray / Brown / Green / Cyan / Blue / Yellow / Orange / Red），颜色 = AT 原生色；副行 = "参赛 N 场（非 rated M 场）"；tooltip 附 `Place`（"第 59 名 · Perf 2455"）。
- **诚实标注（一行，从简）**：`2016 起 · 参赛史非提交史 · 来源：AtCoder 官方页 / AtCoder Problems`。
- 活跃格子：与 CF 同构（当日 AC 去重题数、5 档、tooltip），标题注明平台。**档位一律沿用 CF 阈值 `0 / 1–2 / 3–5 / 6–9 / 10+`，不得按源独立分档**（2026-10-04 定稿：独立阈值会让两源格子失去横向可比性；曾以"演示数据单日最高 6 题"为据提过独立阈值方案，该论据不成立 —— 那是生成器上限，真实侧 ABC 8 题 / ARC 6 题 / AGC 6–8 题，练习 AC 同样计入日格）。**色阶按源分**：CF 琥珀阶、AT 青阶，明度阶梯逐级对齐（含 0 档必须比卡片底亮、空格仍然看得见），只换色相不换标尺。**换色范围仅活跃格子**：连续训练刻度与当月柱保持琥珀阶 —— 它们是训练热度读数、与 CF 同语言；格子是日期矩阵、屏上面积最大的组件，承担"换了平台"的识别信号（2026-10-04 收口）。

## 6. 时区钉死

- 全部日/月分桶改为**固定 `Asia/Shanghai`**：offset 算术 `new Date((epoch + 8*3600) * 1000)` + UTC getter；禁止依赖运行机时区。
- 设置页脚注："时区口径：Asia/Shanghai（固定）"。
- 单测：epoch → day 映射与运行环境 TZ 无关。

## 7. UI / 视觉

- 以 `design/mock-02-three-ends.html` 为视觉基线（产出后冻结）；组件复用切片 1（`StatCard / ActivityGrid / RatingChart / Wizard` 等）。
- **段位色在深底走"同色相提亮表"（用户 2026-10-04 看色卡定稿）**：只有 6 档需要提亮，只改明度不改色相 —— CF `Pupil 008000→41D06B`、`Expert 0000FF→5B7BFF`、`Candidate Master AA00AA→D473D4`；AT `Brown 804000→C58A52`、`Green 008000→41D06B`、`Blue 0000FF→5B7BFF`。其余档位（含 AT Gray/Cyan/Yellow/Orange/Red 与 CF Newbie/Specialist/Master/GM+）原生直用。
  - 这**推翻了 `packages/shared/src/rating.ts` 里"深色底上仍用 CF 原值，不自行提亮"那句**（原生 #0000FF 在 #0A0C10 上约 1.6:1，13px 的 tab rating 读不出来）：`rankColorFor(rating)` 要按 source 分派并返回深底可用值，段位色名与档位边界一律不动；曲线段色（涨蓝 / 跌琥珀）与热力色阶也不受影响。视觉稿 `--rk-*` 同时留了原生与提亮两套值备查。
- 平台识别色只作用于：tab 选中指示、详情区标题 accent、统计卡底部读数线；**强度分档已定：CF / AT 走克制版（就这三处），XCPC 走加强版**（再加卡片极淡色晕 + 同色描边，实现上给该屏根节点加 `is-strong`）—— 占位屏没有内容可辨，色晕是它唯一的归属信号；密集屏不染色免得和热力色阶抢。**热力色阶的"档位"与"色相"分开管：档位跨源共用不动（见 §5），色相按源分（CF 琥珀 / AT 青，明度逐级对齐；**范围仅活跃格子**，见 §5）；琥珀主色不动；rating 数字颜色走段位色规则**。
- 切换动画（2026-10-04 第 15 轮改口径，替代原"渐隐渐出 ≤200ms"）：
  - **方向**：卡片中心在内容中线左侧 → 向左飞、被内容区左边缘裁掉（视觉上钻进侧边栏底下）并在末段淡出；右侧 → 向右飞出屏幕外；跨行宽卡（中线 ±3% 内：格子图 / 曲线 / 降级条）算中部，走右侧。
  - **顺序**：飞出 = 距中线远的先走（外圈先、中部后）；飞入 = 距中线近的先来（中部先、外圈后）。
  - **时序不变量（必须保住）**：第 i 张 `delay = i×STEP`、`duration = DUR + i×DSTEP`，STEP 与 DSTEP 同为正 ⇒ 起步与完成时间均严格递增，**任意两张卡不会同时起步、也不会同时完成**；飞入段整体晚于飞出段一个 handoff，跨段同样不撞。实现用 WAAPI（`element.animate`），飞出段必须 `fill:"forwards"`，否则先飞完的卡会在换屏前复活回原位。
  - **参数（定稿档 = 极缓；2026-10-05 实测微调后现行值）**：飞出 `DUR 360 / STEP 41 / DSTEP 9` 缓动 `cubic-bezier(.65,0,.35,1)`（对称 · 加速度明显）；飞入 `DUR 520 / STEP 30 / DSTEP 14` 缓动 `cubic-bezier(.4,0,.2,1)`（柔和 · 两头收）；空档 40ms、底部升起 72px、**起终点缩放 4%**（飞出缩到 0.96、飞入从 0.96 涨回 1，动势的重量主要靠这条）。原始定稿为 STEP 51/40 + 空档 80；2026-10-05 两轮微调（空档减半 + 两段起步间隔各减 10ms）后即为此值。
  - **总时长**：6 卡 = **1390ms**（出 610 + 空档 40 + 入 740）；AT 屏 7 张 ≈ **1484ms**（原定稿 1530 / 1644ms）。**本切片不追快**，动势顺优先。视觉稿屏 4 的调参台其余预设（快 499 / 标准 ≈700 / 平滑 945）留在稿里当对照。
  - **2026-10-10 UX 批次提速（用户拍板，已交付）**：两段时长各砍半、STEP/DSTEP 同步收 —— 现行参数 = 飞出 `DUR 180 / STEP 20 / DSTEP 5`、飞入 `DUR 260 / STEP 15 / DSTEP 7`、空档 20ms、整段 **695 / 742ms**（上面 360/41/9 与 1390/1484 为提速前口径）；时序不变量与「编排期不可打断」不变，现行值以 `packages/web/src/fly.ts` 为准。
  - **切换中再次点击（2026-10-05 用户拍板定稿）**：**编排期间一律忽略后续切换请求** —— 点谁都不动，等这一轮跑完再响应下一次点击。曾评估"当前动画立即落位、直接开播目标档"，实测会让卡片在中间屏先瞬移回原位再重飞（观感"卡直接出现，然后才开始飞出"），弃用。实现与全场景验证见 `docs/reports/实现说明-切片2.md` §7。
  - 飞行途中给内容区加 `overflow-x:hidden`，既拿到边缘裁切效果（左卡钻进侧边栏、右卡切在屏幕边）又免撑出横向滚动条。
  - 缓动候选（下拉里可选，实现照抄即可）：`soft cubic-bezier(.4,0,.2,1)` · `glide cubic-bezier(.16,1,.3,1)` · `sym cubic-bezier(.65,0,.35,1)` · `emph cubic-bezier(.05,.7,.1,1)` · `pull cubic-bezier(.5,0,.9,.35)`（= 上一版默认，被否：太冲） · `settle cubic-bezier(.22,.71,.3,1)`（= 切片 1 的 `--ease`）。
  - `prefers-reduced-motion`：整套编排跳过，直接换屏。切换进行中忽略后续点击，不叠两套动画；焦点在换屏时交给目标屏的 tab 项。
  - React 侧落点：动画只作用在卡片容器上（`StatCard / ActivityGrid / RatingChart` 的外壳），组件内部不感知切换。

## 9. XCPC 契约（2026-10-05 实测复核版，切片 3 的取数依据）

> 复验注：2026-10-05 用真实数据（`李鑫杰@佛山大学` 等）全程走通。与初版（2026-10-04 依仓库源码推断）的差异：**搜索分片路径修正**（是"首字符的 md5"，不是按拼音字母）、PlayerDetail 字段按实测补全、五维 `panel` 在本版导出**缺席**、skillPanel 只有 `overall` 桶。
>
> **2026-10-06 复账补记（以 `docs/contracts/14` §2 为准）**：① 搜索分片实测为 **256 桶**，入桶 = **姓名首字符与学校首字符（小写）各自 md5[:2]**（`李鑫杰@佛山大学` ∈ `46`+`20` 实测）；② "拼音搜索"的机制是**兜底全扫**——纯拉丁 2–6 位（如 `lxj`）在主桶无命中时扫全部 256 桶按 hay 过滤（站点前端原实现如此），中文查询与被查拼音超长不扫；③ 官方榜分母实路径 = `leaderboards/official/meta.json` → `total`（63,120）；④ **逐场奖牌（编年挂牌）不做**：导出无逐场奖牌字段，用 medalCutoffs 反推仅 44% 命中（133 人有奖牌样本），备选数据集 `xcpcio/board-data`（MIT）与其赛站命名未对齐，搁置。

- **数据源**：heimaom 静态导出 `https://heimaom.cn/data/…`（GitHub Pages 托管；`meta.json` 的 `generatedAt` 当版本号）。两个核心端点：
  1. **选手详情** `players/<shard>.json`，shard = `md5(key)` 前 2 位十六进制（UTF-8）；文件 = `{ key: PlayerDetail }` map。实测单分片 ~1.8MB / 293 人（全量 68,940 人 ≈ 256 片）。
  2. **搜索分片** `search/players/<shard>.json`，shard = `md5(查询首字符)` 前 2 位——中文取字（"李"→`46`）、拼音取首字母（"l"→`2d`）；文件 = 紧凑行数组 `[key, name, org, contests][]`（实测 46.json = 4456 行 / 312KB，内含全部"李"姓）。**过滤在客户端做**：`hay = (name\1org\1拼音声母(name)\1拼音声母(org)).toLowerCase()`，`hay.includes(query)`，取前 6~10 条。
  3. 榜单 `leaderboards/{all,official}/…` 仅用于取总人数分母（all=68,940 / official=63,120）；**rank 值已内嵌在选手详情里，无需拉榜单**。
- **拼音声母**：可复刻原站方案——23 个声母代表字（阿波擦搭鹅发嘎哈击喀垃妈拿哦啪期然撒塌挖昔压杂）+ `Intl.Collator('zh-Hans-u-co-pinyin')` 二分求单字声母（Node 直接可用；原实现见 xcpcrating `web/src/lib/pinyin.ts`，含按字符 memoize）。
- **身份模型**：key = `姓名@学校`。**重名不处理**（用户 2026-10-05 拍：xcpcrating 本身就避免不了重名，候选列表里看到学校自行区分即可）。
- **认领流程**：设置页输入姓名/拼音 → 拉 `search/players/<md5(首字符)[:2]>.json` → 本地过滤 → 候选列表（`名字@学校` + 场次）→ 用户选 → 存 `xcpcPlayerKey`。
- **PlayerDetail 实测字段**：`key / name / org / contests / rating / allRank / officialRank / officialRating / history[] / medals? / skillPanel?`（**五维 `panel` 全员缺席，不做**）。
- **history 逐场字段**（全部实测可用）：`contestId`(slug) / `title` / `startAt`(+08:00 ISO) / `teamName` / `rank` / `teamCount` / `official`(打星=false) / `rated` / `ratedOfficial` / `perf` / `rating_after` / `mu_after`(内部期望值，曲线平滑用) / `tier`(final|regional|invitational|provincial) / `solved` / `rankPercent` / `dirt`(=错题数÷过题数；1.5 = 每过一题错 1.5 次) / `dirtWrong` / `dirtSolved` / `firstATime`(分钟，实测 0.41~284.84) / `lastHourSolved` + **官方榜套装**：`perfOfficial` / `ratingAfterOfficial` / `muAfterOfficial` / `rankOfficial` / `teamCountOfficial` / `rankPercentOfficial`。打星场：`official:false`、官方套装全 null —— 行照列、成绩列渲染 `—`。
- **medals**：`{[tier]: {gold, silver, bronze}}`（零奖牌 tier 省略、无奖牌者整字段省略——读时 defensive）。中文标签（原站口径）：`final`=决赛 / `regional`=区域赛 / `invitational`=邀请赛 / `provincial`=省赛。
- **skillPanel**（留给切片 4 掌握图，XCPC 卡首版不展示）：`{all, official}` × `{overall}`（实测每人只有 overall）× 13 轴；每轴是 20 元素紧凑数组，字段序：`score, mastery, topPercent, grade, coverage, uniqueProblems, successWeight, exposureWeight, validContests, rankScore, rawMastery, effectiveProblems, confidence, evidenceLevel, rankEligible, expectedMastery, ability, posteriorSd, rank, …`。解码照抄 xcpcrating `web/src/lib/data.ts` 的 `decodePlayerSkillPanel`（`SKILL_AXIS_LABELS` 中文轴名也在那）。
- **展示口径**（设计 / 实现共用）：**official 单口径**（不给两榜切换）；rating **无段位色名**（数字颜色建议走平台色，设计定）；**无活跃格子**（该源没有提交粒度）；平台色走**加强版**（`is-strong`）；`skillPanel` 不进首版。
