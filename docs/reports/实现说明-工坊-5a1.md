## 2. 行为口径

### 2.1 中间列表

- 比赛题（`parentId` 指向 contest）归入父比赛组；组头可折叠，默认展开。组头本身是比赛对象：比赛命中当前筛选时可点标题进详情，仅作为上下文出现时标题不可点。
- 未挂比赛的题目进「单题」区，每行显示父目录面包屑（对象文件夹名不重复显示）。
- 模板 / 笔记各自成区；`parentId` 找不到父对象的题目进「父对象缺失」兜底区（扫描层已报 `parent-missing`）。
- 折叠状态是界面态：筛选条件（kind / 标签 / label / 搜索）变化时重置；从别处选中组内题目会自动展开该组。不写 localStorage。

### 2.2 模板文件

- API：
  - `GET /api/work/template?id=` → `{ path, exists, content, revision }`。
  - `POST /api/work/template` `{ id, content, baseRevision }` → 同形 DTO；路由单独放宽到 256KB 请求体，正文按 UTF-8 计上限 64KB。
- 只接受 `kind=template`；模板文件夹必须存在且不是符号链接；模板主文件必须是普通文件（符号链接拒绝）。
- `baseRevision=null` 表示读取时文件不存在；若保存时文件已存在 → `conflict`。
- 内容含 NUL、超过 64KB → 400 `invalid`；文件夹被外部移走 → 404 `not-found`，不重建目录。
- 保存成功返回新 `revision`；内容与磁盘一致时不重复写，避免无意义的 mtime 变化。
- 编辑器只有纯文本 textarea：没有语法高亮、没有其它模板文件编辑，也没有内置编译运行（技术锁与 5a 边界不变）。

### 2.3 默认模板

- 默认模板 = 当前索引里 `kind=template`、`effectiveArchived=false`、`updatedAt` 最新的一件；同刻按 `relPath` 升序取第一。
- `POST /api/work/create` 的 `templateId` 口径：
  - **省略** → 用默认模板（没有则什么都不复制）；
  - `null` / `''` → 明确不复制；
  - 字符串 id → 指定模板（仍允许显式选用归档模板，与 5a 一致）。
- 创建对话框默认选中「默认模板 · <标题>」，另有「不复制模板」与逐个模板可选；选了模板才显示该下拉。

## 5. 已知问题 / 不处理项

1. **默认模板按 meta 的 `updatedAt` 取最新**；模板文件内联编辑不更新 `.anvil.json`（本片「只写模板文件」的约束），因此编辑旧模板不会把它顶成默认。默认项在创建对话框里显式可见，不做隐式惊喜。
2. 模板编辑器是纯 textarea：无语法高亮、无撤销栈以外的编辑能力、无其它模板文件编辑；正文上限 64KB，路由请求体上限 256KB。
3. textarea 提交会把 CRLF 归一成 LF；不保留 BOM；二进制内容（含 NUL）拒绝。
4. 组头的「N 题」是**当前筛选结果内的题数**；只筛「比赛」时组头显示 0 题（题目被 kind 筛选挡掉），这是筛选语义，不是数据丢失。
5. `test.cpp` 若是模板里唯一的 `.cpp`，会按既有解析顺序被当作主文件（既用于 `solution.cpp` 来源，也用于内联编辑）；未在本片改变 5a 的复制优先级。
6. 无文件监视：外部改动靠加载 / 手动刷新；模板保存时会用 revision 检测到外部改动并拒绝覆盖，但不会自动把外部内容拉回界面（需点「重新载入」）。
7. 未配置的受管根 / 未初始化 / 回收站等 5a 既有状态未改动；本片没有新增依赖、没有新增 SQLite 表。
8. 模板编辑的未保存 / 加载失败边界：切换对象或离开工坊时没有未保存拦截，本地改动会丢；模板加载失败后编辑器可能暂时保留上一个模板的内容（组件未清空 file）。5a.2 补。
9. 中间列表语义：`单题` 是「未挂比赛的题目」子集，不是 kind；行内未常驻 kind 徽章，自由标签（如「笔记」「板子」）与 kind 视觉相近；分区计数（比赛 2 / 单题 4 / 模板 2 / 笔记 1）不是对象总数的相加分区（比赛组内还含 5 题）。5a.2 统一：kind 徽章、`单题` 改名、计数补齐。
