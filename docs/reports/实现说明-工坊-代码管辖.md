## 3.3 追加：VP 成绩存档（用户 2026-10-21 追加需求）

### 路径输入兼容

- 服务端 `validateRootPath()` / `resolveInside()` 统一走 `normalizeInputPath()`：去掉首尾引号（资源管理器「复制为路径」形状），`/` 与 `\` 都接受。
- 设置根输入框失焦时归一成 `/`，并在输入框下提示两种分隔符都行。
- `work-paths.test.ts` 增加反斜杠 / 带引号路径用例（9 条）。

### 保存链路

- **目录行**：`listGhostPaths()` 枚举 `arena:ghost:` 键；有逐发成绩的场次出现「保存」；保存时按当前 `live` 会话位置存 `live`，否则按回顾会话 `scrubMs` 存 `review`。
- **回放顶栏**：有逐发成绩时出现「保存」；写入当前 `review/live`、`viewMs`、暂停态与封榜视角。
- **落点**：`POST /api/work/arena-record` 按 `arenaPath` 找唯一 contest；
  - 已有：更新其 `record.json`；
  - 没有：自动建一场 contest（标题取目录行的 `日期 + 站名`，`links.arenaPath` 写入），再写 `record.json`；
  - 同 `arenaPath` 多个对象 → 409 `conflict`。
- **record.json**（2 空格缩进 + 末尾换行，原子写）：`{schema:1, arenaPath, title, savedAt, ghost:{show,subs}, view:{mode,viewMs,paused,frozenView}}`；服务端 `parseWorkArenaRecord()` 校验 schema / 路径白名单 / 逐发判名（只收 AC/WA/TLE/RE/CE）/ 回放位置。

### 从工坊回到回放

- 比赛对象详情出现「回到回放」（`links.arenaPath` 存在时）。
- 深链 `#/arena?path=<arenaPath>`：目录就绪后找行 → `GET /api/work/arena-record` → 进回放；入口消费后用 `replaceState('#/arena')` 清掉查询，避免退回目录又被带入。
- `ArenaBoard` 接 `initialRecord`：
  - 幽灵逐发写回 localStorage，面板 / 榜单行同源；
  - `review` 存档停在 `viewMs`（封榜视角一并恢复，不落「回放中」会话）；
  - `live` 存档从 `viewMs` 接钟，暂停态保留。

### 端到端证据

- 使用真实缓存场次 `official/ucup/ucup2ndfinals.srk.json`（复制到 temp 应用，不碰用户 vault）。
- 目录保存后：工坊自动出现 `2025-02-22 The 2nd Finals`，`record.json` 进入文件列表；record 逐发为 25′ WA / 30′ AC。
- 工坊「回到回放」后：榜单显示 `0:30:00` 回顾位置、幽灵行「我的成绩 / 你」第 17 名（1 题 / 50 罚时），顶栏「保存」可用；hash 回到 `#/arena`；零页面异常。
- 目录行保存与回放顶栏保存各走一次，均返回「已保存」。

7. **`root-version` 的根不能就地降级**：设置屏允许输入另一个路径重新初始化；同一路径会继续返回 409。
8. **parent-missing 对象保留在列表**：按 §4.4「保留该对象，进 errors」；计数仍按自身 primary 计，标签悬空时不计。
9. **未做视觉稿评审**：本片按现有 token 直接实现，三栏信息密度与详情字段顺序需要设计侧过目后再冻结。
10. **手测口径**：契约 §13.2 的「VS Code 新建文件」用等价的外部文件写入 + rescan 验证；未真实拉起 VS Code。
11. **`open` 的 VS Code 分支未真机触达**：避免在自证时打开真实编辑器；文件夹 → Explorer 已真机冒烟，文件 → VS Code 的路径解析（`E:\Microsoft VS Code\Code.exe`）已验，spawn 由注入单测覆盖。
12. **契约基线数字**：契约写 384，实际开工基线 387；本报告以 387 为基线。
13. **VP 存档是 §15.3 的先行实现**：`record.json` 不写回 `.anvil.json`，工作台对象本身不记录「已存」状态；目录行的「已保存」只保留到本次目录挂载，重新进入会回到「保存」（重复保存是幂等的）。
14. **目录行保存的回放位置**：优先用当前 `live` 会话；没有会话时用最近会话的 `scrubMs`，再没有就是从 0 开始的回顾。要精确存当前位置，请用回放顶栏的保存。
15. **自动建比赛**：没有同 `arenaPath` 的 contest 时自动建一场，标题取目录行的「日期 + 站名」，目录日期用创建当天（契约 §5.1 的服务端本地日期），不是比赛日期；标题超过 120 字会拒绝。
16. **同一 arenaPath 多个 contest**：保存和读取都返回 409 `conflict`，不自动挑一个或合并。
17. **record.json 文件同名**：若用户手动在比赛文件夹里放了 `record.json`，保存会覆盖它（与回收站 `trash.json` 同类边界）。
18. **保存是手动快照**：保存后继续改「我的成绩」或拖动回放进度，要再点一次保存；不做自动同步。
19. **「打开文件夹」改为资源管理器优先**：按用户 2026-10-21 反馈（按钮语义 + 真机没有窗口），文件夹先 `explorer.exe`、失败再 VS Code；文件仍 VS Code 优先。与契约 §6.7 的 code → explorer 顺序有意不同。同时去掉 spawn 的 `windowsHide`（会把 GUI 窗口一起藏掉），并修正 `where code` 只取第一行导致漏掉无扩展 `bin/code` 的问题。**真机冒烟已通过**（临时文件夹 Explorer 窗口检测 + 关闭）。
