## 4. 已知问题与偏差

1. **词表别名检索未落**：`WorkTaxonomyDto` 没有 aliases 字段，v1 搜索只覆盖标题 / labels / 节点名 / 路径；代码留 `TODO(切片5a)`（`web/src/components/work/derive.ts`）。
2. **模板创建不预写 `template.cpp`**：契约 §4.1 标为可选；创建流程只写 `.anvil.json`，从既有模板新建题目时才复制文件。
3. **`arenaPath` 只有普通文本输入**，没有榜单目录选择器；服务端按 `contestPathOk` 校验。
4. **根路径展示**：主界面工具栏只显示 basename（完整路径在 tooltip 与设置屏），以贴合 §9.2「root 仅用于设置页展示」。
5. **回收站清单名固定 `trash.json`**：若对象文件夹内原本有同名文件，移入回收站时会覆盖；v1 未处理此极端碰撞。
6. **切换根只有 API**：`POST /api/work/init` 支持切换；界面未提供「换根」入口（契约只要求设置屏初始化）。
7. **`root-version` 的根不能就地降级**：设置屏允许输入另一个路径重新初始化；同一路径会继续返回 409。
8. **parent-missing 对象保留在列表**：按 §4.4「保留该对象，进 errors」；计数仍按自身 primary 计，标签悬空时不计。
9. **未做视觉稿评审**：本片按现有 token 直接实现，三栏信息密度与详情字段顺序需要设计侧过目后再冻结。
10. **手测口径**：契约 §13.2 的「VS Code 新建文件」用等价的外部文件写入 + rescan 验证；未真实拉起 VS Code。
11. **`open` 的编辑器解析在真机未触达**：避免在自证时打开用户编辑器；注入 spawn 已覆盖协议。
12. **契约基线数字**：契约写 384，实际开工基线 387；本报告以 387 为基线。
