## 4. 关键实现口径

### 4.1 文件与 DTO

- `problem-marks.json` 放在比赛目录根，与 `record.json` 同级；扫描器只把它当元数据，不登记对象、不当题组候选。
- DTO：`ProblemMarksDto`（`contestId` / `arenaPath` / `revision` / `problems` / `marks` / 可选 `unreadableMarks`）；`WorkObjectDto.problemMarkSummary`；`WorkTreeDto.problemTags`。
- `marks` 的键必须是快照 alias；快照外的手写条目在读取时计数并在重写时原样保留；`prefillApplied` 不进 DTO。
- 文件列表把 `problem-marks.json` / `record.json` 标为「元数据」。

### 4.2 预填与幂等

- 只读存档 `ghost.subs`，按 `problems[p].alias` 映射；只填 `contest-ac`，已有进度、`prefillApplied` 命中的一律跳过。
- 只有自动预填过的 alias 才进 `prefillApplied`；用户手动设过的 `已过` 清空后再保存会重新预填，这是契约口径（见 §6.1 已知问题说明）。
- 同输入重复 `sync` 不重写、不改 revision；`update` 整份替换、全空条目删除、`prefillApplied` 保留。

### 4.3 用户拍板的三个实现细节

1. 模板分类选择器随词表退役移除；新建模板统一落 `templates/_unsorted/`，旧模板目录不动。
2. 榜单 `problems[]` 缺 / 坏 `alias` 时，前端按题序补 A/B/C…，保证快照能建立；合法别名的题保持原值。
3. 从榜单「去标记」落在已归档比赛时，按用户决定视为不可用、停在列表；归档比赛的标记需从「看归档」进入详情修改。

## 6. 已知问题 / 不处理项

### 6.1 已知问题

1. **归档比赛的保存提示与深链**：保存后提示仍按契约显示「去标记」，但按 2026-10-30 的决定，归档对象深链视为不可用；用户需从「看归档」进入详情改标记。提示条本身会显示「这场已归档，题目标记仍可修改」。
2. **列表徽章滞后**：列表汇总在扫描时派生；外部手改 `problem-marks.json` 后不点「重新扫描」，列表徽章可能滞后；详情每次读取最新文件并给错误 / 最新标记。
3. **离开提醒的覆盖面**：关闭 / 刷新走 `beforeunload`；工坊内切对象 / 切活动归档 / 去回放 / 侧栏导航、导入 / 新建 / 登记完成后的自动切换、重新扫描、改标题 / 标签 / 归档 / 关联，以及 `#/master` 内的深链前进后退都有确认（对抗修复 `ef13e9b`）。仍未覆盖：外部改动导致当前对象从树里消失时的被动卸载。
4. **手动设过的 `已过` 清空后会再预填**：只有自动预填过的 alias 在 `prefillApplied` 里；这是契约 §3.4 的刻意口径，不是遗漏。

### 6.2 本片不做（契约 §2.2）

掌握图 / 热力图 / 能力推断；单题目录对象 / 文件级标签 / 代码文件绑定；补题状态机 / SRS / 提醒；题面链接；个人赛事导入；全局待补页面；多标签交集筛选；自动拉题目标签 / 难度；成绩曲线 / 赛后摘要；批量标记；旧对象标签自动迁移。
