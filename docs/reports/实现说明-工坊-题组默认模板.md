## 1. 问题与断点

5a.1（`7a02c8d`）给「新建题目」做了默认模板：对话框「模板」下拉的默认项是 `默认模板 · <模板名>`（另有「不复制模板」与逐个模板），服务端在 `templateId` 省略时把默认模板的 `template.cpp` / 首个 `.cpp` 复制为 `solution.cpp`，`test.cpp` 一并复制。

5a-2 题组语义（`f2cbe4f`）把「题目」从可建类型里去掉、题组（`problemset`）成为唯一可建单元，**对话框里的模板下拉跟着整个题目表单一起删了**；服务端 `createNow` 的默认模板分支仍限定 `kind === 'problem'`，而 UI 已建不出 `problem`。结果：功能在 UI 上彻底消失，题组（用户实际唯一会建的对象）从来不走这条路。契约 23 §6.1 当时写的是「`templateId` 仅 problem」，26 的题组语义没接手这条——不是谁改坏，是对象模型搬家时漏搬。

## 4. 已知问题 / 不处理项

- **没有「不复制模板」的 UI 出口**：新建题组一律带默认模板；要临时不要模板，目前只能建完后手动删 `solution.cpp`。API 层已支持 `templateId: null`，补一个下拉即可（Web 一个文件）。
- **默认模板按 `updatedAt` 最新挑选**：与 5a.1 同判据（`shared/work.ts` `defaultTemplateOf()`）；归档模板不参与。
- **旧 `problem` 不受影响**：其默认模板行为与 5a.1 一致；本次只是把题组并入同一判据。
