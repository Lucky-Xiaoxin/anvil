## 3. 实现摘要

- **数据**：新增 schema 2 存档（`.anvil-records/<recordId>.json`），结束状态合法组合、revision（原文件字节 SHA-256）、缓存榜单校验（题数 / 时长 / 分钟值）；比赛对象与 `.anvil.json` 不变。
- **服务端**：`work/records.ts` 文件层 + `work/store.ts` 宿主 / 写队列 / 回收站；新 `arena-records` 系列接口（列表 / 条目 / 旧档 / 创建 / 更新 / 改名 / 回收 / 恢复），创建 201 / 幂等 200，成绩写 1 MiB；回收清单 schema 2 `arena-record` 与对象 schema 1 并存。
- **前端**：单键 `arena:draft:<path>` 草稿（phase / session / ghost / result / target / savedBaseline / pendingSave）；旧 `arena:session:` / `arena:ghost:` 在新键不存在时迁移，成功后才删旧键；三种身份（当前练习 / 查看 / 编辑）加查看终榜；历史选择层、命名 / 替换确认、冲突与未知结果对账、多标签失效提示。
- **工坊**：比赛详情「历史成绩」区（改名 / 删除 / 旧进度恢复），回收站两类条目徽标、所属比赛与父比赛提示。
- **顶栏收口（§6.1.1 / D11）**：常驻只留回到目录 / 标题 / 状态条 / 时钟（并入状态条）/ 我的成绩排名 / 保存；其余进带文字的「更多」菜单（历史成绩 + 计数、我的成绩、另存一份、再练一次、手动记一场、标记旧成绩已结束、重试对账）；查看身份主按钮改为编辑成绩、无保存；编辑身份保留保存（用户确认）；封榜视角 / 仅正式队移到榜体第二行工具条；状态统一为一句话；多档时保存右侧显示 `→ 目标`，单档仅 tooltip，保存成功短暂显示 `已保存到 …`；多档首次出现时全局提示一次历史成绩入口已进菜单。
- **旧数据**：旧根 `record.json` 只读兼容；review 投影进 `records`，live 只进 `legacy`；仅改名升级保留 unknown，编辑需确认结束后转 manual；旧 live 恢复不改原文件。
- 不新增依赖、不新增 SQLite 表、不改比赛 / 题组模型。

## 6. 已知问题、未做与不处理

- **真实数据未迁移**：旧 `record.json` / 旧浏览器数据只读兼容；升级发生在用户明确编辑或改名时。真实工作区未执行任何迁移或删除。
- **多标签不承诺并行编辑**：同一草稿被另一标签改动后，旧页只读并要求重新读取；正式档靠 revision 防覆盖。真实双页已验证失效提示，未做自动合并。
- **超时对账路径**：浏览器实测的是“服务不可达 → 结果未知 → 重新读取”；60s 读超时后的 idempotent 重试由服务端单测覆盖，未在浏览器里构造完整 60s 延迟。
- **1280 顶栏**：保存目标名在 ≤1320 隐藏，全名放在「保存」按钮 title；这是契约允许的“省略但可查看全名”。
- **顶栏收口口径（用户 2026-10-29 确认）**：查看历史身份不显示保存（主按钮编辑成绩）；编辑身份保留保存为主按钮；「我的成绩」进菜单；不新增“存到其它档”；多档历史入口提示全局一次。
- **工坊历史区滚动**：记录多时右栏需要滚动；未做分页（个人数据量，非本片范围）。
- **不处理**：单份永久删除、成绩曲线、存档内版本历史、自动合并冲突、性能专项、真实 srk 数据入库（契约 §2.2）。

## 9. 补记 2026-10-30：删除目标存档后的悬空草稿

**现象**：在工坊删除某场比赛的旧 `record.json`（legacy）后，回到回放页继续编辑并保存，反复提示「找不到这份存档」；目录行保存也一样。

**根因**：删除只移动存档文件，浏览器草稿仍绑定被删的 `recordId`（这里是 `legacy`）；`update` 按 revision 找不到文件，服务端返回 404，界面把原始错误直接反复显示。不是 revision 冲突，也不是题目快照问题。

**修复**：

- [draft.ts](../../packages/web/src/components/arena/draft.ts) 新增 `detachDraftTarget`：删除存档后，若同场草稿的 `target.recordId` 命中，清 `target` / `savedBaseline`，保留 `ghost` 与 `result`。
- [WorkRecords.tsx](../../packages/web/src/components/work/WorkRecords.tsx) 删除成功后自动解绑，并提示「原存档已删除；这场本地草稿已解除保存目标，下次保存会新建一份」。
- [ArenaBoard.tsx](../../packages/web/src/components/arena/ArenaBoard.tsx) / [ArenaCatalog.tsx](../../packages/web/src/components/arena/ArenaCatalog.tsx)：更新遇到 404（另一标签页 / 其它浏览器删除）时不再反复报错，自动解绑并打开命名对话框，按新建保存。
- 测试：`arena-draft` 新增 2 条（解绑保留成绩 / 不匹配不动）；组合 `npm run verify` **642/642**（34 文件）+ build 通过。

**用户现场**：2026-05-02 西安邀请赛的旧 `record.json` 在回收站 `20261030-182853_tr_d52ad4551a5807531529df2c6c99f646`；新存档 `rec_da40d44c1dcc731a0ff0dd82c169fdb4` 未受影响。重启到修复后的前端后，直接保存会转成新建命名；也可以先从回收站恢复旧档来解除悬空。
