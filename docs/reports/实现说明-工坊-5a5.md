## 6. 修复批次（2026-10-26，提交 `2e27413`）

### 6.1 冻结判据统一到 `effectiveArchived`

**问题**：`updateNow` 的冻结判断只看对象自己的 `archived`，而 `trashNow` / `createNow` 看的是 `effectiveArchived`。旧 `problem` 被父比赛带着归档时（它自己 `archived=false`）会出现一套自相矛盾的行为：列表把它当归档显示 → 回收被拒（409「先取消归档」）→ 改标题 / 标签在 API 层放行（UI 是禁用的，接口不设防）→ 而按提示去调「取消归档」返回 200 却什么都没发生（它自己的开关本来就是 false），对象仍留在归档列表。跟着错误提示走会原地兜圈，真正能解冻的是父比赛。

**修复**：`store.ts` `updateNow` 的冻结判据 `current.archived` → `obj.effectiveArchived`，与 trash / create 用同一个词。改完后服务端与 UI 同口径：继承归档的旧 problem 在父比赛解冻前完全只读。这是判据收敛，不是加防御。

**回归**：`work-store.test.ts`「继承归档同样冻结：父比赛归档时旧 problem 的 retitle / labels / trash 一律拒绝」。

### 6.2 归档类拒绝错误码统一为 `conflict`（409）

**问题**：同为「先取消归档再重试就能成功」的拒绝，409 conflict 与 400 invalid 各占一半（改字段 / 回收走 409，关联与挂到归档比赛走 400）。

**修复**：五处 throw 点 `invalid` → `conflict`——create 往归档比赛建题、create 题组关联归档比赛、adopt 关联归档比赛、update 当前关联归档时改挂 / 清除、update 挂到归档比赛。`400` 留给形状 / 值域错误（zod 层已是这一口径）。不新增 `WorkErrorKind`，契约 27 §4「沿用现有 WorkError」不破；文案不变、前端不按 status 分支，UI 无感。

### 6.3 保存成绩不再无声覆盖上一份（最小改动）

**模型限制（非本片引入）**：一个 `arenaPath` ↔ 一个 contest 对象 ↔ 一份 `record.json`。`saveArenaRecordNow` 每次对同一文件整份 `writeFileAtomic` 覆盖，且同 `arenaPath` 出现两个 contest 会被 `contestByArenaPath` 判为冲突坏状态——所以「同一场 VP 两次、两份都留」在当前模型下做不到，手动建第二个对象也不是旁路。契约 16 定义 `record.json` 时就是「这场的那份存档」，契约 20 v8 的逐发录入也建在同一份之上。

**本批做法**：回放页两个保存入口（目录行 `ArenaCatalog.saveGhost`、回放顶栏 `ArenaBoard.saveRecord`）写之前先探一次已有存档（`probeSavedRecord`：404 = 没存过 → 直接保存；其它错误照抛，那种状态下保存本身也会失败）。命中已有存档时，第一次点击只挂出确认——按钮 `保存` → `确认覆盖`，行内 / 顶栏小字 `已有 10-20 14:32 的存档 · 3 发`——第二次点击才写，按钮失焦即取消（同 `GhostPanel` 清除、`WorkDetail` 回收的两击确认口径）。不改数据模型，不引入多份文件。

**纯逻辑**：`record.ts` 新增 `probeSavedRecord` / `overwriteHintOf`，后者补 2 条用例（上海时间到分钟、跨年补年份）。

### 6.4 口径（只记录，代码不动）

- **归档不冻结成绩存档**：归档定格的是工作台内的组织结构（标题 / 标签 / 关联 / 回收站），`record.json` 归榜单侧管——归档比赛在回放页仍可保存成绩。契约 27 §4 的冻结清单本就是枚举式，`record.json` 不在列，本条只是把模糊变成明确；拒绝它会把 VP 流程打断在「先去工坊取消归档」这种绕路上。
- **同场多存档另立契约**：要留两次 VP 需要「列出一个 arenaPath 下所有存档」+ 保存目标名（建议 `record-<时间戳>.json`，自描述且免「-2 已存在」顺延）+ 读取侧每处回答「认哪份」（「我的成绩」幽灵行、回放位置）。改动量中型，不塞进 5a-5。
- **WONTFIX 两条**：① `adoptNow` 不查父比赛是否归档——触发条件苛刻（须手动往归档目录塞文件夹再点「登记」，正常 UI 流程碰不到），且旧 problem 挂 contest 本就是 5a 之前的兼容区；② 归档模板正文仍可写——`saveWorkTemplate` 不在 27 §4 冻结清单内。
