## 5. 已知问题与偏差清单（如实）

**A. 契约与实测冲突（最重要，建议架构侧回写）**

1. **`docs/contracts/09` §2 说 kenkoooo「单请求全量、无分页；一次同步只打 1 次」—— 实测不成立。** 2026-10-05 本机复测：`/v3/user/submissions` 每请求**最多 500 条**、按 `from_second` **升序**返回，加 `limit` 参数无效；chokudai 全量 = **5 页 2230 条**。照契约只打一次的话，大号只会留下**最早** 500 条（chokudai 是 2012–2016），活跃格子、总过题、连续训练全部读错。已按「沿时间前沿翻页 + 页边界重叠一秒靠主键去重 + 同一秒挤满一页才停手 + `MAX_PAGES=200` 兜底」实现。
   注：`docs/reference/03` 里「单请求全量、无分页」那句原本是描述**官方 `history/json`** 的（那句仍然成立），`docs/contracts/09` §2 把它挪到了 kenkoooo 头上。

### 6.2 回退了什么

`git revert` 掉 `1fac0b1` 与 `f479621` 两个提交里的结构性改动，代码回到 `5cd5db6` 的切换实现：

### 6.3 回退前采集到的现象（下一步查案的起点）

用户实测记录，比"Firefox 首帧闪"更具体，而且**Edge 也能复现其中一条**：

1. AT 未配置（停在「还没填 AtCoder handle」空态卡）时，**AT → CF 百分百闪**，闪出来的内容是那张空态卡本身 —— 说明闪的不是"新屏没动画的第一帧"，而是**旧屏的内容在新屏之后又被画了一次**。
2. 四张统计卡**完全出现后会突然消失，然后再次飞入出现** —— 像是飞入段跑了两遍，或第一遍跑完后被第二次 `flyIn` 重新按回起始态。
3. 同步 AT 之后，**CF → AT 也出现同样问题**。
4. 原先只当作 Firefox 特有的那一帧，在 Edge 上也能复现 → 「Gecko 首帧不回填 `backwards`」这个定性**不成立或至少不完整**，我前两轮的方向都被它带偏了。

这三条共同指向：**换屏与 `flyIn` 的触发次数 / 时机**有问题（`landRef` 与 `useLayoutEffect([shown])` 的重入、`commit` 的两条路径、或 React 在 `setTimeout` 里那次非 flush 提交与 effect 之间的间隙），而不是引擎对首帧的处理差异。回退到干净基线后再从这里查。

## 7. 切 tab 闪屏 · 根因与修复（2026-10-05，分支 `fix-tab-switch-flash`）

用户口径：**启动后 CF ⇄ AT 两个方向切都会闪，概率性触发；Edge 不复现，Chrome / Firefox 复现。**
现象 = 目的地（或原位置）的卡先以终态"全部出现"，闪一下，再消失，然后才开始飞入。

### 7.1 结论：是三个代码缺陷，不是引擎首帧问题

§6.2 回退的两次尝试（三屏常驻 DOM、内联钉桩）方向都不对。真正的原因全部在 `packages/web/src/App.tsx` 的切换状态机里：

| # | 位置 | 机制 | 症状那几拍 |
|---|---|---|---|
| **A** | `commit()`（原 `flush = false` 那条路径） | 落地的换屏走的是普通 `setShown()`，而 `main.tsx` 是 `createRoot` + 该调用发生在 `setTimeout` 里 ⇒ React 18 把这次提交排进调度器，**换屏不在本 task 内**。换屏前一行刚 `cancel()` 掉挂着 `fill:"forwards"` 的飞出动画 ⇒ 旧屏的卡先以终态**复活**，新屏还没上 | "卡突然全部出现" + 概率性（取决于这一帧有没有被让出去） |
| **B** | `select()` 的中断分支（原 161–166） | 在飞时又点击 → `cancelFly()` 撤掉在飞动画（`forwards` 填充丢失 ⇒ 卡片瞬回原位），紧接着 `commit(mid, true)` 把**在途目标屏**整屏无动画地摆上屏，而 `landRef === false` ⇒ 落地布局效果早退、**这一屏永远拿不到飞入**。AT 空态屏只有 1 张卡，它的飞出段只有 360+40=400ms，在途窗口比 6 卡屏（650ms）短得多 —— 所以"AT 未配置时 AT→CF 百分百闪" | "闪一下"（闪的正是那张空态卡本身，与 §6.3.1 记录一致） |
| **C** | `select()` 缺"目标没变就忽略"守卫（§6.2 连它一起回退了） | 连点同一个 tab：撤掉飞出段（同上，卡片回原位）→ 又开一段新的 `flyOut`，而 `flyOut` 的首帧关键帧**就是自然位 + `opacity:1`**（`fly.ts:76/81`）⇒ 卡片停在终态不动、等各自 delay（最多 246ms）才开始飞走 | "又瞬间消失" |

A 解释"概率性 + Chrome/Firefox 有、Edge 没有"（调度时机差异）；B/C 解释"两个方向都有、某些场景百分百"。
三者叠起来正好是用户描述的三拍，且都**不需要任何引擎假设** —— 这也解释了为什么前两轮按"Gecko 首帧不回填 `backwards`"改都没修好。

**已排除**（逐条核过，不要再往这些方向改）：
- `.rise` 重播 —— CF/AT 的卡片容器被 React 复用（打标签实测 4 次切换节点全部存活），只挂载时播一次；
- WAAPI `fill:"backwards"` 首帧不生效 —— 实测换屏那一帧目的地卡片已是 `opacity 0 / translateY 72–145px / scale 0.96`，同 commit 内不可能被绘制分开；
- 一次点击里 `flyIn` 跑两遍 —— 它在 `useLayoutEffect([shown])` 里，只在 `shown` 变化时执行。

### 7.2 改了什么

1. `commit()` **一律 `flushSync`**（去掉 `flush` 参数）：让 `setShown` 与随之而来的 `useLayoutEffect`（挂飞入动画）在**同一个 task** 内跑完，从根上不给浏览器插帧的机会。→ 治 A。
2. `select()` **不再有"改道"分支**：`decideSwitch()` 只要看到编排在播就返回 `ignore`（用户 2026-10-05 拍板，见 §5-B4）。在途屏不再上屏 —— 早期版本那句 `commit(mid, true)` 会把中间屏整屏无动画地摆出来，是症状 B 的直接来源。→ 治 B。
3. 因此 `cancelFly()` / `wantRef` / `resetFly()` 全部成了死代码，已一并删除：现在不存在"撤销一段编排"的路径，每段编排都跑到自然结束。
4. 把决策抽成纯函数 `decideSwitch()`（`packages/web/src/switcher.ts`）+ 5 条单测，钉住"在飞一律忽略""同屏不重播""换源从当前屏起飞"三条规则，避免再被回退掉。

`fly.ts` 的时序数值一个没动（`fly.test.ts` 的 1390 / 1484 断言照旧绿）。
