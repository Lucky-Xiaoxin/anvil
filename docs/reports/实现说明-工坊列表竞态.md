## 1. 背景

`Workbench.load()` 原先没有请求序号 / 取消：快速切换活动与归档时，先发出的树请求如果后返回，会覆盖 `tree`（列表、计数）和选中项；旧请求失败还会把 error notice 打到新视图上。异步操作（保存 / 归档 / 回收 / 扫描 / 导入）之后的刷新使用闭包里的旧 `archived`，用户在操作期间切视图时也会被旧视图覆盖。

## 2. 本次口径（2026-10-28 已拍板）

| 项 | 口径 |
|---|---|
| 最后请求胜出 | 只有最后发起的树请求能写回列表、计数、选中项、加载态、错误提示与设置态；旧请求取消 + 序号双重判定 |
| 旧失败 | 旧请求失败不写回新视图，不出错误条、不切设置屏 |
| 选中项 | 响应回来时按当前选中项判定；加载期间新选的对象不被旧视图清掉；切视图先清空，新视图加载完再按最新选中决定 |
| 异步后刷新 | 保存 / 归档 / 回收 / 扫描 / 导入后的 reload 使用当前视图；操作期间用户切视图或换选中项时，完成态不抢选中项 |

## 8. 合并前独立验收与修复（2026-10-28）

原提交的树请求隔离有效，但以下完成态仍会抢选中项；本节补充 §3 的完成结论，不覆盖原验收记录。

- 新建 / 登记 / 导入后带指定对象的 reload：等待期间选择 B，旧 reload 完成后仍会选回新对象。增加独立的选择序号门；用户再选择、清空或切视图后，旧的自动选中失效，即使先选 B 再选回 A 也不恢复旧意图。
- 回收 A 期间选择 B：原完成回调无条件清空详情。现在只在当前仍选 A 时清空；刷新失败保留错误提示，不再被“已移入回收站”盖掉。
- 导入完成后的 reload 被新视图请求取代：不再直接跳过导入结果；树加载清旧提示提前到发起时，避免新视图的成功响应擦掉已经产生的导入汇总，已有错误优先保留。
