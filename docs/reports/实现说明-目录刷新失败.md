## 1. 背景

「刷新目录」失败时有两级静默：服务端 `catalog(refresh)` 在有旧缓存时回 200 旧缓存，DTO 没有 stale 标记；前端显式刷新失败只在 catch 里存 `error`，页面仍是 ready，不显示任何提示。用户唯一能察觉的是 `fetchedAt` 没动。无缓存时初次加载本来就有错误屏 + 重试，本批补齐「有缓存但刷新失败」的反馈。

## 2. 本次口径（2026-10-28 已拍板）

| 项 | 口径 |
|---|---|
| 服务端表达 | 显式刷新失败但有旧缓存 → **200** + `stale: true` + `refreshError`（上游原因）；`fetchedAt` 仍是旧缓存 mtime；无缓存 → 502 |
| 有缓存提示 | 目录照常显示；搜索框上方常驻 warn 条「刷新失败，正在显示旧缓存（目录缓存于 …）」+ 重试；下次刷新成功即消失 |
| 无缓存提示 | 完全没数据才出错误屏「目录拉取失败（无可用缓存；原因）」+ 重试 |
| 客户端已有旧目录、服务端无缓存 | 保留旧目录 + warn 条 + 重试，不白屏 |

## 5. 真机验证（2026-10-28）

隔离方式：`git archive` 当前分支 HEAD + `git apply` 工作树改动到系统 temp 副本，`node_modules` 用 junction；临时 mock 上游在 `127.0.0.1:7801`，ANVIL 在 **7799**，临时 `vault/` 独立。真实 `vault/config.json` / `vault/anvil.db` 验证前后 sha1 一致（`68476b…` / `34686c…`），文件数 105 不变；临时目录与两个进程已清理，7799 / 7801 无监听。

1. **有缓存 + 刷新失败**：mock 上游切 503，点「刷新目录」→ 服务端 200 `{ total: 1, stale: true, refreshError: "127.0.0.1:7801 HTTP 503 · 已重试 3 次 · 1 个源" }`；目录保留，搜索框上方出现 warn 条「刷新失败，正在显示旧缓存 · 目录缓存于 2026/10/28 20:45:01」+ 原因 +「重试」。
2. **重试恢复**：mock 切回 200，点「重试」→ warn 条消失，footer 缓存时间更新为 20:51:30。
3. **客户端有旧目录、服务端无缓存**：删临时 `vault/arena/_catalog.yaml`、mock 切 503，点「刷新目录」→ 服务端 502；目录仍保留，warn 条出现。
4. **完全无缓存**：保持 mock 503 并刷新页面 → 错误屏「目录拉取失败（无可用缓存；127.0.0.1:7801 HTTP 503 …）」+「重试」；mock 切回 200 后点「重试」→ 错误屏消失，目录恢复（1 场）。
- 本批无视觉稿变化，未新增入库截图；验证证据为浏览器 DOM 快照、服务端 DTO 与 mock 上游请求计数。

## 6. 已知问题 / 不处理项

- 只在显式「刷新目录」失败时标 stale；非刷新请求命中缓存是正常路径，不提示。
- 没有自动定时刷新；本批不新增。
- 单场榜单（回放入口）的失败提示沿用既有逻辑，不在本批范围。
- stale 原因可能较长（多源重试串），作为 warn 条第二行展示；不做折叠。
