## 2. 路径安全细节

- `allocateTarget()`：每个候选目标先 `resolveInside(root, rel, { allowMissing: true })`，任一级符号链接 / junction 直接报 `unsafe-path`，不换后缀重试。
- `stageUnit()`：`batchDir` / `unitDir` 走 `resolveInside`；`mkdir` 后再 `assertNoSymlinkComponents`，防止暂存根被换成链接。
- `publishUnit()`：最终目标与暂存单元都先校验，`mkdir` 父目录后再校验一次才 `rename`。
- `writeManifest()`：写前校验 `.anvil/imports/...` 的每一级；`.anvil/imports` 是 junction 时提交直接 400，不写根外。
- `cleanupStagingUnit()` / `cleanupStagingBatch()`：路径含链接时放弃清理并保留现场，不删除根外目录。

## 3. 去重细节

- 重复判定键 = 规范真实源路径 + 内容指纹；Windows 上路径键大小写归一。
- 扫描时 `duplicate` 只作预览提示；commit 在写队列内重新读取 `.anvil/imports/` 历史并核对目标目录 + 索引 objectId。
- 扫描后被其他 plan 导入：本次自动跳过并记入 `skipped`（`kind:'duplicate'`），不创建 `-2`。
- 扫描后历史目标被删除：本次照常导入，不误跳过。
- 不同源路径同内容仍只提示「潜在重复」，必须 `keepDuplicate:true`。

## 5. 已知边界

1. 路径校验与 `mkdir` / `rename` 之间仍有本机外部进程替换目录的 TOCTOU 窗口；本工具面向单机自用，未引入句柄级目录 API。
2. 显式 vscode 只观察启动后 300ms 内的非零退出；更晚的失败仍按已启动处理（窗口是否出现以实际为准）。
3. Windows 上来源键大小写归一会把极少数「启用区分大小写目录」的不同目录视为同一来源；与 Windows 默认语义一致。
4. 「不同源路径 + 同内容」在双 plan 并发扫描时仍无法在扫描阶段互相看见；本批只保证同源不重复搬运。
5. DOM 行为无单测环境，UI 刷新与按钮入口仍靠真机冒烟。
