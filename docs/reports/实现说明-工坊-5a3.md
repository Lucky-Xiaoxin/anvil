### API / DTO

- `WorkImportCandidateDto` 增加 `sourceParentRelPath` / `scope` / `isContainer` / `sourceCount`。
- `WorkObjectDto` 增加可选 `sourcePath`；`.anvil.json` 顶层字段，不升级 schema、不进 `links`。
- manifest 的 item 增加 `scope`；恢复按 `objectId + targetRelPath` 对账。
- 非法父子 / 散题与整目录同选 / 空范围 / 潜在重复未确认 → `import-conflict`，不写 manifest。

### 界面

- 导入预览改为源目录树：容器 / 题组 / 散题有文字徽章；叶子默认勾选，容器和散题默认不选；父子互斥即时禁用。
- 结果页区分成功、失败、自动跳过、用户跳过；成功与失败并存时显示「部分成功」。
- 工坊中间列表按 `sourcePath` 父路径生成「（根） > 2026 > 10」虚拟来源组；组头可折叠、不可打开/打标/回收。
- 详情「关联」区只读显示来源路径。
- 无任何 `sourcePath` 时退回 5a-2 平铺表现。

## 4. 已知问题 / 不处理项

1. **尚未合并 main**：分支 `feat/workbench-5a.3` 待用户授权后以 `--no-ff` 合并；合并后再把契约 25 状态改为「现行」。
2. **散题候选的生成范围**：契约 §3.2 把散题定义为容器目录的直接文件，§4.2 则写「目录有直接文件」；本实现只在目录存在下级源码目录（`childSourceCount >= 1`）时生成 `direct` 候选，避免叶子目录出现与整目录完全重复的第二个候选。叶子目录的散题可通过整目录候选导入。

5. **无导入历史 UI / 撤销整批**：契约 §2.2 明确不做；manifest 仅作为 journal 与恢复依据。

## 5. 主要改动与复现

```text
packages/shared/src/work-import.ts    批量目录分类 / scope / 来源排序 / sourcePath 清洗 / 批量选择
packages/shared/src/work.ts           WorkMeta / WorkObjectDto.sourcePath
packages/server/src/work/import.ts    多候选扫描 / 多 unit / scope 去重 / manifest scope / sourcePath 写入
packages/server/src/work/store.ts     DTO 透传 sourcePath
packages/web/src/components/work/     WorkImport 树形预览 / import-derive 批量状态 / WorkList 来源视图 / WorkDetail 来源路径 / derive 来源树
packages/web/src/styles.css           来源组头与散题行样式
```

复现：

1. `npm run verify`。
2. 构造一个含 `2026/10/{10.ptc,17.VP,TreeDP}`、`2026/7`、`2026_ICPC_1` 与 `2026/10` 直接文件的旧代码根。
3. 工坊 → 导入旧代码 → 扫描；默认勾选叶子，容器/散题默认不选。
4. 提交后检查 `contests/` 平铺、`.anvil.json` 的 `sourcePath`、来源视图与详情来源路径。
5. 扫描后改动一个叶子源文件再提交，验证部分成功。
