## 1. 新语义

**比赛 = 一个 `contest` 文件夹。**

**题组 = 这个比赛文件夹里的源码文件集合**（`.cpp` / `.py` / `.c` 等），不再生成独立的 `problem` 对象。

- 新建「题组」= 建一个比赛文件夹；写题时直接往里放 `.cpp`，题目就是这些文件。
- 新建「比赛」= 也是比赛文件夹；可以暂时没有源码（没挂题组），也可以之后把源码放进去（挂了题组）。
- **比赛可以挂题组，也可以不挂**：列表里按「比赛」分区；有主源码的比赛显示「题组」徽章，没有的不显示。
- **导入一个目录 = 一个题组**：整个目录的非忽略文件原样复制进一个比赛文件夹，保留相对路径；不再拆成「比赛 + 每道题一个题目对象」。
- 旧的 `problem` 对象仍可查看（列表「旧题目对象」区，只有存在旧数据时出现），但新建 / 导入都不再产生它们。

对象类型没有新增：`contest` / `problem` / `template` / `note` 仍是 5a 的四类；本次只是把 `contest` 用作「比赛 / 题组文件夹」，并停止从 UI 创建 `problem`。`.anvil.json schema=1` 不变。

## 3. 行为细节

### 3.1 新建

- 类型：**题组 / 比赛 / 模板 / 笔记**。
  - 题组：标题必填；建 `contests/<日期>_<slug>/`；不显示榜单路径。
  - 比赛：标题必填；可选 `links.arenaPath`；建 `contests/<日期>_<slug>/`。
  - 题组和比赛内部都是 `contest`；区别是表单意图（题组默认用于放源码，比赛可选挂榜单）。
- 新建题组后，用「打开文件夹」在资源管理器 / 编辑器里直接建 `.cpp`；回到工坊点「重新扫描」，题组徽章和文件列表出现。
- 新建里不再有「题目」选项；API 仍保留 `problem` kind 以兼容旧数据 / 测试，但 UI 不再调用。

### 3.2 列表

- 分区：**比赛 / 模板 / 笔记**；旧数据存在时额外显示「旧题目对象」。
- 比赛行：
  - `sourceCount > 0`（比赛文件夹里有主源码）→ 显示「题组」徽章，行内显示文件数。
  - `sourceCount = 0` → 不显示徽章（没挂题组）。
  - 没有子题目对象的新比赛按普通行显示，不再有「展开 / N 题」的折叠组。
- 旧的「比赛 + 子 problem 对象」数据仍按折叠组显示（组头带「题组」徽章、`N 题`），只用于旧数据兼容。
- 左侧「题目」筛选只在 `counts.problem > 0` 时出现，避免新用户看到空的旧分类。

### 3.3 题组详情动作

- 题组（`contest`）详情动作：**打开文件夹**（Explorer）+ **用 VS Code 打开**（`Code.exe --new-window <abs>`；本机版本目录布局自动走 `cli.js + ELECTRON_RUN_AS_NODE`，失败 502 不回退）。
- 旧 `problem` 对象保留同样两个按钮；模板 / 笔记仍只有「打开文件夹」。
- 文件列表点击文件仍走 `app:auto`，不改变 5a-2 语义。

### 3.4 导入

- 扫描一个绝对目录：
  - `totals.candidates = 1`（目录有非忽略普通文件时）；文件数 / 字节 / 忽略统计不变。
  - 候选：`shape=contest-group`、`role=contest`、`sourceRelPath=''`、标题取目录名、`files` 为全部非忽略文件、`childItemIds=[]`。
  - 识别理由：`整目录导入：N 个文件`、`主源码 M 个；题目就是题组里的源码文件，不单独建对象`。
  - 扫描仍只读，不写受管根。
- 提交：
  - 一个原子单元 = 一个 contest 对象；整个目录复制到 `contests/<日期>_<slug>/`，相对路径逐字节保留。
  - staging → 校验 → 根内 rename → 索引对账 → manifest 的流程不变。
  - 同源同指纹自动跳过；同源变化 → 来源新版本；不同源同内容 → 潜在重复；目标重名 → `-2` / `-3` 后缀。重复矩阵按整个目录算。
- 限制：目录深度 16、文件 10,000、总字节 1 GiB、单文件 128 MiB、候选 2,000 不变；源路径安全边界、符号链接规则、忽略表不变。

### 3.4 数据

- `WorkObjectDto` 新增 `sourceCount: number`：对象自身文件列表里主源码扩展名（`.cpp` / `.cc` / `.cxx` / `.c` / `.py` / `.java` / `.kt` / `.go` / `.rs`）的数量。它只用于「题组」徽章 / 计数，不写 meta、不新增表。
- 旧的 `problem` 对象不迁移、不删除；新导入 / 新建不生成。列表的「旧题目对象」区可以继续打开、打标、归档、移入回收站。

## 6. 已知问题 / 不处理

1. **题组不是独立对象**：题组是比赛文件夹里的源码集合；如果以后要做「一个题组挂到多个比赛」或「题组与比赛分离」，需要新增对象类型 / 关联字段，属于另一轮模型变更。
2. **一个目录 = 一个题组**：如果旧根目录里有多个比赛子目录，导入父目录会得到一个包含全部文件的大题组；要分开请逐个目录导入。这是本次明确的口径。
3. **旧题目对象**不迁移、不自动转换；仍显示在「旧题目对象」区，左侧「题目」筛选只在有旧数据时出现。新导入 / 新建不会生成它们。
4. **5a-2 的多候选分类函数**（`classifyImportTree`）仍保留在 shared 作为遗留工具和测试对象，但当前导入路径不再调用；如确认不需要，可在后续清理。
5. **题组徽章依赖主源码扩展名**：只有附件 / 文档、没有 `.cpp` 等主源码的比赛不显示题组徽章；`sourceCount` 是派生字段，不写 meta。
6. **新建「题组」和「比赛」内部都是 `contest`**：详情里的 kind 文案仍可能显示「比赛」；这是不新增对象类型的取舍。两者区别是表单意图（题组无榜单路径，比赛可选）。题组详情的 VS Code 按钮按 `contest` kind 生效，不依赖标题或路径。
7. **导入仍是单目录**：一次扫描 / 提交只处理一个源目录；不支持一次选多个目录，也不支持旧的多候选拆分。
8. **部分成功状态**：新模型下一个目录只有一个原子单元，单个导入不会出现「多个单元里部分成功」；UI 仍保留旧多单元结果的渲染兼容。
9. **旧版的 5a-2 报告 / 截图**保留为历史；本文取代其导入口径。`docs/contracts/24` 未改动（按用户要求），阅读契约时以本文为准。
