## 1. 定位与创意核心

**一句话**：ANVIL 把每一场比赛——尤其是输掉的那些——变成下一次的武器。

**核心循环**（产品的一切都围绕它）：

```
  ┌──────────────────────► 赛（Contest）
  │                        打完一场 / 开一场 VP
  │                              │
  │      黄金 15 分钟 ────────────┤
  │                              ▼
  │                        复盘（Postmortem）
  │                        名次曲线 · 逐题状态 · 奖牌线差 · 卡点
  │                              │
  │                              ▼
  │                        补题（Repair）
  │                        未解题自动入补题簿；补完标记"独立/看题解"
  │                              │
  │                              ▼
  └──────────────────────── 复习（Review）
                           错题重做 · 口述思路 · 默写模板（间隔重复）
```

**赛后黄金 15 分钟**（本产品的招牌体验）：
一场比赛结束后，把导出文件丢进工作台，15 分钟内得到三样东西——
① 一张**复盘页**（你 vs 全场，不是排行榜截屏）；
② 一份**补题清单**（没做出来的题自动入队）；
③ 几张**复习卡**（卡点分类 + 关键 trick）。
**赢了拿名次，输了拿素材，不空手而归。**

- 代号：沿用 ANVIL / 更换待定 ⚠️Q-E1。
- 它**不是**：刷题网站、榜单查看器（榜单只是原料）、多人协作工具。

**明确不做**：不做云/账号/多人；不做在线判题（不替你往 OJ 交代码）；不硬爬有反爬的站；不替你写题。

## 2. 一天的用法（四个剧本）

### 剧本 1 · 赛后之夜（最重要）

```
1. algoux 导出比赛文件 → 丢进 vault/inbox/（或下载目录即 inbox）
2. 工作台自动嗅探格式 → 榜单页出现这一场（无需手输任何数据）
3. 点「我的复盘」：
   ┌──────────────────────────────────────────────┐
   │ 2026 CCPC 广东站 · FOSU3                      │
   │ 最终 164 / 342 · 5 题 · 罚时 623              │
   │ 名次曲线（每 AC 一个点的排名折线）              │
   │ [A✓ 0:14] [B✓ 0:52] [C✗ 4次] [D✓ 1:47] ...   │
   │ 铜牌线：差 1 题（且 C 题 4 次罚时是最大失血点）  │
   └──────────────────────────────────────────────┘
4. 对 C 题点「入补题簿」→ 选卡点分类（30 秒）→ 完成
```
整条链 ≤ 5 分钟。

### 剧本 2 · 补题日

补题簿按"欠账时间"排序（待补 6 题）→ 点某题「开补」→ 工作台打开该题本地文件夹（或直接唤起编辑器）→ 补完标「独立完成 / 参考题解」→ 自动生成复习卡（3 天后到期重做）。

### 剧本 3 · 周末 VP

从目录选历史场（如 2024 上海）→ 开 VP（**默认封榜视角**）→ 大倒计时 + 你的 13 格 → 每交一题一键录入 → 右侧实时显示"你在全场 352 队里第 N 名" → 结束出对比卡（你第 X / 奖牌线差 / 与上届自己的对比）。

### 剧本 4 · 平时的 10 分钟

Ctrl+K →「复习」→ 今天到期的 3 张卡：1 张重做（这题 3 个月没碰）、1 张口述、1 张默写（LCT 模板）→ 收工，训练日点阵 +3。

## 3. 设计原则

1. **文件优先**：题解、代码、模板、笔记都是 vault 里的真实文件（Markdown / cpp），SQLite 只是索引，**可从文件重建**。你能用 VS Code / grep 直接操作自己的资产，无锁定。
2. **榜单是派生视图**（铁律）：只存提交流；实时刷新、回放 scrub、封榜、VP 叠加、换计分规则，全部是同一个纯函数换参数。
3. **诚实数据**：恢复不了的时间标"未知"（`timeExact=false`，UI 画虚线）；热力图格子标注样本量；不做虚假 streak；"放弃"也要显式标记，防自欺。
4. **零摩擦**：能自动的绝不让手输（inbox 监听、格式嗅探、我的队伍自动匹配）；任何操作 ≤ 3 次按键。
5. **完成大于完美**：每个里程碑以"真人可用"为验收；没有写验收的功能不许开工（范围冻结条款见 §8）。

## 7. 关键机制

### 7.1 导入（继承实测结论）

格式嗅探顺序（敏感）：
```
1. .json 且 type==='general' 且有 version/contest/problems/rows   → srk
2. 文本首行以 @contest 开头                                        → ghost
3. .xlsx 表头含 {Rank|#} + {Team|Name} + {Solved|Score} + {Penalty|Time} → algoux-xlsx
4. .xlsx 无表头，col0 字符串、col1.. 匹配 ^(\d+:\d\d:\d\d/\d+|\(-\d+\)|)$   → vjreplay
5. 否则报错；允许 --format 强制覆盖
```
- 原件**原样留存** `vault/contests/<slug>/`，`file_hash` 相同跳过（`--force` 重导）。
- 四格式逐条坑 → 附录 A。⚠️ 样本文件需重新放回 `fixtures/samples/`（Q-C2）。
- M1 先只上主格式（哪一种按问卷 C1 排序定 ⚠️Q-C1），其余 M2 补齐。

### 7.2 计分引擎（纯函数）

```ts
deriveBoard(contest, problems, teams, subs,
  { atS?, includeFrozen?, extraTeams?, extraSubs? }): Board
```
要点（全部经过真实数据实测，完整规则见附录 A）：
- 时间窗 `timeMs/1000 <= atS`；`timeMs=null` 的失败提交**始终计尝试数**（不影响时间轴）。
- 封榜：`(durationS - frozenS, durationS]` 内提交显示 `?`，不计 solved/penalty；`includeFrozen` 揭开。
- 单题结算：第一个 AC 定时间；`penalty = AC 起始分钟 + AC 前失败数 × 20min`。
- 排序：`solved↓, penalty↑, 源行序`（末级**不能**用队名字典序，实测复现不出并列）。
- 非官方队 `rank=null`，保留在列表；奖牌带按官方队顺序消费：金 1–34、银 35–102、铜 103–204。

### 7.3 复盘页指标定义（新）

- **名次曲线**：对每个我的提交时点 t，取 `deriveBoard(atS=t)` 中我的 rank 画折线（失败提交若 `timeMs=null` 不画点，标注"时间轴精度：仅 AC 事件"）。
- **逐题格**：状态 / 尝试次数 / 首交与 AC 相对时间（场内分钟）。
- **奖牌线差**：我的 rank 与奖牌带边界的队数差；并回答"差在题数还是罚时"。
- **卡点录入**：每场赛后 8 选 1（见 7.5），30 秒内完成。

### 7.4 VP 语义（继承）

合并榜 = `deriveBoard(..., extraTeams=[vpTeam], extraSubs=vpSubs, atS=elapsed)`：
- 历史提交流 `origin='import'`，视图默认 `frozen`（更接近现场体验）。
- 你的提交流 `origin='vp'`，`timeMs` = 相对 VP 开始的偏移；**永不污染历史数据**。
- 你的真实排名 = 你在合并榜中的 rank；结束写 `my_contest_records` 并出对比卡。

### 7.5 补题簿状态机 + 卡点分类（新，前移自 P1）

```
queued ──► working ──► solved (independent | with_editorial) ──► 复习池
                └──► dropped（明确放弃也要标记，防自欺）
```

卡点分类（赛后必选其一）：
`NOT_SEEN 没思路 / WRONG_DIRECTION 方向错 / ALMOST 差一步 / IMPL_BUG 实现挂 / COMPLEXITY 复杂度错 / READ_FAIL 读题挂 / GIVE_UP_EARLY 过早放弃 / TUNNEL_VISION 卡死一题`
——聚合出"**你怎么失败的**"，比"你做了多少"有用得多。

### 7.6 复习引擎（SRS，继承自 v0.2 §12）

- 卡型：`REDO` 到期重做该题 / `RECALL` 口述或手写思路 / `TEMPLATE` 默写模板。
- 阶梯 1/3/7/16/35/90 天；评分 AGAIN/HARD/GOOD/EASY 调 `ease ∈ [1.3, 2.8]`。
- 掌握度 = 时间衰减加权证据均值：`e = 0.6*result + 0.25*independence + 0.15*speed`，`w = exp(-days/60)`，`mastery = Σew/Σw`；置信度 `Σw` 决定 UI 饱和度——**样本少不许显示"精通"**。

### 7.7 模板保鲜 + 对拍衔接（新）

- 模板文件必须带 `*.test.cpp` 自检 + `last_verified_at`；>90 天标红（比赛现场写没验证过的模板是灾难）。
- 与你现有 `tester.py`（`ACM/try/`）的衔接方式待定 ⚠️Q-B7：生成/管理测试点目录、一键对拍、或仅记录。

### 7.8 实时链路（继承）

inbox 监听（chokidar）→ hash 去重 → 重导 diff 追加 → SSE `submissions.appended` → 前端重推导。
覆盖写同名文件即"刷新"；直播场可选 URL 轮询（仅无鉴权 srk 端点）。
事件：`contest.imported` / `submissions.appended` / `vp.tick` / `vp.submission`。

## 附录 A · 已实测格式规则（资产速查，勿丢）

> 来源：2026-10-02 对 icpc2024shanghai 四件套 + CCPC 样本的逐行实测。**新做任何解析前，先跑脚本核对真实文件，不照本文档写。**

四格式对比：

| 格式 | 自描述性 | 逐次提交时间 | 比赛元信息 | 关键坑 |
|---|---|---|---|---|
| **srk.json**（v0.3.13） | ✅ 完整 | ✅ 毫秒级 | ✅ title/startAt/duration/frozen/sorter | 信息最全，**定为内部模型基准**；FB 只存在于 `statuses[].result`（`solutions[].result` 永不含 FB） |
| **gym ghost .dat** | ✅ `@` 头 | ✅ 秒级 | ✅ | `@contlen` 单位是**分钟**；`@s` 时间是**整数秒**；verdict 是 `OK`/`RJ`（非 AC）；≥17990 的"哨兵时间"实为真实末段提交（曾误判，不得置空）；非官方队 = 队名 `*` 前缀（16 队）；`@t` 的 teamId 是注册序非榜序，join 用 name+organization |
| **algoux xlsx** | 表头带题号与 (ac/sub) | ❌ 仅最终 AC 时间 + 总尝试数 | ⚠️ 表头无 startAt | **至少两种表头变体**（ICPC 站 `#,R#,S#,Markers,Official,Organization,Name,...` / CCPC 站 `Rank,Organization Rank,Organization,Team,Solved,Penalty,...`，第 0 行是标题）→ 严格表头语义匹配，绝不写死列下标 |
| **vjreplay xlsx** | ❌ 无表头无题号无元信息 | ❌ 仅 AC（`H:MM:SS/n`；失败 `(-N)`） | ❌ 完全没有 | col0=队名；必须配对元数据定位题号；失败提交时间不可恢复**但计分正确**（罚时只需 AC 时间 + 失败次数） |

v0.1 被实测推翻的条目（教训，别再犯）：
1. ghost 时间是整数**秒**不是分钟；verdict 是 `OK`/`RJ`，`OK`→`AC`。
2. 排序 tie-break 用**源文件行序**（上海站 20 组并列，字典序复现不出；srk 数组序即权威序）。
3. 奖牌带 34/68/102 是**各段数量**：金 1–34、银 35–102、铜 103–204，按**官方队顺序**消费；非官方队不占奖牌不占名次；并列只影响 `R#` 跳号。
4. FB 判定分两路：srk/algoux 用**源给的**（srk 在 `statuses[].result`）；ghost/vjreplay 才走事后计算（该题全局最早 AC）。混用会错（上海站多出 2 个）。
5. vjreplay 失败时间不可恢复，但 `timeExact=false` 标注即可，不影响正确性。

## 附录 B · 术语表

- **SRK**：XCPCIO 标准榜单格式（`type:"general"`），本文内部模型的基准。
- **VP**：Virtual Participation，虚拟参赛（本产品 = 你的提交流叠加到历史场）。

- **FB**：First Blood，一血。
- **提交流**：append-only 的 Submission 集合，榜单的唯一事实来源。
- **派生榜单**：由提交流 + 计分规则即时推导、不入库的视图。
- **补题簿 / 卡点分类 / SRS**：见 §7.5 / §7.6。
