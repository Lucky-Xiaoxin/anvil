## 0. 一句话目标

做一个**能打开、能看到真实数据**的个人 ICPC 训练工作台骨架：
本地 Web 应用，首次启动输入 Codeforces handle → 拉取全量历史 → 仪表盘呈现活跃格子图、统计与 rating。
**此切片不包含 VP、掌握热力图等大模块**——它们在后续切片叠加（见 §7）。

## 1. 交付物（Definition of Done）

1. `E:\icpc-workspace` 下可运行的 monorepo（`git init` 完成，含 `.gitignore`）。
2. `npm run dev` 可开发运行；**`start.bat` 双击 = 起服务 + 自动打开浏览器**（http://localhost:7788）。
3. 首次打开 → 设置向导：输入 CF handle → 校验（`user.status?count=1`）→ 全量同步（有进度反馈）→ 进入仪表盘。
4. 仪表盘第一屏（深色、有游戏化质感，视觉规格见 §5）：
   - **活跃格子图**：53 周 × 7 天，GitHub 贡献图形态，颜色按"当日独立过题数"分 5 档；
   - **统计卡**：总过题数（去重）、当月过题数（+ 近 6 个月迷你柱状，hover 明细）、CF 当前 rating + 最高 rating + 迷你曲线、连续训练天数（诚实算法见 §4.3）；
   - **导航壳**：仪表盘 / 掌握图 / VP / 设置；未实现模块显示"未解锁"占位页；
   - **同步按钮**：增量拉取（轮询进度，见 §5 API）。
5. `npm test` 全绿（必测项见 §6）。
6. 断网时可打开：展示已缓存数据 + 明确提示，不崩。
7. 实现说明一页：做了/没做什么、如何跑、**附首屏截图 2 张（1280×800、1440×900）**。

## 4. 数据层

### 4.1 CF 同步（`server/src/sync/cf.ts`）

- 官方接口（无需 key）：
  - `GET https://codeforces.com/api/user.status?handle={h}&from={n}&count=10000`（单次上限 10000 条）
  - `GET https://codeforces.com/api/user.rating?handle={h}`
- **限速**：约 1 req / 2s，请求间 sleep ≥ 2s；失败重试 3 次（指数退避）；非 `OK` 状态给出可读错误。
- **全量**：`from=1` 循环直到不足一页；**增量**：`from=1` 拉到遇到已存 id 即停（幂等，重拉不重复）。
- 只落库所需字段：提交 id、contestId、`problem{contestId,index,name,rating?,tags?}`、verdict、creationTimeSeconds、relativeTimeSeconds、`author.participantType`、programmingLanguage。
- **已实测的坑（照抄处理）**：
  - `relativeTimeSeconds = 2147483647` 是"非比赛内"哨兵 → 存 `NULL`；
  - gym 题无 `rating`/`tags`（存 NULL / 空数组）；普通 CF 题内嵌 `tags`+`rating`；
  - `participantType ∈ {CONTESTANT, PRACTICE, VIRTUAL, MANAGER, OUT_OF_COMPETITION}`，原样存（后续 VP 切片要用）。

### 4.2 SQLite DDL（schema_version = 1，`vault/anvil.db`）

```sql
PRAGMA journal_mode = WAL;
CREATE TABLE IF NOT EXISTS meta (k TEXT PRIMARY KEY, v TEXT NOT NULL);   -- schema_version 等
CREATE TABLE IF NOT EXISTS submissions (
  id INTEGER PRIMARY KEY,              -- CF submission id
  contest_id INTEGER,
  problem_key TEXT NOT NULL,           -- 'cf:{contestId}:{index}'，如 cf:2268:D
  problem_name TEXT,
  problem_rating INTEGER,              -- 可空（gym 题无）
  problem_tags_json TEXT,              -- JSON 数组，可空
  verdict TEXT, language TEXT,
  participant_type TEXT,
  created_ts INTEGER NOT NULL,         -- epoch 秒
  relative_ts INTEGER                  -- 场外为 NULL
);
CREATE INDEX IF NOT EXISTS idx_sub_time ON submissions(created_ts);
CREATE INDEX IF NOT EXISTS idx_sub_problem ON submissions(problem_key);
CREATE TABLE IF NOT EXISTS rating_history (
  contest_id INTEGER PRIMARY KEY, contest_name TEXT, rank INTEGER,
  old_rating INTEGER, new_rating INTEGER, updated_ts INTEGER
);
CREATE TABLE IF NOT EXISTS sync_state (k TEXT PRIMARY KEY, v TEXT NOT NULL);  -- last_sync_at 等
```

### 4.3 聚合规则（`packages/shared`，纯函数 + 单测）

- **活跃格子图**：按本地时区自然日聚合 `distinct problem_key WHERE verdict='OK'`（同题同日多次只算一次）；5 档：0 / 1-2 / 3-5 / 6-9 / 10+。
- **总过题数**：`distinct problem_key` 首次 OK 的题数。
- **当月过题数 + 月度柱状**：当月过题 = 本地日历月的 AC 去重题数（主数字）；卡片附**近 6 个自然月迷你柱状**（`[{month, solved, partial}]`，当月 `partial=true` 以"进行中"样式呈现；柱 hover 出 tooltip：月份 · N 题 · 进行中）。**不做任何"高于 / 低于"判断、不出现月均 / 日均 / 年均**——涨跌交给柱子形状，细节交给 hover。历史不足 6 个月就返回实际月数，不补齐。
- **连续训练天数**：截至"今天"的连续"有 AC 的自然日"；今天尚无 AC 时从昨天起算，文案如实写"今天还没开张"（禁止虚假 streak）。
- 时区：本机本地时区（Asia/Shanghai）。

### 4.4 API 契约（server）

字段级语义以视觉基线（`design/mock-01-dashboard.html` 第 4 屏「Data slots」表）为准，实现必须一致。总原则：

- **主数字给 int**（要跑 count-up）；**读数与副行给带单位的成品串**（口径复杂，后端拼一次胜过前端猜十次）；
- **tone 类字段给数值**（正负号决定绿/琥珀，颜色不靠文案猜）；取不到值的槽渲染 `—`，不渲染 0；
- `activity[]` 的 `day` 为本地日 `"YYYY-MM-DD"`；**数组中缺项 = 那天还没到**（与 `solved:0` 是两件事）。

```
GET  /api/status    -> { configured, handle, lastSyncAt(epoch), counts:{submissions, problems} }
                       # lastSyncText 由前端按 lastSyncAt 格式化，接口不给成品串（会过期）

POST /api/config    { handle }  -> 校验并保存
POST /api/sync      -> 202 启动后台同步
GET  /api/sync/state -> { phase: idle|fetching|storing|done|error,
                          fetched, stored, error?,
                          total, pages, problems, ratingContests, offsite }
                       # offsite = 哨兵值转 NULL 的场外提交数；前端 1s 轮询

GET  /api/dashboard -> {
  activity: [{ day:"YYYY-MM-DD", solved:int }],           # 53 周窗口，缺项=未到
  stats: {
    totalSolved:int, activityTotal:int,                   # 去重题数 / 题次（两者无加法关系）
    months:[{ month:"YYYY-MM", solved:int, partial:bool }], # 近 6 个月；卡 2 主数字 = 末项 solved（§4.3）
    streak:{ days:int, sub:string },                      # sub=诚实文案由后端拼（如"今天还没开张 · 昨日 N 题"）
    longestRun:{ days:string, range:string }, gaps3:string,
    weekendPct:string, emptyCells:string                  # 同源派生读数；整块可删，删了不动布局
  },
  rating: {
    count:int, current:int, first:int, max:int, rankLabel:string,   # CF 原始英文段位名（Expert 等），不做中译
    totalDelta:string, totalDeltaTone:int,
    lastDeltaText:string, lastDeltaTone:int,
    lastContestShort:string, lastContest:string,          # 短名上卡面，全名留给 tooltip
    series: [{ ts:"YYYY-MM", newRating:int, contestName:string, delta:int }]
  }
}
```

所有派生量（最长连续、断档次数、周末占比、近 14 日刻度）都归 `packages/shared` 的纯函数，接口出、界面收。

## 5. UI 规格

> **视觉基线**：`design/mock-01-dashboard.html`（**已评审冻结**的 4 屏可交互视觉稿 · v2；其预览截图已于 2026-10-04 随仓库清理移除，git 历史可找回）。实现时 tokens / 布局 / 动效 / `data-bind` 槽位**一律照抄**，不自创风格；以该文件为准，与本节文字冲突时它优先。

**基调**："深色机房 + 炉火"（铁砧意象）。高信息密度但不冷——数字有"燃烧起身"的感觉，克制、不花哨。

设计 tokens（起点，允许微调但需保持同风格）：

```
--bg:#0A0C10  --panel:#12161D  --panel-2:#171C25  --line:#222A36
--text:#E8ECF3  --text-dim:#94A0B4
--accent:#F5A524（炉火琥珀）  --accent-2:#4CC9F0（数据蓝）
--ok:#3FB950  --warn:#D29922  --bad:#F85149
--gold:#D9A441  --silver:#AEB8C6  --bronze:#B08968   # 奖牌色（后续切片用）
格子图色阶（琥珀渐深）: #1A1F29 → #4A3520 → #7A5426 → #B27B2E → #F5A524
radius:10px；间距 8 的倍数；数字一律 tabular-nums
字体：UI 用 "Segoe UI"/"Microsoft YaHei UI"；数字用 "Cascadia Code"/Consolas 等宽
```

组件：

- `AppShell`：左侧导航（仪表盘/掌握图/VP/设置）+ 顶栏（同步按钮、handle 显示）。
- `Wizard`：单页向导（handle 输入 → 校验 → 拉取进度）。
- `StatCard`：大数字 + 小标签；数字用 count-up 动画（≤600ms）。
- `ActivityGrid`：自绘；格子 10×10px，hover 高亮 + tooltip（日期/当日题数）；年度切换暂不做。
- `RatingMiniChart`：SVG 折线 + 末点高亮 + 当前值。
- `LockedModule`：占位页（"未解锁 · 下一片区域"），点击可看一句后续预告。
- 动效：150-200ms ease-out；格子载入 stagger fade；一律尊重 `prefers-reduced-motion`。

文案风格：短句、直给、有一点点游戏感但不油（错误态：说清楚发生了什么 + 下一步；空态：促进行动）。

**文案从简（用户明确偏好）**：不写自明注释、不解释显而易见的东西；口径类信息最多一行、优先放 tooltip；"开发细节"（接口名、限速数字、实现方式）不进产品 UI。

## 6. 测试与验收

**单测（vitest，mock 网络，不打真实请求）**：

- 同步：分页循环、增量去重（重拉不重复）、哨兵值→NULL、非 OK 响应→可读错误；
- 聚合：活跃图 5 档分界、同题同日去重、总过题去重、连续天数边界（今天无 AC / 昨天断 / 跨月）、月度分桶（跨年 12→1 月、当月 partial、历史不足 6 个月不补齐）；
- DDL：迁移幂等（重复 init 不炸）。

**手测验收清单（reviewer 用，也供实现 agent 自检）**：

- [ ] `start.bat` 双击 → 浏览器自动打开 → 有数据时首屏 < 3s；
- [ ] 向导输入真实 handle（自测可用公开 handle `Benq`）→ 全量同步完成（~8.5k 条提交应在 2-3 次请求内完成）；
- [ ] 重启进程后数据仍在；再点同步只拉增量；
- [ ] 断网打开：页面可开、旧数据在、提示清楚；
- [ ] `npm test` 全绿；
- [ ] 截图 2 张附在实现说明里。

**性能**：仪表盘接口 < 50ms（万级提交）；格子图渲染流畅无卡顿。
